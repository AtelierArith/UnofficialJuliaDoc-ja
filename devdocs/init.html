Initialization of the Julia runtime

Juliaランタイムはjulia -e 'println("Hello World!")'をどのように実行するのでしょうか？

main()

実行はmain() in cli/loader_exe.cから始まります。これはcli/loader_lib.c内のjl_load_repl()を呼び出し、いくつかのライブラリを読み込んだ後、最終的にjl_repl_entrypoint() in src/jlapi.cを呼び出します。

jl_repl_entrypoint()はlibsupport_init()を呼び出してCライブラリのロケールを設定し、「ios」ライブラリを初期化します（ios_init_stdstreams()およびLegacy ios.c libraryを参照）。

次に、コマンドラインオプションを処理するため、jl_parse_opts()が呼び出されます。jl_parse_opts()が扱うのは、コード生成または初期化の早い段階に影響するオプションだけです。それ以外のオプションは、後でexec_options() in base/client.jlが処理します。

jl_parse_opts()は、コマンドラインオプションをglobal jl_options structに格納します。

julia_init()

julia_init() in init.cはmain()から呼び出され、さらに_julia_init() in init.cを呼び出します。

_julia_init()は、まず再びlibsupport_init()を呼び出します（2回目は何もしません）。

シグナルハンドラーマスクをゼロにするため、restore_signals()が呼び出されます。

jl_resolve_sysimg_location()は、設定済みのパスからベースシステムイメージを探します。Building the Julia system imageを参照してください。

jl_gc_init()は、割り当てプールと、弱参照、保持された値、ファイナライゼーション用のリストを準備します。

jl_init_frontend()は、スキャナー／パーサーを含む、コンパイル済みのfemtolispイメージを読み込んで初期化します。

jl_init_types()は、built-in types defined in julia.h用にjl_datatype_t型の記述オブジェクトを作成します。例：

jl_any_type = jl_new_abstracttype(jl_symbol("Any"), core, NULL, jl_emptysvec);
jl_any_type->super = jl_any_type;

jl_type_type = jl_new_abstracttype(jl_symbol("Type"), core, jl_any_type, jl_emptysvec);

jl_int32_type = jl_new_primitivetype(jl_symbol("Int32"), core,
                                     jl_any_type, jl_emptysvec, 32);

jl_init_tasks()はjl_datatype_t* jl_task_typeオブジェクトを作成し、グローバルなjl_root_task構造体を初期化して、jl_current_taskをルートタスクに設定します。

jl_init_codegen()はLLVM libraryを初期化します。

jl_init_serializer()は、組み込みのjl_value_t値に対する8ビットのシリアライズタグを初期化します。

sysimgファイル（!jl_options.image_file）がない場合は、CoreモジュールとMainモジュールが作成され、boot.jlが評価されます。

jl_core_module = jl_new_module(jl_symbol("Core"), NULL)は、JuliaのCoreモジュールを作成します。

jl_init_intrinsic_functions()は、新しいJuliaモジュールIntrinsicsを作成し、定数のjl_intrinsic_typeシンボルを格納します。これらのシンボルは、各intrinsic functionに整数コードを割り当てます。コード生成時には、emit_intrinsic()がこれらのシンボルをLLVM命令に変換します。

jl_init_primitives()は、C関数をJuliaの関数シンボルに結び付けます。たとえば、Core.:(===)()シンボルは、add_builtin_func("===", jl_f_is)を呼び出すことで、C関数ポインターjl_f_is()に結び付けられます。

jl_new_main_module()はグローバルな「Main」モジュールを作成し、jl_current_task->current_module = jl_main_moduleを設定します。

注：_julia_init() then sets jl_root_task->current_module = jl_core_module。ここではjl_root_taskはjl_current_taskの別名なので、上でjl_new_main_module()が設定したcurrent_moduleは上書きされます。

jl_load("boot.jl", sizeof("boot.jl"))はjl_parse_eval_allを呼び出します。これはjl_toplevel_eval_flex()を繰り返し呼び出して、boot.jlを実行します。<!– TODO – evalを掘り下げる？ –>

jl_get_builtin_hooks()は、boot.jlで定義されたJuliaのグローバル変数を指す、グローバルなCポインターを初期化します。

jl_init_box_caches()は、1024以下の値について、ボックス化された整数値オブジェクトをあらかじめグローバルに確保します。これにより、後でボックス化整数を割り当てる処理が高速になります。例：

jl_value_t *jl_box_uint8(uint32_t x)
{
    return boxed_uint8_cache[(uint8_t)x];
}

_julia_init() iteratesはjl_core_module->bindings.tableを走査してjl_datatype_t値を探し、型名のモジュール接頭辞をjl_core_moduleに設定します。

jl_add_standard_imports(jl_main_module)は「Main」モジュールで「using Base」を実行します。

注：_julia_init()は、上でjl_core_moduleに設定される前の状態であるjl_root_task->current_module = jl_main_moduleに戻ります。

SIGSEGV（OSX、Linux）およびSIGFPE（Windows）向けに、プラットフォーム固有のシグナルハンドラーが初期化されます。

その他のシグナル（SIGINFO, SIGBUS, SIGILL, SIGTERM, SIGABRT, SIGQUIT, SIGSYSおよびSIGPIPE）は、バックトレースを出力するsigdie_handler()に接続されます。

jl_init_restored_module()は、デシリアライズされた各モジュールについてjl_module_run_initializer()を呼び出し、__init__()関数を実行します。

最後に、sigint_handler()がSIGINTに接続され、jl_throw(jl_interrupt_exception)を呼び出します。

その後、_julia_init()はback to main() in cli/loader_exe.cを返し、main()がrepl_entrypoint(argc, (char**)argv)を呼び出します。

sysimg

sysimgファイルがある場合、そこにはCoreモジュールとMainモジュール（およびboot.jlによって作成されたその他のもの）の、あらかじめ作成されたイメージが含まれています。Building the Julia system imageを参照してください。

jl_restore_system_image()は、保存されたsysimgを現在のJuliaランタイム環境にデシリアライズします。その後、以下のjl_init_box_caches()から初期化が続行されます。

注：jl_restore_system_image() (and staticdata.c in general)はLegacy ios.c libraryを使用します。

repl_entrypoint()

repl_entrypoint()は、argv[]の内容をBase.ARGSに読み込みます。

コマンドラインで.jlの「program」ファイルが指定されている場合、exec_program()はjl_load(program,len)を呼び出します。これはjl_parse_eval_allを呼び出し、さらにjl_toplevel_eval_flex()を繰り返し呼び出してプログラムを実行します。

ただし、この例（julia -e 'println("Hello World!")'）では、jl_get_global(jl_base_module, jl_symbol("_start"))がBase._startを検索し、jl_apply()がそれを実行します。

Base._start

Base._startはBase.exec_optionsを呼び出します。これは、式オブジェクトを作成するjl_parse_input_line("println("Hello World!")")と、Mainのモジュールコンテキストでパース済みの式exを実行するCore.eval(Main, ex)を呼び出します。

Core.eval

Core.eval(Main, ex)はjl_toplevel_eval_in(m, ex)を呼び出し、さらにこれはjl_toplevel_eval_flexを呼び出します。jl_toplevel_eval_flexは、与えられたコードサンクをコンパイルするか、インタープリターで実行するかを決める簡単なヒューリスティックを実装しています。println("Hello World!")が渡された場合、通常はインタープリターで実行すると判断します。その場合、jl_interpret_toplevel_thunkを呼び出し、さらにeval_bodyを呼び出します。

以下のスタックダンプは、インタープリターがBase.println()およびBase.print()のさまざまなメソッドをたどり、ccall(jl_uv_write())を実行するwrite(s::IO, a::Array{T}) where Tに到達するまでの様子を示しています。

jl_uv_write()はuv_write()を呼び出し、JL_STDOUTに「Hello World!」を書き込みます。Libuv wrappers for stdioを参照してください。

jl_atexit_hook()

main()はjl_atexit_hook()を呼び出します。これはBase._atexitを呼び出した後、jl_gc_run_all_finalizers()を呼び出してlibuvハンドルをクリーンアップします。

julia_save()

最後に、main()はjulia_save()を呼び出します。コマンドラインで要求されている場合、これはランタイムの状態を新しいシステムイメージに保存します。jl_compile_all()およびjl_save_system_image()を参照してください。
