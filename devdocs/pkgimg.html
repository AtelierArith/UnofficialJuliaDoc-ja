Package Images

Juliaのパッケージイメージは、Juliaパッケージ用のオブジェクト（ネイティブコード）キャッシュを提供します。Juliaのsystem imageと似ており、多くの機能を共有しています。実際、基盤となるシリアライズ形式は同じで、システムイメージはパッケージイメージのビルド元となるベースイメージです。

High-level overview

パッケージイメージは、コードとデータの両方を含む共有ライブラリです。.jiキャッシュファイルと同様に、パッケージごとに生成されます。データセクションには、グローバルデータ（パッケージ内のグローバル変数）と、そのパッケージで定義されているメソッドや型に関する必要なメタデータが含まれます。コードセクションには、JuliaのLLVMベースのコンパイラーによる最終出力をキャッシュしたネイティブオブジェクトが含まれます。

コマンドラインオプション--pkgimages=noを使うと、このセッションでのオブジェクトキャッシュを無効にできます。この場合、キャッシュファイルが再生成される可能性が高いことに注意してください。Juliaがデフォルトでキャッシュするバリアント数の上限については、JULIA_MAX_NUM_PRECOMPILE_FILESを参照してください。

Note

パッケージイメージはネイティブ共有ライブラリのように見えますが、あくまでその近似にすぎません。ネイティブプログラムからリンクすることはできず、Juliaから読み込む必要があります。

Linking

パッケージイメージにはネイティブコードが含まれるため、使用する前にリンカーを実行する必要があります。環境変数JULIA_VERBOSE_LINKINGをtrueに設定すると、パッケージイメージのリンク処理を詳細に表示できます。

また、ユーザーの環境に正常に動作するシステムリンカーがインストールされているとは限りません。そのため、Juliaには、すぐに使える環境を提供するために、LLVMリンカーのLLDが同梱されています。base/linking.jlでは、サポート対象のすべてのプラットフォームでパッケージイメージをリンクできるよう、限定的なインターフェースを実装しています。

Quirks

LLDはマルチプラットフォーム対応のリンカーですが、プラットフォーム間で一貫したインターフェースを提供していません。また、clangなどのコンパイラードライバーから使うことを想定しているため、llvm-project/clang/lib/Driver/ToolChainsのロジックの一部を再実装しています。幸い、lld -flavorを使えば、LLDを適切なプラットフォーム向けに設定できます。

Windows

link.exeを扱わずに済むよう、-flavor gnuを使い、実質的にlldをmingw32環境から使うクロスリンカーにしています。WindowsのDLLには_DllMainCRTStartup関数が必要です。mingw32ライブラリへの依存を最小限に抑えるため、そのスタブ定義は独自に挿入しています。

MacOS

macOSの動的ライブラリは、-lSystemにリンクする必要があります。最近のmacOSでは、Xcodeが利用可能な場合に限り、-lSystemをリンクに使用できます。そのため、-undefined dynamic_lookupとリンクしています。

Package images optimized for multiple microarchitectures

システムイメージのmulti-versioningと同様に、パッケージイメージもマルチバージョニングに対応しています。これにより、同じ環境内の異なるCPUアーキテクチャで効率よく実行できるパッケージキャッシュを作成できます。

パッケージイメージのCPUターゲットの設定方法については、環境変数JULIA_CPU_TARGETを参照してください。

Flags that impact package image creation and selection

以下は、キャッシュの選択に影響するJuliaのコマンドラインフラグです。異なるフラグで作成されたパッケージイメージは拒否されます。

  • -g、--debug-info: コード生成に影響するため、完全一致が必要です。
  • --check-bounds: コード生成に影響するため、完全一致が必要です。
  • --inline: コード生成に影響するため、完全一致が必要です。
  • --pkgimages: オブジェクトキャッシュを有効にせずに実行できるようにします。
  • -O、--optimize: 最適化レベルが低い設定で生成されたパッケージイメージは拒否しますが、より高い最適化レベルのイメージは読み込みを許可します。
