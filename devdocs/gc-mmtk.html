Julia + MMTk

Julia 内部の GC コードをリファクタリングし、外部 GC をサポートするために、これまで多くの取り組みが行われてきました。Julia で異なる GC アルゴリズムを使えるようにするための第一歩として、GC interface の設計と実装が行われました。このインターフェースを利用するため、MMTk（Memory Management Toolkit）を使って Julia をビルドする機能を追加しました。Julia と MMTk を組み合わせることで、さまざまな GC 実装をテストできるようになり、開発者は Julia をソースからビルドする際に特定の実装を選択できます。Julia と MMTk の接続には binding を使います。これは言語ランタイムと MMTk のコアをつなぐものです。mmtk-julia binding は Rust で書かれており、this repository にあります。

[!NOTE] 別の GC を使うには、Julia をソースからビルドする必要があります。実行時に実装を切り替えることはできません。現在使用中の GC のバージョンを確認するには、Julia REPL で versioninfo() を実行してください。バージョンは GC: ... の下に表示されます。

Building Julia with MMTk

MMTk を使って Julia をビルドする方法は 3 つあります。binding の固定リリースを使ってソースからビルドする方法、mmtk-julia の repository でカスタムバージョンをチェックアウトする方法、Julia の BinaryBuilder が提供するプリコンパイル済みバイナリを使う方法です。最も簡単なのは BinaryBuilder のバイナリを使う方法です。まず、MMTk をサードパーティ製 GC として有効にするため、変数 WITH_THIRD_PARTY_GC を mmtk に設定します。次に、たとえば Immix を GC として使うには、変数 MMTK_PLAN=Immix を設定し、通常どおり Julia をビルドします。

以下の変数を使って、さまざまな構成を指定できます。これらの変数は、Make.user ファイルまたは環境変数として設定できます。現時点では、MMTK_PLAN=StickyImmix（世代別 Immix を使う）または MMTK_MOVING=1（オブジェクトの移動を有効にする）を設定すると、これらの構成への対応がまだ追加されていないため、セグメンテーション違反などのビルドエラーが発生する可能性が高いことに注意してください。MMTK_BUILD=debug を設定すると、binding がデバッグビルドされます。これにより、MMTk 固有のエラーの特定に役立つログ情報が出力されます。

変数
MMTK_PLANImmixStickyImmix
MMTK_MOVING01
MMTK_BUILDreleasedebug

MMTK_PLAN だけを設定した場合、デフォルトでは非移動型のリリースビルドになります。

Building mmtk-julia from source

binding をソースからビルドすることもできます。その場合は変数 USE_BINARYBUILDER_MMTK_JULIA=0 を設定します。Julia のビルド時に、binding の最新リリース版がダウンロードされ、ビルドされます。この方法には Rust ツールチェーンのインストールが必要です。

git repository からカスタムバージョンをチェックアウトし、binding を含むディレクトリのパスを変数 MMTK_JULIA_DIR に設定すれば、binding のカスタムバージョンをビルドすることもできます。

MMTk を使った Julia のビルドについて詳しくは、binding リポジトリにある README ファイルを参照してください。

I've got a build error when building Julia with MMTk, what should I do?

MMTk を使って Julia をビルドしようとしてエラーが発生した場合、Julia の変更が binding にまだ反映されていないか、Julia 内の MMTk 固有コードに問題がある可能性があります。変更の例を以下に示します。

(1) Julia のオブジェクトのメモリレイアウトを変更する場合。binding は、Julia のコードから自動生成される Rust FFI バインディングに依存しています。これらのファイルは、rust-bindgen という名前のクレートを使って生成されます。ファイルを再生成するには、最新バージョンの mmtk-julia binding をチェックアウトし、ビルド対象の Julia のパスを変数 JULIA_PATH に設定してから、binding のディレクトリで make regen-bindgen-ffi を実行します。これにより、現在の FFI バインディングが削除され、JULIA_PATH の Julia コードに基づく新しいバージョンが生成されます。

(2) GC に渡すルートオブジェクトを変更する場合。Julia は関数 gcmarkroots で、オブジェクトの集合をルートとして GC に渡します。現時点では、この集合は Stock GC と MMTk の両方で一致している必要があります（関数 jl_gc_scan_vm_specific_roots）。

(3) オブジェクトのスキャン方法を変更する場合。MMTk は、Julia のオブジェクト内の参照を見つけるために、標準の GC と同じ方法を使います（gcmarkoutrefs を参照）。この関数のロジックを変更した場合は、binding 内の Rust コードにも反映する必要があります。該当するコードは scan Julia objects にあります。

上記のいずれにも該当しない場合は、Julia リポジトリに issue を作成し、GC: MMTK ラベルを付けてください。
