```julia
struct LimitedAccuracy
```

`LimitedAccuracy` lattice 要素は、再帰のヒューリスティックな打ち切りによって、実際の推論結果が近似値になったことを示すために使われます。たとえば、`A` と `B` から始まる、次のような2つの呼び出しスタックを考えてみましょう。

```julia
A -> C -> A -> D
B -> C -> A -> D
```

最初のケースでは、推論が `A->C->A` を循環と判断し、そうでなければ結果を得られた可能性がある場合でも、`C` について得られた結果を拡大していることがあります。この場合、`C` について推論された結果には、この lattice 型の注釈が付けられます。これは、得られた結果が、制限のない推論で得られる結果の上界であることを示します。特に、`B` から始まる呼び出しスタックでは、`A` の推論中に得られた不正確な可能性のある結果に汚染されることなく、推論が再実行されます。

注：逆方向については、保証するための対策を一切講じていません。たとえば、`B` が先に推論された場合、`C` について正確な結果をキャッシュし、`A` の推論時にその結果を再利用することがあります。これは、制限のために `A` の推論ではその結果を得られなかった場合でも同様です。推論結果が順序に依存するため望ましくありませんが、この状況をどうすれば回避できるのかは明らかではありません。

`LimitedAccuracy` 要素は、別の lattice 要素（これを `T` と呼びます）をラップし、さらに、制限が発生した原因となる `causes` を追跡します。lattice 要素として、`LimitedAccuracy(T)` は対応する lattice 要素 `T` より ε だけ小さいものとみなされます。ただし特に、`⊑ T` であるすべての lattice 要素（`T` と等しいものを除く）も、`⊑ LimitedAccuracy(T)` です。

`causes` リストは、特定の制限原因が避けられないかどうかを判定し、避けられない場合は `LimitedAccuracy(T)` を `T` に戻すために使われます。たとえば、上記の呼び出しスタックで、`A` への呼び出しが必ず `A` に戻るのであれば、`A` から開始するか、`B` 経由で到達するかは関係ありません。`A` に到達する推論では、必ず同じ制限に達するため、その結果をキャッシュできます。
