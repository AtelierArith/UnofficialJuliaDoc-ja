```julia
tree_hash([ predicate, ] tarball;
          [ algorithm = "git-sha1", ]
          [ skip_empty = false ]) -> hash::String

    predicate  :: Header --> Bool
    tarball    :: Union{AbstractString, AbstractCmd, IO}
    algorithm  :: AbstractString
    skip_empty :: Bool
```

tarball に含まれるファイルツリーのツリーハッシュ値を計算します。デフォルトでは、git のツリーハッシュアルゴリズムと SHA1 暗号学的ハッシュ関数（現在の git のバージョンと同様）を使用します。つまり、git が表現できるファイルツリー（ファイル、シンボリックリンク、空でないディレクトリのみを含むツリー）であれば、この関数が計算するハッシュ値は、git がそのファイルツリーに対して計算するハッシュ値と一致します。tarball では空のディレクトリを含むファイルツリーも表現できますが、git は空のディレクトリを保存できません。この関数は空のディレクトリを含むツリーのハッシュも生成できますが、デフォルトでは（この動作を変更する方法については下記の `skip_empty` を参照）、空のディレクトリを省いた tarball のハッシュとは異なります。つまり、このハッシュ関数は git が表現できるすべてのツリーについて git と同じ結果を返しつつ、git では表現できないツリーにも一貫した方法でハッシュ可能な範囲を広げています。

`predicate` 関数が渡された場合、`tarball` の処理中に見つかった各 `Header` オブジェクトに対してその関数が呼び出され、`predicate(hdr)` が true の場合に限り、そのエントリがハッシュ化されます。これにより、アーカイブの一部だけを選択してハッシュ化したり、`extract` がエラーをスローするエントリをスキップしたり、ハッシュ計算中に展開された内容を記録したりできます。

述語関数に渡される前に、`Header` オブジェクトには tarball の生のヘッダーからいくつか変更が加えられます。`path` フィールドは、`.` エントリを取り除き、連続する複数のスラッシュを単一のスラッシュに置き換える形で正規化されます。エントリの型が `:hardlink` の場合は、リンク先のエントリのパスと一致するよう、リンク先パスも同じ方法で正規化されます。また、サイズフィールドにはリンク先パスのサイズが設定されます（リンク先は、すでに確認済みのファイルでなければなりません）。

現在、`algorithm` に指定できる値は `git-sha1`（デフォルト）と `git-sha256` です。後者は `git-sha1` と同じ基本アルゴリズムを使いますが、SHA1 ハッシュ関数を SHA2-256 に置き換えます。SHA2-256 は、SHA1 に対する既知の攻撃を受けて、将来 git が採用する予定のハッシュ関数です。今後、ほかのファイルツリーハッシュアルゴリズムもサポートされる可能性があります。

`skip_empty` オプションは、tarball 内にある、ファイルもシンボリックリンクも再帰的に含まないディレクトリをハッシュに含めるか、無視するかを制御します。一般に、tarball やファイルツリーの内容をハッシュ化する場合、空でないディレクトリだけでなく、すべてのディレクトリが対象となるため、デフォルトでは空のディレクトリもハッシュに含めます。それでは、なぜこの関数には空のディレクトリをスキップするオプションがあるのでしょうか。git は空のディレクトリを保存せず、リポジトリに追加しようとしても無視するためです。そのため、ファイルを git リポジトリに追加してから git にツリーハッシュを問い合わせて参照用のツリーハッシュを計算すると、得られるハッシュ値は、`tree_hash` に `skip_empty=true` を指定した場合に計算されるハッシュ値と一致します。つまり、このオプションを使うと、`tree_hash` は空のディレクトリを含むツリーに対する git のハッシュ計算を再現できます。ただし、空のディレクトリを含む可能性のあるツリー（つまり、git リポジトリ由来ではないツリー）をハッシュ化する場合は、空のディレクトリを無視しないツール（このツールなど）を使うことをおすすめします。
