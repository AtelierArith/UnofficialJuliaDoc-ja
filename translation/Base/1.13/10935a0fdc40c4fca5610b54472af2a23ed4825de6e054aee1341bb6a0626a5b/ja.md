`AbstractString` 型は、Julia におけるすべての文字列実装のスーパータイプです。文字列は、`AbstractChar` 型で表される [Unicode](https://unicode.org/) コードポイントの列をエンコードしたものです。Julia の文字列には、いくつかの前提があります。

  * 文字列は、固定サイズの「コードユニット」でエンコードされます。

      * コードユニットは `codeunit(s, i)` で取り出せます。
      * 最初のコードユニットのインデックスは `1` です。
      * 最後のコードユニットのインデックスは `ncodeunits(s)` です。
      * `1 ≤ i ≤ ncodeunits(s)` が範囲内であるようなインデックス `i` は、すべて有効です。
  * 文字列のインデックス付けは、これらのコードユニットを基準に行われます。

      * 有効な文字列インデックス `i` を指定して `s[i]` を呼び出すと、文字を取り出せます。
      * 文字列内の各 `AbstractChar` は、1つ以上のコードユニットでエンコードされます。
      * `AbstractChar` の最初のコードユニットのインデックスだけが有効なインデックスです。
      * `AbstractChar` のエンコードは、その前後にある内容に依存しません。
      * 文字列のエンコードは [self-synchronizing](https://en.wikipedia.org/wiki/Self-synchronizing_code) です。つまり、`isvalid(s, i)` は O(1) です。

文字列からコードユニット、文字、部分文字列を取り出す関数の中には、範囲外または無効な文字列インデックスを渡すとエラーになるものがあります。`codeunit(s, i)` と `s[i]` もこれに該当します。一方、文字列インデックスの算術演算を行う関数は、より緩やかな方法でインデックスを扱います。範囲内では最も近い有効な文字列インデックスを返し、範囲外では、文字列の両側に無限個の文字が埋め込まれているかのように動作します。通常、これらの仮想的な埋め込み文字のコードユニット長は `1` ですが、文字列型によっては、実装に適した別の「仮想」文字サイズを選ぶこともできます（たとえば、部分文字列では、インデックス算術をビュー先の元の文字列に委ねる場合があります）。インデックス算術を目的とする `thisind`、`nextind`、`prevind` などが、こうした緩やかなインデックス処理を行う関数です。このモデルでは、範囲外のインデックスを中間値として使っても、文字の取得に使わない限りインデックス算術を行えます。そのため、境界条件に対処するコードを避けられることがよくあります。
