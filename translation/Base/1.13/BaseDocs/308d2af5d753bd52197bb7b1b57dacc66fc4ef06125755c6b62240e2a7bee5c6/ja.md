```julia
Base.donotdelete(args...)
```

この関数は、自身と渡されたすべての引数がデッドコード除去（DCE）されるのを防ぎます。それ以外の点では、可能な限り軽量なバリアです。特に、GCセーフポイントではなく、観測可能なヒープ効果をモデル化せず、それ自体がコードに展開されることもありません。また、ほかの副作用との実行順序が入れ替わることがあります（ただし、実行回数の合計は変わりません）。

この関数の有用なモデルとして、引数からすべてのメモリ `reachable` をハッシュし、プログラムの動作にはそれ以外の影響を与えない、観測可能な何らかのサイドチャネルを通じてその情報を外部に逃がす、というものがあります。もちろん、これはあくまでモデルです。この関数は何もせず、`nothing` を返します。

これは、`args` が実際に計算されることを保証したいベンチマークでの使用を想定しています。（そうでないと、ベンチマークの結果が使われていないことをDCEが検出し、ベンチマークのコード全体を削除する可能性があります。）

!!! note
    `donotdelete` は定数畳み込みには影響しません。たとえば、`donotdelete(1+1)` では、実行時に加算命令を実行する必要はなく、コードは意味的に `donotdelete(2).` と等価です。


!!! note
    この組み込み関数は、*到達不能*であるためにデッドとなっているコードの意味には影響しません。たとえば、関数 `f(x) = false && donotdelete(x)` の本体は、全体を削除できる場合があります。この組み込み関数の意味が保証するのは、*この組み込み関数が意味的に実行される場合*に限り、その引数の値が利用可能だったプログラム状態（レジスタ内、メモリ内など）が存在することだけです。


!!! compat "Julia 1.8"
    このメソッドはJulia 1.8で追加されました。


# Examples

```julia
function loop()
    for i = 1:1000
        # The compiler must guarantee that there are 1000 program points (in the correct
        # order) at which the value of `i` is in a register, but has otherwise
        # total control over the program.
        donotdelete(i)
    end
end
```
