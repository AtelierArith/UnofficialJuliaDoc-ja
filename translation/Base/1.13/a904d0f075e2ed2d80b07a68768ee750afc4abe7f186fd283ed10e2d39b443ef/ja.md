```julia
==(x, y)
```

汎用の等価演算子です。[`===`](@ref) にフォールバックします。インスタンスが表す抽象的な値に基づいて、等価性の概念を持つすべての型で実装する必要があります。たとえば、数値型は型を無視して数値として比較されます。文字列はエンコーディングを無視し、文字の並びとして比較されます。同じ型のコレクションは通常、キーの集合を比較し、それらが `==` であれば、各キーに対応する値を比較して、すべての組が `==` の場合に true を返します。通常、正確な型など、その他のプロパティは考慮されません。

この演算子は浮動小数点数に対して IEEE のセマンティクスに従います。`0.0 == -0.0` と `NaN != NaN`。

結果の型は `Bool` です。ただし、オペランドのいずれかが [`missing`](@ref) の場合は、`missing` が返されます（[three-valued logic](https://en.wikipedia.org/wiki/Three-valued_logic)）。コレクションは通常、[`all`](@ref) に似た三値論理を実装します。オペランドに missing 値が含まれていて、その他のすべての組が等しい場合は missing を返します。常に `Bool` の結果を得るには、[`isequal`](@ref) または [`===`](@ref) を使用してください。

# Implementation

新しい数値型では、その型の引数を2つ取るこの関数を実装し、可能であれば昇格規則に従って他の型との比較も処理する必要があります。

等価性とハッシュは密接に関係しています。[`isequal`](@ref) と見なされる2つの値は、同じ [`hash`](@ref) を持たなければなりません。また、デフォルトでは `isequal` は `==` にフォールバックします。型が `==` や [`isequal`](@ref) の動作をカスタマイズする場合は、[`hash`](@ref) も同様に実装し、`isequal` と `hash` が一致するようにする必要があります。`Set`s、`Dict`s、およびその他多くの内部実装は、この不変条件が成り立つことを前提としています。

ある型が `==`、[`isequal`](@ref)、[`isless`](@ref) を定義する場合は、比較の一貫性を保つため、[`<`](@ref) も実装する必要があります。
