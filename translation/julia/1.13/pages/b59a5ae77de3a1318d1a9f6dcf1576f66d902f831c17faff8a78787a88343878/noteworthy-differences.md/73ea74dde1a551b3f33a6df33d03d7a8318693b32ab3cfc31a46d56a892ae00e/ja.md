# Noteworthy Differences from other Languages

## Noteworthy differences from MATLAB

MATLABユーザーにはJuliaの構文がなじみ深く感じられるかもしれませんが、JuliaはMATLABのクローンではありません。構文にも機能にも大きな違いがあります。以下は、MATLABに慣れたJuliaユーザーがつまずきやすい、主な相違点です。

  * Juliaの配列のインデックス指定には角括弧を使います。`A[i,j]`。
  * Juliaの配列は、別の変数に代入してもコピーされません。`A = B`の後で`B`の要素を変更すると、`A`も変更されます。これを避けるには`A = copy(B)`を使ってください。
  * Juliaの値は、関数に渡してもコピーされません。関数が配列を変更すると、その変更は呼び出し元にも反映されます。
  * Juliaでは、代入文によって配列が自動的に拡張されることはありません。MATLABでは`a(4) = 3.2`で配列`a = [0 0 0 3.2]`を作成でき、`a(5) = 7`で`a = [0 0 0 3.2 7]`へと拡張できます。一方、対応するJuliaの文`a[5] = 7`は、`a`の長さが5未満の場合や、この文で識別子`a`を初めて使用する場合にはエラーを送出します。Juliaには[`push!`](@ref)と[`append!`](@ref)があり、MATLABの`a(end+1) = val`よりもはるかに効率よく`Vector`を拡張できます。
  * 虚数単位`sqrt(-1)`は、Juliaでは[`im`](@ref)で表します。MATLABのように`i`や`j`ではありません。
  * Juliaでは、小数点のない数値リテラル（`42`など）は浮動小数点数ではなく整数を生成します。このため、浮動小数点数を想定する演算では定義域エラーが送出されることがあります。たとえば、`julia> a = -1; 2^a`は結果が整数にならないため、定義域エラーを送出します（詳細は[the FAQ entry on domain errors](@ref faq-domain-errors)を参照）。
  * Juliaでは、複数の値を返したり代入したりする場合にタプルを使います。たとえば`(a, b) = (1, 2)`や`a, b = 1, 2`です。MATLABでは返される値の数に応じて追加の処理を行うために`nargout`をよく使いますが、Juliaにはこれに相当するものはありません。代わりに、オプション引数やキーワード引数で同様の機能を実現できます。
  * Juliaには真の1次元配列があります。列ベクトルのサイズは`N`であり、`Nx1`ではありません。たとえば、[`rand(N)`](@ref)は1次元配列を作成します。
  * Juliaでは、`[x,y,z]`は常に`x`、`y`、`z`を含む3要素の配列を構築します。

      * 第1次元（「縦方向」）に連結するには、[`vcat(x,y,z)`](@ref)を使うか、セミコロンで区切ります（`[x; y; z]`）。
      * 第2次元（「横方向」）に連結するには、[`hcat(x,y,z)`](@ref)を使うか、空白で区切ります（`[x y z]`）。
      * ブロック行列を構築する（最初の2つの次元に沿って連結する）には、[`hvcat`](@ref)を使うか、空白とセミコロンを組み合わせます（`[a b; c d]`）。
  * Juliaでは、`a:b`と`a:b:c`は`AbstractRange`オブジェクトを構築します。MATLABのように全要素を格納したベクトルを構築するには、[`collect(a:b)`](@ref)を使います。ただし、通常は`collect`を呼び出す必要はありません。`AbstractRange`オブジェクトは、ほとんどの場合、通常の配列と同じように動作しますが、値を遅延計算するため効率的です。完全な配列ではなく専用のオブジェクトを作成するこのパターンは頻繁に使われており、[`range`](@ref)などの関数や、`enumerate`、`zip`などのイテレーターでも見られます。こうした専用オブジェクトは、たいてい通常の配列と同じように使えます。
  * Juliaの関数は、関数定義で返す変数名を列挙するのではなく、最後の式の値、または`return`キーワードで指定した値を返します（詳細は[The return Keyword](@ref)を参照）。
  * Juliaのスクリプトには任意の数の関数を含めることができ、ファイルを読み込むとすべての定義が外部から参照可能になります。現在の作業ディレクトリ以外にあるファイルからも、関数定義を読み込めます。
  * Juliaでは、[`sum`](@ref)、[`prod`](@ref)、[`maximum`](@ref)などのリダクションを`sum(A)`のように単一の引数で呼び出すと、`A`が多次元であっても、配列の全要素に対して処理が行われます。
  * Juliaでは、引数のない関数を呼び出す場合にも、[`rand()`](@ref)のように丸括弧が必要です。
  * Juliaでは、文の末尾にセミコロンを付けることは推奨されません。文の結果は自動的には表示されず（対話プロンプトを除く）、コードの行をセミコロンで終える必要はありません。特定の出力を表示するには[`println`](@ref)または[`@printf`](@ref)を使えます。
  * Juliaでは、`A`と`B`が配列の場合、`A == B`のような論理比較演算はブール値の配列を返しません。代わりに`A .== B`を使ってください。[`<`](@ref)、[`>`](@ref)など、ほかのブール演算子も同様です。
  * Juliaでスカラー値を返す関数を配列の要素ごとに適用するには、ブロードキャスト構文を使います。つまり、`f(A)`ではなく`f.(A)`と書きます。両方の演算が定義されていても、意味が異なる場合があります。MATLABでは`exp(A)`が要素ごとの適用で、`expm(A)`が[matrix exponential](https://en.wikipedia.org/wiki/Matrix_exponential)ですが、Juliaでは`exp.(A)`が要素ごとの適用で、`exp(A)`が行列指数関数です。
  * Juliaの演算子[`&`](@ref)、[`|`](@ref)、[`⊻`](@ref xor)（[`xor`](@ref)）は、それぞれMATLABの`and`、`or`、`xor`に相当するビット演算を行います。その優先順位は、Cとは異なり、Pythonのビット演算子に似ています。配列に対してブール論理演算子を適用する（MATLABの`&`や`|`の一般的な使い方に相当する）には、Juliaの短絡評価演算子`.&&`と`.||`をブロードキャストしてください。たとえば、配列`A`の要素が1または2に等しいかどうかを調べるには、`A .== 1 .|| A .== 2`を使えます。
  * Juliaでは、`xs=[1,2]; f(xs...)`のように、スプラット演算子`...`を使ってコレクションの各要素を関数の引数として渡せます。
  * Juliaの[`svd`](@ref)は、特異値を密な対角行列ではなくベクトルとして返します。
  * Juliaでは、コードの行を継続するために`...`を使うことはありません。未完の式は自動的に次の行へ継続されます。
  * JuliaでもMATLABでも、対話セッションで最後に実行された式の値が変数`ans`に設定されます。ただし、MATLABとは異なり、Juliaのコードを非対話モードで実行する場合には`ans`は設定されません。
  * Juliaの`struct`は、MATLABの`class`とは異なり、実行時の動的なフィールド追加をサポートしていません。代わりに[`Dict`](@ref)を使ってください。JuliaのDictは順序を保持しません。
  * Juliaではモジュールごとに独自のグローバルスコープ／名前空間がありますが、MATLABにはグローバルスコープが1つしかありません。
  * MATLABで不要な値を取り除く一般的な方法は、論理インデックスを使うことです。たとえば式`x(x>3)`や、`x`をその場で変更する文`x(x>3) = []`がこれに当たります。一方、Juliaには高階関数[`filter`](@ref)と[`filter!`](@ref)があるため、直訳に相当する`x[x.>3]`と`x = x[x.>3]`の代わりに、`filter(z->z>3, x)`と`filter!(z->z>3, x)`と書けます。[`filter!`](@ref)を使うと、一時配列の使用を減らせます。
  * 前項に関連して、特定の条件を満たす値を置き換える処理、たとえば行列の全要素に対するしきい値処理は、MATLABでは`A(A < threshold) = 0`のように実現できます。Juliaでこれに相当するのは`A[A .< threshold] .= 0`です。
  * MATLABで`vertcat(A{:})`のようにセル配列の全要素を取り出す（「参照を外す」）操作に相当するものは、Juliaではスプラット演算子を使って`vcat(A...)`のように書きます。
  * Juliaの`adjoint`関数は共役転置を行います。MATLABの`adjoint`は「余因子行列（adjugate）」または古典随伴行列、すなわち各成分の余因子を並べた行列の転置を返します。
  * Juliaではa^b^cはa^(b^c)として評価されますが、MATLABでは(a^b)^cとして評価されます。

## Noteworthy differences from R

Juliaの目標の1つは、データ分析と統計プログラミングに有用な言語を提供することです。RからJuliaに移行するユーザーにとって、主な相違点は次のとおりです。

  * Juliaの単一引用符は、文字列ではなく文字を囲みます。
  * Juliaでは、文字列へのインデックス指定で部分文字列を作成できます。Rでは、部分文字列を作成する前に文字列を文字ベクトルへ変換する必要があります。
  * Juliaでは、Rとは異なり、Pythonと同様に三重引用符`""" ... """`で文字列を作成できます。この構文は、改行を含む文字列を構築するのに便利です。
  * Juliaでは可変長引数をスプラット演算子`...`で指定し、この演算子は必ず特定の変数名の後に置きます。Rでは`...`を単独で使用できる点が異なります。
  * Juliaでモジュロ演算に使うのは`mod(a, b)`であり、`a %% b`ではありません。Juliaの`%`は剰余演算子です。
  * Juliaでは角括弧を使ってベクトルを構築します。Juliaの`[1, 2, 3]`は、Rの`c(1, 2, 3)`に相当します。
  * Juliaでは、すべてのデータ構造が論理インデックスをサポートしているわけではありません。また、Juliaで論理インデックスに使えるのは、インデックス指定の対象と同じ長さのベクトルだけです。たとえば、次のようになります。

      * Rでは、`c(1, 2, 3, 4)[c(TRUE, FALSE)]`は`c(1, 3)`と同等です。
      * Rでは、`c(1, 2, 3, 4)[c(TRUE, FALSE, TRUE, FALSE)]`は`c(1, 3)`と同等です。
      * Juliaでは、`[1, 2, 3, 4][[true, false]]`は[`BoundsError`](@ref)を送出します。
      * Juliaでは、`[1, 2, 3, 4][[true, false, true, false]]`の結果は`[1, 3]`になります。
  * 多くの言語と同様に、Juliaでは長さの異なるベクトル間の演算が常に許されるわけではありません。これは、ベクトルが共通のインデックス範囲を持ちさえすればよいRとは異なります。たとえば、`c(1, 2, 3, 4) + c(1, 2)`はRでは有効ですが、対応する`[1, 2, 3, 4] + [1, 2]`はJuliaではエラーを送出します。
  * Juliaでは、コードの意味が変わらない場合、末尾のカンマを省略しても付けてもかまいません。このため、配列のインデックス指定でRユーザーが混乱することがあります。たとえば、Rの`x[1,]`は行列の第1行を返します。しかしJuliaではカンマが無視されるため、`x[1,] == x[1]`となり、最初の要素を返します。行を取り出すには、`x[1,:]`のように、必ず`:`を使ってください。
  * Juliaの[`map`](@ref)は、Rの`lapply(<structure>, function, ...)`とは異なり、最初に関数、その後にその関数の引数を受け取ります。同様に、Rの`apply(X, MARGIN, FUN, ...)`に相当するJuliaの[`mapslices`](@ref)でも、関数が第1引数になります。
  * Rにおける多変量のapply、たとえば`mapply(choose, 11:13, 1:3)`は、Juliaでは`broadcast(binomial, 11:13, 1:3)`と書けます。同等の処理として、Juliaには関数をベクトル化する短いドット構文`binomial.(11:13, 1:3)`もあります。
  * Juliaでは、`if`などの条件ブロック、`while`／`for`などのループブロック、および関数の終わりを`end`で表します。1行の`if ( cond ) statement`の代わりに、Juliaでは`if cond; statement; end`、`cond && statement`、`!cond || statement`という形式の文を使えます。後者2つの構文で代入文を使う場合は、`cond && (x = value)`のように明示的に丸括弧で囲む必要があります。
  * Juliaでは、`<-`、`<<-`、`->`は代入演算子ではありません。
  * Juliaの`->`は無名関数を作成します。
  * Juliaの[`*`](@ref)演算子は、Rとは異なり行列積を計算できます。`A`と`B`が行列の場合、Juliaの`A * B`は行列積を表し、Rの`A %*% B`に相当します。Rでは、これと同じ記法で要素ごとの積（アダマール積）を計算します。Juliaで要素ごとの積を計算するには、`A .* B`と書く必要があります。
  * Juliaでは、行列の転置には`transpose`関数を、共役転置には`'`演算子または`adjoint`関数を使います。したがって、Juliaの`transpose(A)`はRの`t(A)`に相当します。また、Juliaでは`permutedims`関数で非再帰的な転置を行えます。
  * Juliaでは、`if`文や`for`／`while`ループを書く際に丸括弧は不要です。`for (i in c(1, 2, 3))`ではなく`for i in [1, 2, 3]`を、`if (i == 1)`ではなく`if i == 1`を使ってください。
  * Juliaでは、数値`0`と`1`をブール値として扱いません。`if`文はブール値しか受け付けないため、Juliaで`if (1)`とは書けません。代わりに、`if true`、`if Bool(1)`、または`if 1==1`と書けます。
  * Juliaには`nrow`と`ncol`はありません。`nrow(M)`の代わりに`size(M, 1)`を、`ncol(M)`の代わりに`size(M, 2)`を使ってください。
  * Juliaでは、スカラー、ベクトル、行列を明確に区別します。Rでは`1`と`c(1)`は同じですが、Juliaでは互いに置き換えて使うことはできません。
  * Juliaの[`diag`](@ref)と[`diagm`](@ref)は、Rのものとは異なります。
  * Juliaでは、代入演算の左辺に関数呼び出しの結果を置いて代入することはできません。`diag(M) = fill(1, n)`とは書けません。
  * Juliaでは、メインの名前空間に多数の関数を詰め込むことは推奨されません。Juliaの統計機能の大半は、[JuliaStats organization](https://github.com/JuliaStats)の下にある[packages](https://pkg.julialang.org/)にあります。たとえば、次のとおりです。

      * 確率分布に関する関数は[Distributions package](https://github.com/JuliaStats/Distributions.jl)で提供されています。
      * [DataFrames package](https://github.com/JuliaData/DataFrames.jl)はデータフレームを提供します。
      * 一般化線形モデルは[GLM package](https://github.com/JuliaStats/GLM.jl)で提供されています。
  * Juliaにはタプルと本格的なハッシュテーブルがありますが、R形式のリストはありません。複数の項目を返す場合は、通常、タプルまたは名前付きタプルを使うのが適切です。`list(a = 1, b = 2)`ではなく、`(1, 2)`または`(a=1, b=2)`を使ってください。
  * Juliaでは、ユーザーが独自の型を作成することを推奨しています。これはRのS3やS4オブジェクトよりも使いやすいものです。Juliaの多重ディスパッチにより、`table(x::TypeA)`と`table(x::TypeB)`は、Rの`table.TypeA(x)`と`table.TypeB(x)`のように動作します。
  * Juliaでは、代入時や関数に渡す際に値がコピーされることはありません。関数が配列を変更すると、その変更は呼び出し元にも反映されます。これはRとは大きく異なり、大きなデータ構造をはるかに効率よく処理する新たな関数を作成できます。
  * Juliaでベクトルや行列を連結するには、Rのような`c`、`rbind`、`cbind`ではなく、[`hcat`](@ref)、[`vcat`](@ref)、[`hvcat`](@ref)を使います。
  * Juliaでは、`a:b`のような範囲は、Rのようにベクトルの省略記法ではなく、反復処理に使う専用の`AbstractRange`オブジェクトです。範囲をベクトルに変換するには[`collect(a:b)`](@ref)を使ってください。
  * `:`演算子の優先順位は、RとJuliaで異なります。具体的には、Juliaでは算術演算子の優先順位が`:`演算子より高く、Rではその逆です。たとえば、Juliaの`1:n-1`は、Rの`1:(n-1)`に相当します。
  * Juliaの[`max`](@ref)と[`min`](@ref)は、それぞれRの`pmax`と`pmin`に相当しますが、両方の引数の次元が一致している必要があります。また、[`maximum`](@ref)と[`minimum`](@ref)はRの`max`と`min`の代わりになりますが、重要な違いがあります。
  * Juliaの[`sum`](@ref)、[`prod`](@ref)、[`maximum`](@ref)、[`minimum`](@ref)は、対応するRの関数とは異なります。いずれも、演算を行う次元を指定するオプションのキーワード引数`dims`を受け取ります。たとえば、Juliaの`A = [1 2; 3 4]`とRの`B <- rbind(c(1,2),c(3,4))`が同じ行列であるとします。このとき、`sum(A)`は`sum(B)`と同じ結果を返しますが、`sum(A, dims=1)`は各列の和を含む行ベクトル、`sum(A, dims=2)`は各行の和を含む列ベクトルになります。これは、個別の関数`colSums(B)`と`rowSums(B)`でこれらの機能を提供するRの動作とは対照的です。キーワード引数`dims`がベクトルの場合は、和を取るすべての次元を指定します。その際、集計対象の配列の次元数は維持されます。たとえば`sum(A, dims=(1,2)) == hcat(10)`です。第2引数に関するエラーチェックは行われない点に注意してください。
  * Juliaには、引数を変更できる関数がいくつもあります。たとえば、[`sort`](@ref)と[`sort!`](@ref)の両方があります。
  * Rで性能を得るにはベクトル化が必要です。Juliaでは、ほぼその逆です。ベクトル化せずにループを使うことで、最も高性能なコードになることがよくあります。
  * Juliaは即時評価を行い、R形式の遅延評価はサポートしていません。多くのユーザーにとって、これはクォートせずに扱う式や列名がごく少ないことを意味します。
  * Juliaは`NULL`型をサポートしていません。最も近いものは[`nothing`](@ref)ですが、リストではなくスカラー値として動作します。`is.null(x)`ではなく`x === nothing`を使ってください。
  * Juliaでは、欠損値は`NA`ではなく[`missing`](@ref)オブジェクトで表します。`is.na(x)`ではなく、[`ismissing(x)`](@ref)（ベクトルの要素ごとの処理には`ismissing.(x)`）を使ってください。一般に、`na.rm=TRUE`の代わりには[`skipmissing`](@ref)関数を使います（ただし、特定の場合には関数が`skipmissing`引数を受け取ることもあります）。
  * Juliaには、Rの`assign`や`get`に相当するものはありません。
  * Juliaでは、`return`に丸括弧は不要です。
  * Rで不要な値を取り除く一般的な方法は、論理インデックスを使うことです。たとえば式`x[x>3]`や、`x`をその場で変更する文`x = x[x>3]`がこれに当たります。一方、Juliaには高階関数[`filter`](@ref)と[`filter!`](@ref)があるため、直訳に相当する`x[x.>3]`と`x = x[x.>3]`の代わりに、`filter(z->z>3, x)`と`filter!(z->z>3, x)`と書けます。[`filter!`](@ref)を使うと、一時配列の使用を減らせます。

## Noteworthy differences from Python

  * Juliaの`for`、`if`、`while`などのブロックは、`end`キーワードで終わります。Pythonとは異なり、インデントの深さに意味はありません。また、Pythonと違ってJuliaには`pass`キーワードがありません。
  * Juliaでは、文字列を二重引用符（`"text"`）で表し、複数行の文字列には二重引用符を3つ並べて使います。一方Pythonでは、単一引用符（`'text'`）と二重引用符（`"text"`）のどちらでも文字列を表せます。Juliaでは単一引用符は文字に使います（`'c'`）。
  * Juliaで文字列を連結するには、Pythonのように`+`ではなく、`*`を使います。同様に、文字列の繰り返しには`*`ではなく`^`を使います。Pythonのような文字列リテラルの暗黙の連結（たとえば`'ab' 'cd' == 'abcd'`）は、Juliaでは行われません。
  * 柔軟ですが低速なPythonのリストに相当するのは、Juliaの`Vector{Any}`型、より一般的には`Vector{T}`です。ここで`T`は非具象の要素型です。NumPy配列のように要素をその場に格納する「高速な」配列（`dtype`が`np.float64`、`[('f1', np.uint64), ('f2', np.int32)]`などである配列）は、`Array{T}`で表せます。ここで`T`は具象かつ不変の要素型です。これには`Float64`、`Int32`、`Int64`などの組み込み型だけでなく、`Tuple{UInt64,Float64}`のようなより複雑な型や、多くのユーザー定義型も含まれます。
  * Juliaでは、配列や文字列などのインデックスは0ではなく1から始まります。
  * Pythonとは異なり、Juliaのスライスによるインデックス指定は末尾の要素も含みます。Juliaの`a[2:3]`は、Pythonの`a[1:3]`に相当します。
  * Pythonとは異なり、Juliaでは[AbstractArrays with arbitrary indexes](https://julialang.org/blog/2017/04/offset-arrays/)が可能です。Pythonで特別な意味を持つ負のインデックス指定`a[-1]`と`a[-2]`は、Juliaでは`a[end]`と`a[end-1]`と書きます。
  * Juliaで最後の要素までインデックス指定するには`end`が必要です。Juliaの`x[2:end]`は、Pythonの`x[1:]`に相当します。
  * Juliaでは、オブジェクトの前に`:`を置くと[`Symbol`](@ref)を作成するか、式を*クォート*します。したがって、`x[:5]`は`x[5]`と同じです。配列の先頭から`n`個の要素を取得したい場合は、範囲によるインデックス指定を使ってください。
  * Juliaの範囲によるインデックス指定は`x[start:step:stop]`という形式ですが、Pythonでは`x[start:(stop+1):step]`という形式です。したがって、Pythonの`x[0:10:2]`はJuliaの`x[1:2:10]`に相当します。同様に、配列の逆順を表すPythonの`x[::-1]`は、Juliaの`x[end:-1:1]`に相当します。
  * Juliaでは、配列のインデックス指定と同じ構文`start:step:stop`を使って、範囲を単独で構築できます。`range`関数もサポートしています。
  * Juliaで`X[[1,2], [1,3]]`のように配列を使って行列をインデックス指定すると、第1・第2行と第1・第3列の交点を含む部分行列を参照します。Pythonの`X[[1,2], [1,3]]`は、行列のセル`[1,1]`と`[2,3]`の値を含むベクトルを参照します。Juliaの`X[[1,2], [1,3]]`はPythonの`X[np.ix_([0,1],[0,2])]`に相当します。Pythonの`X[[0,1], [0,2]]`はJuliaの`X[[CartesianIndex(1,1), CartesianIndex(2,3)]]`に相当します。
  * Juliaには行継続の構文がありません。行末までの入力が完全な式であれば、その式は完了したとみなされます。そうでなければ入力が継続されます。式を強制的に継続させる方法の1つは、丸括弧で囲むことです。
  * Juliaの配列は列優先（Fortran順）ですが、NumPyの配列はデフォルトでは行優先（C順）です。配列をループで処理する際に最適な性能を得るには、JuliaではNumPyに対してループの順序を逆にする必要があります（[relevant section of Performance Tips](@ref man-performance-column-major)を参照）。
  * Juliaの更新演算子（`+=`、`-=`など）は、NumPyとは異なり、*その場で変更する演算ではありません*。つまり、`A = [1, 1]; B = A; B += [3, 3]`は`A`内の値を変更せず、名前`B`を右辺`B = B + 3`の結果である新しい配列に再束縛します。その場で変更するには、`B .+= 3`（[dot operators](@ref man-dot-operators)も参照）、明示的なループ、または`InplaceOps.jl`を使ってください。
  * Juliaでは、メソッドを呼び出すたびに関数引数のデフォルト値を評価します。Pythonでは、関数定義時に一度だけ評価する点が異なります。たとえば、関数`f(x=rand()) = x`は引数なしで呼び出すたびに新しい乱数を返します。一方、関数`g(x=[1,2]) = push!(x,3)`は、`g()`として呼び出すたびに`[1,2,3]`を返します。
  * Juliaでは、キーワード引数はキーワードを使って渡す必要があります。Pythonでは通常、位置引数としても渡せる点が異なります。キーワード引数を位置引数として渡そうとすると、メソッドシグネチャが変わり、`MethodError`が発生するか、意図しないメソッドが呼び出されます。
  * Juliaの`%`は剰余演算子ですが、Pythonではモジュロ演算子です。
  * Juliaでよく使う`Int`型は、機械整数型（`Int32`または`Int64`）に相当します。これは、`int`が任意精度整数であるPythonとは異なります。したがって、Juliaの`Int`型ではオーバーフローが起こり、`2^64 == 0`となります。より大きな値が必要な場合は、`Int128`、[`BigInt`](@ref)、あるいは`Float64`のような浮動小数点型など、適切な別の型を使ってください。
  * 虚数単位`sqrt(-1)`は、Juliaでは`im`で表します。Pythonのように`j`ではありません。
  * Juliaのべき乗演算子は`^`であり、Pythonのように`**`ではありません。
  * Juliaでは、null値を`Nothing`型の`nothing`で表します。Pythonでは`NoneType`型の`None`を使います。
  * Juliaでは、行列型に対する標準の演算子は行列演算ですが、Pythonでは要素ごとの演算です。`A`と`B`がどちらも行列の場合、Juliaの`A * B`は行列積を計算し、Pythonのような要素ごとの積にはなりません。Juliaの`A * B`はPythonの`A @ B`に相当し、Pythonの`A * B`はJuliaの`A .* B`に相当します。
  * Juliaでスカラー値を返す関数を配列の要素ごとに適用するには、ブロードキャスト構文を使います。つまり、`f(A)`ではなく`f.(A)`と書きます。両方の演算が定義されていても、意味が異なる場合があります。`numpy.exp(A)`は要素ごとの適用で、`scipy.linalg.expm(A)`は[matrix exponential](https://en.wikipedia.org/wiki/Matrix_exponential)ですが、Juliaでは`exp.(A)`が要素ごとの適用で、`exp(A)`が行列指数関数です。
  * Juliaの随伴演算子`'`は、ベクトルの随伴（行ベクトルの遅延表現）を返します。一方、Pythonでベクトルに転置演算子`.T`を適用しても、元のベクトルがそのまま返ります（何も行われません）。
  * Juliaでは、関数に複数の具体的な実装（*メソッド*と呼びます）を持たせることができ、呼び出し時のすべての引数の型に基づく多重ディスパッチによって実装を選択します。これに対してPythonの関数は実装が1つで、多相性を持ちません（ただしPythonのメソッド呼び出しは別の構文を使い、メソッドのレシーバーに基づくディスパッチが可能です）。
  * Juliaにはクラスがありません。代わりに、データを含むがメソッドは含まない構造体（可変または不変）があります。
  * Pythonでのクラスインスタンスのメソッド呼び出し（`x = MyClass(*args); x.f(y)`）は、Juliaでは`x = MyType(args...); f(x, y)`のような関数呼び出しに相当します。一般に、多重ディスパッチはPythonのクラスシステムよりも柔軟で強力です。
  * Juliaの構造体が持てるスーパータイプは抽象型1つだけですが、Pythonのクラスは1つ以上のスーパークラス（抽象または具象）を継承できます。
  * Juliaの論理的なプログラム構造（パッケージとモジュール）はファイル構造から独立しています。一方、Pythonのコード構造はディレクトリ（パッケージ）とファイル（モジュール）によって定義されます。
  * Juliaでは、大きなモジュールのコードを複数のファイルに分割し、ファイルごとに新しいモジュールを作らないのが一般的です。メインファイル内の単一のモジュールで、`include`を使ってコードをまとめて読み込みます。Pythonの相当機能（`exec`）は、以前の定義を警告なしに上書きするため、この用途には通常使いません。一方、Juliaのプログラムは`module`単位で定義され、`using`または`import`によって、Pythonの`include`と同様に、最初に必要になったとき一度だけ実行されます。これらのモジュール内では、モジュールを構成する各ファイルを意図した順序で一度ずつ列挙し、`include`で読み込みます。
  * Juliaの三項演算子`x > 0 ? 1 : -1`は、Pythonの条件式`1 if x > 0 else -1`に相当します。
  * Juliaの`@`記号はマクロを表しますが、Pythonではデコレーターを表します。
  * Juliaの例外処理では、`try` — `except` — `finally`ではなく、`try` — `catch` — `finally`を使います。Pythonとは対照的に、Juliaでは通常の処理の流れに例外処理を使うことは推奨されません（Pythonに比べて、Juliaは通常の制御フローが高速ですが、例外の捕捉は低速です）。
  * Juliaのループは高速なので、性能のために「ベクトル化」したコードを書く必要はありません。
  * Juliaで定数でないグローバル変数を使う際は、特にタイトなループ内で注意してください。Pythonとは異なり、Juliaではハードウェアに近い低水準のコードを書けるため、グローバル変数の影響が非常に大きくなることがあります（[Performance Tips](@ref man-performance-tips)を参照）。
  * Juliaでは、丸めと切り捨てを明示的に行います。Pythonの`int(3.7)`は、`floor(Int, 3.7)`または`Int(floor(3.7))`と書く必要があり、`round(Int, 3.7)`とは区別されます。`floor(x)`と`round(x)`は、単独では常に`Int`を返すのではなく、`x`と同じ型で整数値を返します。
  * Juliaでは、パースを明示的に行います。Pythonの`float("3.7")`は、Juliaでは`parse(Float64, "3.7")`となります。
  * Pythonでは、ほとんどの値を論理的な文脈で使えます（たとえば、`if "a":`では後続のブロックが実行され、`if "":`では実行されません）。Juliaでは、`Bool`への明示的な変換が必要です（たとえば、`if "a"`は例外を送出します）。Juliaで文字列が空でないかを調べるには、`if !isempty("")`と明示的に書きます。意外かもしれませんが、Pythonでは`if "False"`と`bool("False")`はどちらも`True`に評価されます（`"False"`が空でない文字列だからです）。Juliaでは、`parse(Bool, "false")`は`false`を返します。
  * Juliaでは、ループや`try` — `catch` — `finally`を含むほとんどのコードブロックで、新しいローカルスコープが導入されます。なお、内包表記（リスト、ジェネレーターなど）はPythonでもJuliaでも新しいローカルスコープを導入しますが、`if`ブロックはいずれの言語でも新しいローカルスコープを導入しません。

## Noteworthy differences from C/C++

  * Juliaの配列のインデックス指定には角括弧を使い、複数の次元を指定できます。`A[i,j]`。この構文は、C/C++のようにポインターやアドレスの参照を簡単に書くためだけの糖衣構文ではありません。[the manual entry about array construction](@ref man-multi-dim-arrays)を参照してください。
  * Juliaでは、配列や文字列などのインデックスは0ではなく1から始まります。
  * Juliaの配列は、別の変数に代入してもコピーされません。`A = B`の後で`B`の要素を変更すると、`A`も変更されます。`+=`などの更新演算子は、その場で変更する演算ではありません。これらは`A = A + B`と同等であり、左辺を右辺の式の結果に再束縛します。
  * Juliaの配列は列優先（Fortran順）ですが、C/C++の配列はデフォルトでは行優先です。配列をループで処理する際に最適な性能を得るには、JuliaではC/C++に対してループの順序を逆にする必要があります（[relevant section of Performance Tips](@ref man-performance-column-major)を参照）。
  * Juliaでは、代入時や関数に渡す際に値がコピーされることはありません。関数が配列を変更すると、その変更は呼び出し元にも反映されます。
  * C/C++とは異なり、Juliaでは空白が意味を持つため、Juliaプログラムの空白を追加・削除するときは注意が必要です。
  * Juliaでは、小数点のない数値リテラル（`42`など）は`Int`型の符号付き整数を生成します。ただし、マシンのワードサイズに収まらないリテラルは、`Int64`（`Int`が`Int32`の場合）、`Int128`、あるいは任意の大きさを扱える`BigInt`型など、より大きな型へ自動的に昇格します。`L`、`LL`、`U`、`UL`、`ULL`のように、符号の有無などを指定する数値リテラルの接尾辞はありません。10進リテラルは常に符号付きです。16進リテラル（C/C++と同じく`0x`で始まります）は符号なしですが、128ビットを超える場合は`BigInt`型になります。また、16進リテラルの型は、C/C++/JavaやJuliaの10進リテラルとは異なり、先頭の0も含めたリテラルの*長さ*で決まります。たとえば、`0x0`と`0x00`は[`UInt8`](@ref)型、`0x000`と`0x0000`は[`UInt16`](@ref)型になります。さらに、16進数で5～8桁のリテラルは`UInt32`型、9～16桁は`UInt64`型、17～32桁は`UInt128`型、32桁を超えるものは`BigInt`型になります。16進マスクを定義する際は、この点を考慮する必要があります。たとえば、`~0xf == 0xf0`と`~0x000f == 0xfff0`は大きく異なります。64ビットの`Float64`と32ビットの[`Float32`](@ref)のビットリテラルは、それぞれ`1.0`と`1.0f0`で表します。浮動小数点リテラルを正確に表現できない場合は丸められ、`BigFloat`型には昇格しません。浮動小数点リテラルの動作はC/C++に近いものです。8進リテラル（接頭辞は`0o`）と2進リテラル（接頭辞は`0b`）も符号なしとして扱われます（128ビットを超える場合は`BigInt`）。
  * Juliaの除算演算子[`/`](@ref)は、両方のオペランドが整数型でも浮動小数点数を返します。整数除算を行うには[`div`](@ref)または[`÷`](@ref div)を使ってください。
  * Juliaでは、浮動小数点型を使って`Array`をインデックス指定すると、通常はエラーになります。Cの式`a[i / 2]`に相当するJuliaの式は`a[i ÷ 2 + 1]`であり、ここで`i`は整数型です。
  * 文字列リテラルは`"`または`"""`で囲めます。`"""`で囲んだリテラルには、`"\""`のようにエスケープせずに`"`文字を含められます。文字列リテラルには、`$variablename`または`$(expression)`を使って、ほかの変数の値や式の値を埋め込めます。その変数名や式は、関数のコンテキストで評価されます。
  * `//`は[`Rational`](@ref)数を表し、単一行コメントではありません（Juliaの単一行コメントは`#`です）。
  * `#=`は複数行コメントの開始を、`=#`はその終わりを表します。
  * Juliaの関数は、最後の式の値、または`return`キーワードで指定した値を返します。C/C++で必要になるような値へのポインターの受け渡し（`a = myfunction(&b)`）を行う代わりに、関数から複数の値を返し、`(a, b) = myfunction()`や`a, b = myfunction()`のようにタプルとして代入できます。
  * Juliaでは、文の末尾にセミコロンを付ける必要はありません。式の結果は自動的には表示されず（対話プロンプト、すなわちREPLを除く）、コードの行をセミコロンで終える必要もありません。特定の出力を表示するには[`println`](@ref)または[`@printf`](@ref)を使えます。REPLでは`;`で出力を抑制できます。また、`;`は`[ ]`内では別の意味を持つため注意してください。`;`を使って1行内の式を区切ることもできますが、多くの場合は必須ではなく、主に読みやすさのために使います。
  * Juliaの演算子[`⊻`](@ref xor)（[`xor`](@ref)）はビット単位のXOR演算を行い、C/C++の[`^`](@ref)に相当します。また、ビット演算子の優先順位はC/C++と同じではないため、丸括弧が必要な場合があります。
  * Juliaの[`^`](@ref)はべき乗（pow）であり、C/C++のようなビット単位のXORではありません（Juliaでは[`⊻`](@ref xor)または[`xor`](@ref)を使ってください）。
  * Juliaには右シフト演算子が2つあり、`>>`と`>>>`です。`>>`は算術シフトを、`>>>`は常に論理シフトを行います。これは、`>>`の意味がシフトする値の型に依存するC/C++とは異なります。
  * Juliaの`->`は無名関数を作成するものであり、ポインターを介してメンバーにアクセスするものではありません。
  * Juliaでは、`if`文や`for`／`while`ループを書く際に丸括弧は不要です。`for (int i=1; i <= 3; i++)`ではなく`for i in [1, 2, 3]`を、`if (i == 1)`ではなく`if i == 1`を使ってください。
  * Juliaでは、数値`0`と`1`をブール値として扱いません。`if`文はブール値しか受け付けないため、Juliaで`if (1)`とは書けません。代わりに、`if true`、`if Bool(1)`、または`if 1==1`と書けます。
  * Juliaでは、`if`などの条件ブロック、`while`／`for`などのループブロック、および関数の終わりを`end`で表します。1行の`if ( cond ) statement`の代わりに、Juliaでは`if cond; statement; end`、`cond && statement`、`!cond || statement`という形式の文を使えます。後者2つの構文で代入文を使う場合は、演算子の優先順位のため、`cond && (x = value)`のように明示的に丸括弧で囲む必要があります。
  * Juliaには行継続の構文がありません。行末までの入力が完全な式であれば、その式は完了したとみなされます。そうでなければ入力が継続されます。式を強制的に継続させる方法の1つは、丸括弧で囲むことです。
  * Juliaのマクロは、プログラムのテキストではなくパース済みの式を操作するため、Juliaコードに高度な変換を施せます。マクロ名は`@`文字で始まり、関数風の構文`@mymacro(arg1, arg2, arg3)`と文風の構文`@mymacro arg1 arg2 arg3`の両方を使えます。これらの形式は互いに置き換え可能です。関数風の形式は、マクロが別の式の中に現れる場合に特に有用で、多くの場合、最も明確です。文風の形式は、分散処理の`for`構文である`@distributed for i in 1:n; #= body =#; end`のように、ブロックに注釈を付ける際によく使われます。マクロ構文の終わりが不明確になりそうな場合は、関数風の形式を使ってください。
  * Juliaには列挙型があり、マクロ`@enum(name, value1, value2, ...)`を使って表します。例：`@enum(Fruit, banana=1, apple, pear)`
  * 慣例として、引数を変更する関数の名前には、`push!`のように末尾に`!`を付けます。
  * C++では、デフォルトは静的ディスパッチです。つまり、動的ディスパッチを使うには関数をvirtualとして指定する必要があります。一方、Juliaではすべてのメソッドが「仮想」です（ただし、`this`だけでなくすべての引数の型に基づき、最も具体的な宣言を選ぶ規則でディスパッチするため、実際にはそれより一般的です）。

### Julia ⇔ C/C++: Namespaces

  * C/C++の`namespace`は、おおむねJuliaの`module`に相当します。
  * Juliaには非公開のグローバル変数やフィールドはありません。完全修飾パス（必要に応じて相対パス）を使えば、すべてに外部からアクセスできます。
  * `using MyNamespace::myfun`（C++）は、おおむね`import MyModule: myfun`（Julia）に相当します。
  * `using namespace MyNamespace`（C++）は、おおむね`using MyModule`（Julia）に相当します。

      * Juliaでは、`export`されたシンボルだけが、呼び出し側のモジュールで利用可能になります。
      * C++では、インクルードされた（公開）ヘッダーファイルにある要素だけが利用可能になります。
  * 注意：`import`／`using`キーワード（Julia）は、モジュールの*読み込み*も行います（後述）。
  * 注意：`import`／`using`（Julia）は、グローバルスコープ（`module`）でのみ使用できます。

      * C++では、`using namespace X`を任意のスコープ（関数スコープなど）内で使用できます。

### Julia ⇔ C/C++: Module loading

  * C/C++の「**ライブラリ**」に相当するものを探しているなら、Juliaでは「**パッケージ**」がそれに当たるでしょう。

      * 注意：C/C++のライブラリには複数の「ソフトウェアモジュール」が含まれることがよくありますが、Juliaの「パッケージ」に含まれるのは通常1つです。
      * 再確認：Juliaの`module`はグローバルスコープであり、必ずしも「ソフトウェアモジュール」ではありません。
  * Juliaでは、**ビルドスクリプトや`make`スクリプトの代わりに**、「プロジェクト環境」（単に「プロジェクト」または「環境」と呼ぶこともあります）を使います。

      * ビルドスクリプトが必要なのは、より複雑なアプリケーション（C/C++の実行ファイルのコンパイルやダウンロードが必要なものなど）だけです。
      * Juliaでアプリケーションやプロジェクトを開発するには、そのルートディレクトリを「プロジェクト環境」として初期化し、アプリケーション固有のコードやパッケージをそこに置けます。これにより、プロジェクトの依存関係を適切に管理し、将来の再現性を確保できます。
      * 利用するパッケージは、`Pkg.add()`関数またはPkg REPLモードで「プロジェクト環境」に追加します（ただし、これだけではそのパッケージは**読み込まれません**）。
      * 「プロジェクト環境」で利用可能なパッケージ（直接の依存関係）の一覧は、その環境の`Project.toml`ファイルに保存されます。
      * 「プロジェクト環境」の*完全な*依存関係情報は、`Pkg.resolve()`によって自動生成され、その環境の`Manifest.toml`ファイルに保存されます。
  * 「プロジェクト環境」で利用可能なパッケージ（「ソフトウェアモジュール」）は、`import`または`using`で読み込みます。

      * C/C++では、`#include <moduleheader>`でオブジェクトや関数の宣言を取り込み、実行ファイルのビルド時にライブラリをリンクします。
      * Juliaでusing/importを再度呼び出しても、既存のモジュールがスコープに導入されるだけで、再読み込みはされません（C/C++で非標準の`#pragma once`を追加するのと似ています）。
  * Juliaの**ディレクトリベースのパッケージリポジトリ**は、リポジトリのパスを`Base.LOAD_PATH`配列に追加することで利用可能になります。

      * ディレクトリベースのリポジトリにあるパッケージは、`import`または`using`で読み込む前に、`Pkg.add()`ツールを使う必要はありません。そのままプロジェクトで利用できます。
      * ディレクトリベースのパッケージリポジトリは、ローカルで「ソフトウェアモジュール」のライブラリを開発するための**最も手早い方法**です。

### Julia ⇔ C/C++: Assembling modules

  * C/C++では、`.c`／`.cpp`ファイルをビルドスクリプトや`make`スクリプトでコンパイルし、ライブラリに追加します。

      * Juliaでは、`import [PkgName]`／`using [PkgName]`文が、パッケージの`[PkgName]/src/`サブディレクトリにある`[PkgName].jl`を読み込みます。
      * さらに、`[PkgName].jl`は通常、`include "[someotherfile].jl"`の呼び出しで関連するソースファイルを読み込みます。
  * `include "./path/to/somefile.jl"`（Julia）は、`#include "./path/to/somefile.jl"`（C/C++）によく似ています。

      * ただし、`include "..."`（Julia）はヘッダーファイルを取り込むためのものではありません（ヘッダーファイル自体が不要です）。
      * ほかの「ソフトウェアモジュール」からコードを読み込むために、`include "..."`（Julia）を**使わないでください**（代わりに`import`／`using`を使ってください）。
      * `include "path/to/some/module.jl"`（Julia）を使うと、同じコードの複数の実体が別々のモジュール内に作成されます（*同じ*名前を持つ*別個の*型などが作成されます）。
      * `include "somefile.jl"`は通常、*同じJuliaパッケージ内*（「ソフトウェアモジュール」内）の複数のファイルをまとめるために使います。そのため、各ファイルが一度だけ`include`されるようにするのは比較的簡単です（`#ifdef`による混乱はありません）。

### Julia ⇔ C/C++: Module interface

  * C++では「公開」`.h`／`.hpp`ファイルを使ってインターフェースを公開します。一方、Juliaの`module`では、ユーザー向けの特定のシンボルを`public`または`export`として指定します。

      * Juliaの`module`は、既存の関数（例：`Base.push!`）に新しい「メソッド」を作成するだけで機能を追加することがよくあります。
      * したがって、Juliaパッケージの開発者は、インターフェースのドキュメントとしてヘッダーファイルに頼ることはできません。
      * Juliaパッケージのインターフェースは通常、docstring、README.md、静的なWebページなどで説明します。
  * パッケージやモジュールの利用に必要なシンボルをすべて`export`するわけではない開発者もいますが、その場合でも、エクスポートしないユーザー向けシンボルには`public`を指定すべきです。

      * ユーザーには、関数や構造体などをパッケージ名やモジュール名で修飾して、これらの要素にアクセスすることが求められる場合があります（例：`MyModule.run_this_task(...)`）。

## Noteworthy differences from Common Lisp

  * Juliaの配列のインデックスはデフォルトでは1から始まりますが、任意の[index offsets](@ref man-custom-indices)も扱えます。
  * 関数と変数は同じ名前空間を共有します（「Lisp-1」）。
  * [`Pair`](@ref)型はありますが、`COMMON-LISP:CONS`として使うことは想定されていません。言語の大部分（スプラット、タプルなど）では、さまざまな反復可能なコレクションを互いに置き換えて使えます。異なる型の要素からなる*短い*コレクションでは、`Tuple`がCommon Lispのリストに最も近いものです。連想リストの代わりには`NamedTuple`を使ってください。同じ型の要素からなる大きなコレクションには、`Array`や`Dict`を使うべきです。
  * Juliaでの典型的なプロトタイピングのワークフローでも、イメージを継続的に操作します。これは[Revise.jl](https://github.com/timholy/Revise.jl)パッケージで実現されています。
  * 性能のため、Juliaでは演算が[type stability](@ref man-type-stability)を持つことが望まれます。Common Lispが基盤となる機械演算を抽象化するのに対し、Juliaはそれらにより近い動作をします。たとえば、次のとおりです。

      * `/`を使った整数同士の除算は、割り切れる場合でも常に浮動小数点の結果を返します。

          * `//`は常に有理数の結果を返します。
          * `÷`は常に（切り捨てた）整数の結果を返します。
      * 多倍長整数はサポートしていますが、変換は自動ではありません。通常の整数については[overflow](@ref faq-integer-arithmetic)。
      * 複素数はサポートしていますが、複素数の結果を得るには[you need complex inputs](@ref faq-domain-errors)。
      * 構成要素の型が異なる、複数のComplex型とRational型があります。
  * モジュール（名前空間）は階層化できます。[`import`](@ref)と[`using`](@ref)には、コードを読み込むことと、名前空間で利用可能にすることの2つの役割があります。モジュール名だけを`import`することも可能です（おおむね`ASDF:LOAD-OP`に相当します）。スロット名を個別にエクスポートする必要はありません。モジュールの外部からグローバル変数へ代入することはできません（ただし、抜け道として`eval(mod, :(var = val))`を使う場合を除きます）。
  * マクロは`@`で始まり、Common Lispほどシームレスに言語へ統合されていません。そのため、マクロはCommon Lispほど広くは使われていません。[macros](@ref Metaprogramming)に対する一種のハイジーンは、言語によってサポートされています。表層構文が異なるため、`COMMON-LISP:&BODY`に相当するものはありません。
  * *すべての*関数はジェネリックであり、多重ディスパッチを使います。引数リストを同じ形式にそろえる必要がないため、強力なイディオムが可能になります（[`do`](@ref)を参照）。オプション引数とキーワード引数は異なる方法で処理されます。メソッドの曖昧さはCommon Lisp Object Systemと同じようには解決されないため、重複する場合を対象とする、より具体的なメソッドを定義する必要があります。
  * シンボルはどのパッケージにも属さず、*それ自体では*値を保持しません。`M.var`は、モジュール`M`内でシンボル`var`を評価します。
  * クロージャを含め、関数型プログラミングのスタイルは言語として完全にサポートされていますが、必ずしもJuliaらしい解決方法とは限りません。捕捉した変数を変更する際には、性能のために[workarounds](@ref man-performance-captured)が必要になることがあります。
