# [Package Images](@id pkgimages)

Juliaのパッケージイメージは、Juliaパッケージ用のオブジェクト（ネイティブコード）キャッシュを提供します。Juliaの[system image](@ref dev-sysimg)と似ており、多くの機能を共有しています。実際、基盤となるシリアライズ形式は同じで、システムイメージはパッケージイメージのビルド元となるベースイメージです。

## High-level overview

パッケージイメージは、コードとデータの両方を含む共有ライブラリです。`.ji`キャッシュファイルと同様に、パッケージごとに生成されます。データセクションには、グローバルデータ（パッケージ内のグローバル変数）に加え、そのパッケージで定義されているメソッドや型に関する必要なメタデータが含まれます。コードセクションには、JuliaのLLVMベースのコンパイラーが生成した最終出力をキャッシュするネイティブオブジェクトが含まれます。

コマンドラインオプション`--pkgimages=no`を使うと、このセッションでのオブジェクトキャッシュを無効にできます。この場合、キャッシュファイルは再生成が必要になる可能性が高いことに注意してください。Juliaがデフォルトでキャッシュするバリアント数の上限については、[`JULIA_MAX_NUM_PRECOMPILE_FILES`](@ref JULIA_MAX_NUM_PRECOMPILE_FILES)を参照してください。

!!! note
    パッケージイメージはネイティブ共有ライブラリのように見えますが、あくまでその近似にすぎません。ネイティブプログラムからリンクすることはできず、Juliaから読み込む必要があります。


## Linking

パッケージイメージにはネイティブコードが含まれるため、使用する前にリンカーを実行する必要があります。環境変数[`JULIA_VERBOSE_LINKING`](@ref JULIA_VERBOSE_LINKING)を`true`に設定すると、パッケージイメージのリンク処理を詳細に表示できます。

また、ユーザーの環境に正常に動作するシステムリンカーがインストールされているとは限りません。そのため、JuliaにはLLVMリンカーのLLDが同梱されており、インストール直後から利用できる環境を提供します。`base/linking.jl`では、サポート対象のすべてのプラットフォームでパッケージイメージをリンクできるよう、限定的なインターフェースを実装しています。

### Quirks

LLDはマルチプラットフォーム対応のリンカーですが、プラットフォーム間で一貫したインターフェースを提供していません。また、`clang`などのコンパイラードライバーから使うことを前提としているため、`llvm-project/clang/lib/Driver/ToolChains`のロジックの一部を再実装しています。幸い、`lld -flavor`を使えば、LLDを適切なプラットフォーム向けに設定できます。

#### Windows

`link.exe`を扱わずに済むよう、`-flavor gnu`を使い、`lld`をmingw32環境からのクロスリンカーとして動作させています。WindowsのDLLには`_DllMainCRTStartup`関数が必要です。mingw32ライブラリへの依存を最小限に抑えるため、そのスタブ定義は独自に挿入しています。

#### MacOS

macOSの動的ライブラリは、`-lSystem`にリンクする必要があります。最近のmacOSでは、Xcodeが利用可能な場合に限り、`-lSystem`をリンクに使用できます。そのため、`-undefined dynamic_lookup`を使ってリンクします。

## [Package images optimized for multiple microarchitectures](@id pkgimgs-multi-versioning)

システムイメージの[multi-versioning](@ref sysimg-multi-versioning)と同様に、パッケージイメージもマルチバージョニングに対応しています。これにより、同じ環境内の異なるCPUアーキテクチャで効率よく実行できるパッケージキャッシュを作成できます。

パッケージイメージのCPUターゲットの設定方法については、環境変数[`JULIA_CPU_TARGET`](@ref JULIA_CPU_TARGET)を参照してください。

## Flags that impact package image creation and selection

キャッシュの選択に影響するJuliaのコマンドラインフラグは次のとおりです。異なるフラグで作成されたパッケージイメージは拒否されます。

  * `-g`、`--debug-info`：コード生成に影響するため、完全一致が必要です。
  * `--check-bounds`：コード生成に影響するため、完全一致が必要です。
  * `--inline`：コード生成に影響するため、完全一致が必要です。
  * `--pkgimages`：オブジェクトキャッシュを有効にせずに実行できるようにします。
  * `-O`、`--optimize`：最適化レベルが低い設定で生成されたパッケージイメージは拒否しますが、より高い最適化レベルのイメージは読み込みを許可します。
