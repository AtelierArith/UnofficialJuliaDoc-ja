```julia
verify_host(url::AbstractString, [transport::AbstractString]) :: Bool
```

`verify_host` 関数は、TLS や SSH などのセキュアなトランスポートで通信する際に、ホストの識別情報を検証すべきかどうかを呼び出し元に伝えます。`url` 引数には、次のいずれかを指定できます。

1. `proto://` で始まる正しい URL
2. `ssh` 形式のホスト名、または `user@` を前置したホスト名
3. 上記の `scp` 形式のホスト名に、`:` とパスの場所を続けたもの

いずれの場合も、ホスト名の部分だけが解析され、検証するかどうかはホスト名のみに基づいて判断されます。入力 URL のその他の情報は判断に影響しません。特に、URL のプロトコルは関係ありません（詳細は後述）。

`transport` 引数は、問い合わせの対象となるトランスポートの種類を示します。現在、認識される値は `SSL`/`ssl`（別名 `TLS`/`tls`）と `SSH`/`ssh` です。トランスポートを省略した場合、トランスポートの種類にかかわらずホスト名を検証すべきでないときに限り、問い合わせは `true` を返します。

ホスト名は、`transport` が指定されているかどうか、およびその値に応じて、該当する環境変数内のホストパターンと照合されます。

  * `JULIA_NO_VERIFY_HOSTS` — どのトランスポートでも検証しないホスト
  * `JULIA_SSL_NO_VERIFY_HOSTS` — SSL/TLS では検証しないホスト
  * `JULIA_SSH_NO_VERIFY_HOSTS` — SSH では検証しないホスト
  * `JULIA_ALWAYS_VERIFY_HOSTS` — 常に検証するホスト

各変数の値は、ホスト名パターンをカンマで区切ったリストです。パターンの構文は次のとおりです。各パターンは `.` で分割され、各部分は次のいずれかでなければなりません。

1. ASCII の英字、数字、ハイフン、またはアンダースコア（厳密には正規のホスト名の構成要素ではありませんが、使われることがあります）からなる、1 つ以上の文字を含むドメイン名のリテラル要素。リテラル要素は、それ自体にのみ一致します。
2. 0 個以上のドメイン名要素に一致する `**`。
3. 任意の 1 つのドメイン名要素に一致する `*`。

これらの変数のいずれかにあるパターンリストとホスト名を照合するときは、ホスト名を `.` で分割して要素にし、その並びをパターンと照合します。リテラルパターンは、値が一致するホスト名要素 1 つにのみ一致します。`*` パターンは、値を問わずホスト名要素 1 つに一致します。`**` パターンは、任意の数のホスト名要素に一致します。たとえば、次のようになります。

  * `**` は、すべてのホスト名に一致します。
  * `**.org` は、`.org` トップレベルドメイン内のすべてのホスト名に一致します。
  * `example.com` は、ホスト名が `example.com` と完全に一致する場合にのみ一致します。
  * `*.example.com` は `api.example.com` には一致しますが、`example.com` や `v1.api.example.com` には一致しません。
  * `**.example.com` は、`example.com` 配下のすべてのドメインに一致します。`example.com` 自体に加え、`api.example.com` や `v1.api.example.com` も含まれます。
