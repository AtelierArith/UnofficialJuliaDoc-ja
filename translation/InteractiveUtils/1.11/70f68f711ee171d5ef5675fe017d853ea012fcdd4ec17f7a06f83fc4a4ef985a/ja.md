```julia
define_editor(fn, pattern; wait=false)
```

`pattern`に対応する新しいエディターを定義すると、`fn`を使って、ファイルを開けるようになります（行番号の指定も可能です）。

`fn`引数には、指定したエディターでファイルを開く方法を決める関数を指定します。この関数は、次の4つの引数を受け取ります。

  * `cmd` - エディターのベースとなるコマンドオブジェクト
  * `path` - 開くソースファイルのパス
  * `line` - エディターを開く行番号
  * `column` - エディターを開く列番号

コマンドで特定の行や列を指定して開けないエディターでは、`line`引数や`column`引数を無視してもかまいません。`fn`コールバックは、ファイルを開くための適切な`Cmd`オブジェクトを返すか、そのファイルを編集できないことを示す`nothing`を返す必要があります。このエディターが現在の環境に適さず、別のエディターを試すべき場合は、`nothing`を使ってください。外部コマンドを起動する必要のない、より汎用的な編集フックを追加するには、コールバックをベクター`EDITOR_CALLBACKS`に直接追加します。

`pattern`引数には、文字列、正規表現、または文字列と正規表現の配列を指定します。`fn`が呼び出されるには、パターンのいずれかが`EDITOR`、`VISUAL`、または`JULIA_EDITOR`の値に一致する必要があります。文字列の場合、エディターコマンドの先頭の単語から拡張子（あれば）を除いたものが、[`basename`](@ref)と一致する必要があります。たとえば、"vi"は"vim -g"には一致しませんが、"/usr/bin/vi -m"には一致します。また、`vi.exe`にも一致します。`pattern`が正規表現の場合は、シェルエスケープされた文字列としてのエディターコマンド全体に対して照合されます。配列パターンは、その要素のいずれかが一致すれば一致します。複数のエディターが一致する場合は、最後に追加されたエディターが使われます。

デフォルトでは、juliaはエディターが閉じるのを待たず、バックグラウンドで実行します。ただし、エディターがターミナルベースの場合は、`wait=true`を設定すると、エディターが閉じるまでjuliaは待機してから処理を再開します。

エディター環境変数のいずれかが設定されていても、それに一致するエディター項目がない場合は、デフォルトのエディター項目が呼び出されます。

```julia
(cmd, path, line, column) -> `$cmd $path`
```

なお、多くのエディターはすでに定義されています。次のコマンドは、いずれもそのまま使えるはずです。

  * emacs
  * emacsclient
  * vim
  * nvim
  * nano
  * micro
  * kak
  * helix
  * textmate
  * mate
  * kate
  * subl
  * atom
  * notepad++
  * Visual Studio Code
  * open
  * pycharm
  * bbedit

# Examples

以下は、ターミナルベースの`emacs`の使い方を定義しています。

```julia
define_editor(
    r"\bemacs\b.*\s(-nw|--no-window-system)\b", wait=true) do cmd, path, line
    `$cmd +$line $path`
end
```

!!! compat "Julia 1.4"
    `define_editor`はJulia 1.4で導入されました。
