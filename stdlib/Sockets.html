Sockets.listen — Method
listen([addr, ]port::Integer; backlog::Integer=BACKLOG_DEFAULT) -> TCPServer

addrで指定したアドレスのポートで待ち受けます。デフォルトでは、localhostのみで待ち受けます。すべてのインターフェースで待ち受けるには、状況に応じてIPv4(0)またはIPv6(0)を渡します。backlogは、サーバーが接続を拒否し始めるまでに保留できる接続数（acceptをまだ呼び出していない接続数）を指定します。backlogのデフォルト値は511です。

source
Sockets.listen — Method
listen(path::AbstractString) -> PipeServer

名前付きパイプ／UNIXドメインソケットを作成して、接続を待ち受けます。

Note

Unixでは、パスの長さは92～108バイト程度に制限されています（man unix）。

Sockets.getaddrinfo — Function
getaddrinfo(host::AbstractString, IPAddr) -> IPAddr

指定されたIPAddr型のhostについて、最初のIPアドレスを取得します。オペレーティングシステムの基盤となるgetaddrinfo実装を使用するため、DNSルックアップが行われる場合があります。

Examples

julia> getaddrinfo("localhost", IPv6)
ip"::1"

julia> getaddrinfo("localhost", IPv4)
ip"127.0.0.1"
source
getaddrinfo(host::AbstractString) -> IPAddr

hostの最初に利用可能なIPアドレスを取得します。これはIPv4またはIPv6アドレスのいずれかです。オペレーティングシステムの基盤となるgetaddrinfo実装を使用するため、DNSルックアップが行われる場合があります。

source
Sockets.getipaddr — Function
getipaddr() -> IPAddr

ローカルマシンの IP アドレスを取得します。IPv4 アドレスが IPv6 アドレスより優先されます。アドレスがない場合は例外をスローします。

getipaddr(addr_type::Type{T}) where T<:IPAddr -> T

指定した種類のローカルマシンの IP アドレスを取得します。指定した種類のアドレスがない場合は例外をスローします。

この関数は、後方互換性のための getipaddrs のラッパーです。新しいアプリケーションでは、代わりに getipaddrs を使用してください。

Examples

julia> getipaddr()
ip"192.168.1.28"

julia> getipaddr(IPv6)
ip"fe80::9731:35af:e1c5:6e49"

getipaddrs も参照してください。

source
Sockets.getipaddrs — Function
getipaddrs(addr_type::Type{T}=IPAddr; loopback::Bool=false) where T<:IPAddr -> Vector{T}

ローカルマシンの IP アドレスを取得します。

省略可能な addr_type パラメーターに IPv4 または IPv6 を設定すると、その種類のアドレスのみが返されます。

loopback キーワード引数は、ループバックアドレス（例: ip"127.0.0.1"、ip"::1"）を含めるかどうかを指定します。

Julia 1.2

この関数は Julia 1.2 以降で利用できます。

Examples

julia> getipaddrs()
5-element Vector{IPAddr}:
 ip"198.51.100.17"
 ip"203.0.113.2"
 ip"2001:db8:8:4:445e:5fff:fe5d:5500"
 ip"2001:db8:8:4:c164:402e:7e3c:3668"
 ip"fe80::445e:5fff:fe5d:5500"

julia> getipaddrs(IPv6)
3-element Vector{IPv6}:
 ip"2001:db8:8:4:445e:5fff:fe5d:5500"
 ip"2001:db8:8:4:c164:402e:7e3c:3668"
 ip"fe80::445e:5fff:fe5d:5500"

関連項目: islinklocaladdr。

source
Sockets.islinklocaladdr — Function
islinklocaladdr(addr::IPAddr)

IPアドレスがリンクローカルアドレスかどうかを判定します。リンクローカルアドレスは、ネットワークセグメントを越えて一意であることが保証されないため、ルーターは転送しません。リンクローカルアドレスは、アドレスブロック 169.254.0.0/16 または fe80::/10 に属します。

Examples

filter(!islinklocaladdr, getipaddrs())

Base.bind — Function
bind(chnl::Channel, task::Task)

chnlのライフタイムをタスクに関連付けます。タスクが終了すると、Channel chnlは自動的に閉じられます。タスク内で捕捉されなかった例外は、chnlで待機しているすべてのタスクに伝播します。

chnlオブジェクトは、タスクの終了とは無関係に明示的に閉じることができます。タスクが終了しても、すでに閉じられているChannelオブジェクトには影響しません。

チャネルが複数のタスクに関連付けられている場合、最初に終了したタスクがチャネルを閉じます。複数のチャネルが同じタスクに関連付けられている場合、そのタスクが終了すると、関連付けられているすべてのチャネルが閉じられます。

Examples

julia> c = Channel(0);

julia> task = @async foreach(i->put!(c, i), 1:4);

julia> bind(c,task);

julia> for i in c
           @show i
       end;
i = 1
i = 2
i = 3
i = 4

julia> isopen(c)
false
julia> c = Channel(0);

julia> task = @async (put!(c, 1); error("foo"));

julia> bind(c, task);

julia> take!(c)
1

julia> put!(c, 1);
ERROR: TaskFailedException
Stacktrace:
[...]
    nested task error: foo
[...]
source
bind(socket::Union{TCPServer, UDPSocket, TCPSocket}, host::IPAddr, port::Integer; ipv6only=false, reuseaddr=false, kws...)

socket を指定された host:port にバインドします。0.0.0.0 はすべてのデバイスで待ち受けることに注意してください。

  • ipv6only パラメーターを指定すると、デュアルスタックモードが無効になります。ipv6only=true の場合、IPv6 スタックのみが作成されます。
  • reuseaddr=true の場合、複数のスレッドまたはプロセスが reuseaddr=true をすべて設定していれば、同じアドレスにエラーなくバインドできます。ただし、トラフィックを受信できるのは最後にバインドしたものだけです。

Sockets.recvfrom — Function

Sockets.setopt — Function
setopt(sock::UDPSocket; multicast_loop=nothing, multicast_ttl=nothing, enable_broadcast=nothing, ttl=nothing)

UDPソケットのオプションを設定します。

  • multicast_loop: マルチキャストパケットのループバック（デフォルト: true）。
  • multicast_ttl: マルチキャストパケットのTTL（デフォルト: nothing）。
  • enable_broadcast: ソケットをブロードキャストメッセージに使用する場合は、このフラグをtrueに設定する必要があります。設定しないと、UDPシステムからアクセスエラーが返されます（デフォルト: false）。
  • ttl: ソケットから送信されるパケットの生存時間（デフォルト: nothing）。
source
Sockets.nagle — Function
nagle(socket::Union{TCPServer, TCPSocket}, enable::Bool)

Nagleのアルゴリズムは、複数の小さなTCPパケットをまとめて、より大きなパケットにします。これによりスループットが向上する一方、レイテンシが悪化することがあります。Nagleのアルゴリズムはデフォルトで有効です。この関数は、指定したTCPサーバーまたはソケットでNagleのアルゴリズムを有効にするかどうかを設定します。他の言語では、反対の設定をTCP_NODELAYと呼びます。

Julia 1.3

この関数を使用するには、Julia 1.3以降が必要です。
