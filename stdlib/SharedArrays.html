Shared Arrays

SharedArray represents an array, which is shared across multiple processes, on a single machine.

SharedArrays.SharedArray — Type
SharedArray{T}(dims::NTuple; init=false, pids=Int[])
SharedArray{T,N}(...)

pidsで指定したプロセス間（すべて同一ホスト上にある必要があります）に、ビット型T、サイズdimsのSharedArrayを構築します。SharedArray{T,N}(dims)の呼び出しでNを指定する場合、Nの長さはdimsと一致している必要があります。

pidsを省略すると、共有配列はマスターを含む現在のホスト上のすべてのプロセスにマッピングされます。ただし、localindicesとindexpidsが参照するのはワーカープロセスのみです。これにより、マスタープロセスをドライバーとして動作させながら、ワーカーを実際の計算に使用する作業分散コードを記述できます。

型initfn(S::SharedArray)のinit関数を指定すると、参加するすべてのワーカーで呼び出されます。

共有配列は、マッピングを作成したノード上にSharedArrayオブジェクトへの参照が存在する限り有効です。

SharedArray{T}(filename::AbstractString, dims::NTuple, [offset=0]; mode=nothing, init=false, pids=Int[])
SharedArray{T,N}(...)

pidsで指定したプロセス間（すべて同一ホスト上にある必要があります）に、要素型T（ビット型である必要があります）、サイズdimsの、ファイルfilenameをバックエンドとするSharedArrayを構築します。このファイルはホストメモリにメモリマップされるため、次の点に注意してください。

  • 配列データはバイナリ形式で表現する必要があります（CSVなどのASCII形式はサポートされません）。
  • 配列の値を変更すると（例：A[3] = 0）、ディスク上の値も変更されます。

pidsを省略すると、共有配列はマスターを含む現在のホスト上のすべてのプロセスにマッピングされます。ただし、localindicesとindexpidsが参照するのはワーカープロセスのみです。これにより、マスタープロセスをドライバーとして動作させながら、ワーカーを実際の計算に使用する作業分散コードを記述できます。

modeには、"r"、"r+"、"w+"、"a+"のいずれかを指定します。ファイルfilenameがすでに存在する場合の既定値は"r+"、存在しない場合は"w+"です。型initfn(S::SharedArray)のinit関数を指定すると、参加するすべてのワーカーで呼び出されます。ファイルが書き込み可能でない場合、init関数は指定できません。

offsetを使うと、ファイルの先頭から指定したバイト数を読み飛ばせます。

SharedArrays.indexpids — Function
indexpids(S::SharedArray)

現在のワーカーのインデックスを、SharedArray に対応するワーカーのリスト（つまり、procs(S) が返す同じリスト）内で返します。SharedArray がローカルにマッピングされていない場合は、0 を返します。

source
SharedArrays.localindices — Function
localindices(S::SharedArray)

現在のプロセスが処理する「デフォルト」のインデックスを表す範囲を返します。この範囲は、線形インデックスの意味で解釈されます。つまり、1:length(S) の部分範囲です。複数プロセスのコンテキストでは、親プロセス（または indexpids が 0 を返すプロセス）では空の範囲を返します。

localindices はあくまで便宜上のものです。配列の処理をワーカー間でどのように分割するかは自由です。SharedArray の場合、各ワーカープロセスでは、どのインデックスも同じ速さで処理できる必要があります。
