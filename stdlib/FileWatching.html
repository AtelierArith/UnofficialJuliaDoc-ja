FileWatching.poll_fd — Function
poll_fd(fd, timeout_s::Real=-1; readable=false, writable=false)

ファイルディスクリプター fd について、読み取りまたは書き込みが可能になったかを、timeout_s 秒のタイムアウトで監視します。

キーワード引数で、読み取り状態と書き込み状態のどちらを監視するか（または両方を監視するか）を指定します。少なくとも一方を true に設定する必要があります。

戻り値は、ポーリング結果を示すブール値フィールド readable、writable、timedout を持つオブジェクトです。

これは、FDWatcher 上で wait を呼び出す薄いラッパーです。後者が機能を実装していますが、使用後にユーザーが手動で close を呼び出す必要があり、呼び出さないと深刻なクラッシュを招くおそれがあります。

FileWatching.poll_file — Function
poll_file(path::AbstractString, interval_s::Real=5.007, timeout_s::Real=-1) -> (previous::StatStruct, current)

ファイルに変更があったかどうかを、interval_s 秒ごとにポーリングして監視します。変更が検出されるか、timeout_s 秒が経過すると監視を終了します。interval_s は長めの時間に設定してください。デフォルトは 5.007 秒です。

変更が検出されると、ステータスオブジェクトのペア (previous, current) を返します。previous のステータスは常に StatStruct ですが、すべてのフィールドがゼロになっている場合があります（ファイルが以前は存在しなかった、またはアクセスできなかったことを示します）。

current のステータスオブジェクトは、StatStruct、EOFError（タイムアウトが経過したことを示します）、またはその他の Exception サブタイプ（stat 操作が失敗した場合。たとえば、パスが存在しない場合）になることがあります。

ファイルがいつ変更されたかを判定するには、!(current isa StatStruct && prev == current) を比較して、mtime または inode の変更通知を検出します。ただし、この操作には watch_file を使うことを推奨します。こちらのほうが信頼性と効率に優れていますが、状況によっては利用できない場合があります。

これは、機能を実装する PollingFileWatcher 上で wait を呼び出す薄いラッパーです。ただし、この関数では poll_file の連続した呼び出しの間に小さな競合ウィンドウがあり、その間にファイルが変更されても検出されない可能性があります。

FileWatching.PollingFileWatcher — Type
PollingFileWatcher(path::AbstractString, interval_s::Real=5.007)

ファイルに変更が発生するか、timeout_s 秒が経過するまで、stat を interval_s 秒ごとにポーリングして、ファイルの変更を監視します。interval_s には長い時間を指定してください。デフォルトは 5.007 秒です。最新ではないものの直近の結果を取得するには、対象に対して stat を呼び出します。

これは自動リセット型イベントのように動作します。そのため、wait を呼び出すと、wait の呼び出し開始時に取得した前回の値から、stat の結果が変わるまでブロックされます。wait 関数は、前回 wait を呼び出してから stat の変更が検出されると、ステータスオブジェクトのペア (previous, current) を返します。previous のステータスは常に StatStruct ですが、すべてのフィールドがゼロになっている場合があります（ファイルが以前は存在しなかった、またはアクセスできなかったことを示します）。

current のステータスオブジェクトは、StatStruct、EOFError（このオブジェクトを閉じて待機をキャンセルした場合）、またはその他の Exception サブタイプ（stat 操作が失敗した場合。たとえば、パスが削除された場合）になることがあります。ファイルがその後複数回変更されていると、stat の値が古くなっている可能性があることに注意してください。

この操作には FileMonitor を使用することを推奨します。より信頼性が高く効率的ですが、状況によっては利用できない場合があります。

FileWatching.FDWatcher — Type
FDWatcher(fd::Union{RawFD,WindowsRawSocket}, readable::Bool, writable::Bool)

ファイル記述子 fd を監視し、読み取りまたは書き込みが可能になったことを検知します。

キーワード引数で、読み取り状態と書き込み状態のどちらを監視するか（または両方を監視するか）を指定します。少なくとも一方には true を設定する必要があります。

戻り値は、ポーリング結果を示すブール値フィールド readable、writable、timedout を持つオブジェクトです。

これはレベル検知型のイベントとして動作します。そのため、wait を呼び出すと、いずれかの条件が満たされるまでブロックします。ただし、条件が解消される（読み取るデータがなくなる、書き込みバッファに空きがなくなる、またはその両方）までは、その後もブロックせずに戻り続けます。

Warning

このオブジェクトを使い終えたら、fd 引数を閉じる前に close を手動で呼び出す必要があります。呼び出さないと、重大なクラッシュを引き起こすおそれがあります。

mkpidlock([f::Function], at::String, [pid::Cint]; kwopts...)
mkpidlock(at::String, proc::Process; kwopts...)

現在のプロセス、または pid もしくは proc で指定したプロセスのために、パス "at" に pidfile ロックを作成します。ロック取得後に実行する関数を指定できます。これはdoブロックで使用でき、実行後にロックは自動的に閉じられます。ロックに失敗し、waitがfalseの場合は、エラーがスローされます。

ロックは、close、finalizer、またはprocの終了後まもなく解放されます。プログラムのクリティカルセクションが終わるまで戻り値が有効な状態を保つようにしてください。そうしないと、finalizerによって早期に回収される可能性があります。

省略可能なキーワード引数:

  • mode: ファイルのアクセスモード（プロセスの umask によって変更されます）。デフォルトでは、すべてのユーザーが読み取り可能です。
  • poll_interval: 試行間の最大待ち時間を指定します（watch_fileが機能しない場合）。
  • stale_age: mtime に基づき、指定した秒数より古い既存の pidfile を（ロックを無視して）削除します。ファイル内の pid が有効である可能性がある場合、指定時間の5倍が経過するまでファイルは削除されません。ロックの更新を無効にするためにrefreshを0に上書きした場合は、25倍の時間が経過するまで削除されません。デフォルトでは無効です（stale_age = 0）。通常の完了時間の推定値の約3～5倍を設定するのが一般的な推奨値です。
  • refresh: 一定時間ごとに mtime を更新し、ロックが古くならないようにします。デフォルトではstale_age/2に設定されており、これが推奨値です。
  • wait: true の場合はロックを取得するまで待機し、false の場合はロックに失敗するとエラーをスローします。
