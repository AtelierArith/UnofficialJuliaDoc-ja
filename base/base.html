Essentials

Introduction

Julia Base には、科学技術計算や数値計算に適したさまざまな関数やマクロが含まれていますが、多くの汎用プログラミング言語と同様に、幅広い機能を備えています。機能は、拡充を続けるavailable packagesからも利用できます。関数は以下のトピック別にまとめられています。

一般的な注意事項：

  • モジュールの関数を使うには、import Moduleでモジュールをインポートし、Module.fn(x)で関数を使用します。
  • または、using Moduleを使うと、エクスポートされたすべてのModule関数を現在の名前空間にインポートできます。
  • 慣例として、感嘆符（!）で終わる関数名は、引数を変更します。変更を行う関数（例：sort!）と、変更を行わない関数（sort）の両方が用意されている場合もあります。

Baseおよび標準ライブラリの動作が安定していると見なされるのは、SemVerで定義されているとおり、文書化されている場合に限ります。つまり、Julia documentationに記載され、かつ不安定であるとの注記がないものです。詳しくはAPI FAQを参照してください。

Base.exit — Function
exit(code=0)

終了コードを指定してプログラムを終了します。デフォルトの終了コードはゼロで、プログラムが正常に完了したことを示します。対話セッションでは、キーボードショートカット ^D を使って exit() を呼び出せます。

source
Base.atexit — Function
atexit(f)

プロセス終了時に呼び出す、引数を取らないか、引数を1つ取る関数 f() を登録します。atexit() フックは後入れ先出し（LIFO）の順序で呼び出され、オブジェクトのファイナライザーより先に実行されます。

f に整数引数を1つ取るメソッドが定義されている場合は、f(n::Int32) として呼び出されます。ここで、n は現在の終了コードです。それ以外の場合は、f() として呼び出されます。

Julia 1.9

引数を1つ取る形式には Julia 1.9 が必要です。

終了フック内では exit(n) を呼び出せます。この場合、Julia は元の終了コードではなく、終了コード n で終了します。複数の終了フックが exit(n) を呼び出した場合、Julia は exit(n) を呼び出す終了フックのうち、最後に呼び出されたフックに対応する終了コードで終了します。（終了フックは LIFO 順で呼び出されるため、「最後に呼び出された」は「最初に登録された」と同じ意味になります。）

注：すべての終了フックが呼び出された後は、新たな終了フックを登録できません。すべてのフックの実行が完了した後に atexit(f) を呼び出すと、例外がスローされます。この状況は、シャットダウン中も並行して実行されている可能性のあるバックグラウンドの Task から終了フックを登録する場合に発生し得ます。

Base.summarysize — Function
Base.summarysize(obj; count = false, exclude=Union{...}, chargeall=Union{...})::Int

引数から到達可能な一意なオブジェクトをすべて調べ、それらのメモリ上のサイズ（バイト単位）または占有する割り当て数を返します。

Keyword Arguments

  • count: false の場合、オブジェクトのメモリ上の合計サイズを返します。true の場合、オブジェクトが占有する割り当て数を返します。
  • exclude: 探索対象から除外するオブジェクトの型を指定します。
  • chargeall: 通常なら除外されるフィールドも含め、すべてのフィールドのサイズを常に計上するオブジェクトの型を指定します。

sizeofも参照してください。

Examples

julia> Base.summarysize(1.0)
8

julia> Base.summarysize(Ref(rand(100)))
848

julia> sizeof(Ref(rand(100)))
8

julia> Base.summarysize(Core.svec(1.0, "testing", true); count=true)
4

Base.include — Function
Base.include([mapexpr::Function,] m::Module, path::AbstractString)

入力ソースファイルの内容を、モジュール m のグローバルスコープで評価します（baremodule で定義されたモジュールを除く）。各モジュールには、m 引数を省略してファイルをそのモジュール内で評価する、独自の include 定義があります。戻り値は、入力ファイルで最後に評価された式の結果です。インクルード中は、タスクローカルのインクルードパスがファイルの格納ディレクトリに設定されます。include を入れ子で呼び出すと、このパスを基準に検索します。この関数は通常、ソースを対話的に読み込む場合や、複数のソースファイルに分割されたパッケージのファイルをまとめる場合に使用します。

省略可能な第1引数 mapexpr を指定すると、インクルードしたコードを評価前に変換できます。path 内の解析済みの式 expr ごとに、include 関数が実際に評価するのは mapexpr(expr) です。省略した場合、mapexpr の既定値は identity です。

Julia 1.5

mapexpr 引数を渡すには、Julia 1.5 が必要です。

source
include — Function
include([mapexpr::Function,] path::AbstractString)

入力ソースファイルの内容を、包含先モジュールのグローバルスコープで評価します。baremoduleで定義されたものを除き、すべてのModuleには、1引数を取る非公開のinclude定義があります。この定義は、そのモジュール内で使うために、ファイルをそのモジュール内で評価します。戻り値は、入力ファイルで最後に評価された式の結果です。インクルード中は、ファイルを含むディレクトリがタスクローカルのインクルードパスに設定されます。includeを入れ子で呼び出すと、そのパスを基準に検索します。この関数は通常、ソースを対話的に読み込む場合や、複数のソースファイルに分割されたパッケージ内でファイルを結合する場合に使います。引数pathはnormpathを使って正規化されます。これにより、..などの相対パス要素が解決され、/が適切なパス区切り文字に変換されます。

省略可能な第1引数mapexprを使うと、インクルードしたコードを評価する前に変換できます。path内の解析済みの各式exprについて、実際にはinclude関数がmapexpr(expr)を評価します。省略した場合、mapexprの既定値はidentityです。

別のモジュールにファイルを評価するには、Base.includeを使います。

Note

Juliaの構文降下処理は、トップレベルにあるリテラルincludeへの明示的な呼び出しを認識し、インクルードした定義を後続のコードから参照できるよう、暗黙的な@Core.latestworldを挿入します。ただし、この認識は構文上のものです。つまり、const myinclude = includeを代入する場合は、myincludeの後に明示的な@Core.latestworldの呼び出しが必要になることがあります。

Julia 1.5

mapexpr引数を渡すには、Julia 1.5が必要です。

Base.include_dependency — Function
include_dependency(path::AbstractString; track_content::Bool=true)

モジュール内で、path（相対パスまたは絶対パス）で指定したファイル、ディレクトリ、またはシンボリックリンクがプリコンパイル時の依存関係であることを宣言します。つまり、track_content=true の場合、path の内容が変更されると、モジュールを再コンパイルする必要があります（path がディレクトリの場合、その内容とは join(readdir(path)) を指します）。track_content=false の場合は、path の更新日時 mtime が変更されると、再コンパイルが実行されます。

__init__ — Keyword
__init__

モジュール内の__init__()関数は、実行時にそのモジュールが初めて読み込まれた直後に実行されます。この関数は、モジュール内のほかのすべての文が実行された後に、一度だけ呼び出されます。モジュールの読み込みが完了した後に呼び出されるため、サブモジュールの__init__関数が先に実行されます。__init__の典型的な用途として、外部Cライブラリの実行時初期化関数の呼び出しや、外部ライブラリから返されたポインターを含むグローバル定数の初期化があります。詳しくはmanual section about modulesを参照してください。

関連項目: OncePerProcess。

Examples

const foo_data_ptr = Ref{Ptr{Cvoid}}(0)
function __init__()
    ccall((:foo_init, :libfoo), Cvoid, ())
    foo_data_ptr[] = ccall((:foo_data, :libfoo), Ptr{Cvoid}, ())
    nothing
end
source
Base.OncePerProcess — Type
OncePerProcess{T}(init::Function)() -> T

OncePerProcess オブジェクトを呼び出すと、関数 initializer がプロセスごとにちょうど1回実行され、その戻り値として型 T の値が返されます。同じプロセス内での並行呼び出しも、その後の呼び出しも、すべてまったく同じ値を返します。これは、事前コンパイルされるコードで便利です。シリアライズされないキャッシュやその他の状態をセットアップできます。

Julia 1.12

この型を使用するには、Julia 1.12以降が必要です。

Example

julia> const global_state = Base.OncePerProcess{Vector{UInt32}}() do
           println("Making lazy global value...done.")
           return [Libc.rand()]
       end;

julia> (procstate = global_state()) |> typeof
Making lazy global value...done.
Vector{UInt32} (alias for Array{UInt32, 1})

julia> procstate === global_state()
true

julia> procstate === fetch(@async global_state())
true

Base.OncePerThread — Type
OncePerThread{T}(init::Function)() -> T

OncePerThread オブジェクトを呼び出すと、スレッドごとに関数 initializer がちょうど1回実行され、T 型の値が返されます。同じスレッドでの以降の呼び出しや、同じスレッド ID を指定した並行または将来の呼び出しでは、常にまったく同じ値が返されます。また、既存の任意のスレッドの threadid でこのオブジェクトをインデックスすると、そのスレッドに保存された値を取得できます（または、このスレッド上で初期化できます）。誤った使い方はデータ競合やメモリ破損につながる可能性があるため、ライブラリのスレッド安全性の設計上、その動作が適切な場合にのみ使用してください。

Warning

Task が必ず1つのスレッドだけで実行されるとは限りません。そのため、ここで返される値は他の値とエイリアスする場合や、プログラムの実行中に変化する場合があります。この関数は将来非推奨になる可能性があります。initializer が yield すると、この呼び出しの後に現在のタスクを実行するスレッドは、呼び出し開始時のスレッドと異なる場合があります。

関連項目: OncePerTask。

Julia 1.12

この型を使用するには Julia 1.12 以降が必要です。

Example

julia> const thread_state = Base.OncePerThread{Vector{UInt32}}() do
           println("Making lazy thread value...done.")
           return [Libc.rand()]
       end;

julia> (threadvec = thread_state()) |> typeof
Making lazy thread value...done.
Vector{UInt32} (alias for Array{UInt32, 1})

julia> threadvec === fetch(@async thread_state())
true

julia> threadvec === thread_state[Threads.threadid()]
true

Keywords

Juliaで予約されているキーワードは次のとおりです：baremodule、begin、break、catch、const、continue、do、else、elseif、end、export、false、finally、for、function、global、if、import、let、local、macro、module、quote、return、struct、true、try、using、while。これらのキーワードを変数名として使うことはできません。

次の2語からなる並びも予約されています：abstract type、mutable struct、primitive type。ただし、次の名前の変数は作成できます：abstract、mutable、primitive、type。

最後に、whereはパラメトリックなメソッドや型の定義を書くための中置演算子として解析されます。inとisaは中置演算子として解析されます。publicはトップレベル文の先頭でキーワードとして解析されます。outerは、forループの反復指定において変数のスコープを変更するために使われると、キーワードとして解析されます。また、asは、importまたはusingによってスコープに導入された識別子の名前を変更するキーワードとして使われます。ただし、where、in、isa、outer、asという名前の変数は作成できます。

module — Keyword
module

module は Module を宣言します。これは独立したグローバル変数のワークスペースです。モジュール内では、他のモジュールからどの名前を参照可能にするか（インポートによって）を制御できるほか、自分の名前のうち公開するものを export と public によって指定できます。モジュールを使えば、自分のコードが他の人のコードと組み合わせて使われる場合でも、名前の衝突を心配せずにトップレベルの定義を作成できます。詳しくは manual section about modules を参照してください。

Examples

module Foo
import Base.show
export MyType, foo

struct MyType
    x
end

bar(x) = 2x
foo(a::MyType) = bar(a.x) + 1
show(io::IO, a::MyType) = print(io, "MyType $(a.x)")
end
source
export — Keyword
export

exportは、モジュール内で、どの名前をユーザーが利用できるようにするかをJuliaに伝えるために使われます。たとえば、export fooを使うと、モジュールをusingしたときに、名前fooが利用可能になります。詳しくはmanual section about modulesを参照してください。

source
public — Keyword
public

publicは、モジュール内で、どの名前がそのモジュールの公開APIに含まれるかをJuliaに伝えるために使います。たとえば、public fooは、fooという名前が公開されていることを示しますが、usingそのモジュールから利用可能になるわけではありません。

exportはすでに名前が公開されていることを示すため、同じ名前をpublicとexportedの両方で宣言する必要はなく、宣言するとエラーになります。詳しくはmanual section about modulesを参照してください。

Julia 1.11

publicキーワードはJulia 1.11で追加されました。それ以前は、公開性の概念はより明示的ではありませんでした。

as — Keyword
as

asは、importまたはusingによってスコープに取り込まれた識別子の名前を変更するキーワードです。名前の衝突を回避したり、名前を短くしたりする目的で使用します。（import文またはusing文の外では、asはキーワードではなく、通常の識別子として使用できます。）

import LinearAlgebra as LAを使うと、インポートされた標準ライブラリLinearAlgebraがLAとしてスコープに取り込まれます。

import LinearAlgebra: eigen as eig, cholesky as cholを使うと、LinearAlgebraのメソッドeigenとcholeskyが、それぞれeigとcholとしてスコープに取り込まれます。

asは、個々の識別子をスコープに取り込む場合にのみ、usingと併用できます。たとえば、using LinearAlgebra: eigen as eigやusing LinearAlgebra: eigen as eig, cholesky as cholは有効ですが、using LinearAlgebra as LAは構文として無効です。LinearAlgebraからエクスポートされた名前をすべてLAに変更するのは意味をなさないためです。

macro — Keyword
macro

macroは、プログラムに生成コードを挿入するためのメソッドを定義します。マクロは引数式の列を受け取り、返された式を、マクロが呼び出された位置にプログラムへ直接置き換えます。生成コードは周囲のプログラムの一部となるため、マクロを使えばevalを呼び出さずに生成コードを実行できます。マクロの引数には、式、リテラル値、シンボルを指定できます。可変個数の引数（varargs）を受け取るマクロも定義できますが、キーワード引数は受け付けません。また、すべてのマクロには暗黙的に__source__と__module__も渡されます。前者にはマクロの呼び出し元の行番号とファイル名が含まれ、後者はマクロが展開されるモジュールです。

return — Keyword
return

return x は、指定された値 x を呼び出し元に返し、現在の関数を早期に終了します。値を指定せずに return だけを使うと、return nothing と同じ意味になります（nothing を参照）。

function compare(a, b)
    a == b && return "equal to"
    a < b ? "less than" : "greater than"
end

一般に、関数本体のどこにでも return 文を置けます。深くネストしたループや条件分岐の中でも使えますが、do ブロックでは注意が必要です。たとえば、次のようになります。

function test1(xs)
    for x in xs
        iseven(x) && return 2x
    end
end

function test2(xs)
    map(xs) do x
        iseven(x) && return 2x
        x
    end
end

最初の例では、偶数に達すると return によって test1 から抜けるため、test1([5,6,7]) は 12 を返します。

2つ目の例も同じように動作すると思うかもしれませんが、実際には、そこでの return は（do ブロック内の）内側の関数だけを終了し、値を map に返します。その後、test2([5,6,7]) は [5,12,7] を返します。

トップレベルの式（つまり、関数の外側）で使うと、return は現在のトップレベル式全体を早期に終了します。

let — Keyword
let

let ブロックは新しいハードスコープを作り、必要に応じて新しいローカル束縛を導入します。

other scope constructs と同様に、let ブロックは、新たに導入されたローカル変数を参照できるコードの範囲を定めます。さらに、構文には、let と同じ行に任意で記述できる、カンマ区切りの代入と変数名に関する特別な意味があります。

let var1 = value1, var2, var3 = value3
    code
end

この行で導入された変数は let ブロック内のローカル変数となり、代入は順番に評価されます。その際、各右辺は左辺の名前を考慮しないスコープで評価されます。そのため、let x = x のように書くことができます。この場合、2つの x 変数は別個のものであり、左辺は外側のスコープにある x をローカルでシャドーイングします。ローカルスコープに入るたびに新しいローカル変数が作られるため、これは便利なイディオムにもなり得ます。ただし、その違いが観察できるのは、クロージャを介してスコープの外まで存続する変数の場合に限られます。上の例にある var2 のように、代入を伴わない let 変数は、新しいローカル変数を宣言しますが、まだ値には束縛されていません。

一方、begin ブロックも複数の式をまとめますが、スコープを導入せず、特別な代入構文も持ちません。

Examples

以下の関数では、map によって3回繰り返し更新される x が1つだけあります。返されるクロージャはすべて、その x を最終値で参照します。

julia> function test_outer_x()
           x = 0
           map(1:3) do _
               x += 1
               return ()->x
           end
       end
test_outer_x (generic function with 1 method)

julia> [f() for f in test_outer_x()]
3-element Vector{Int64}:
 3
 3
 3

しかし、新しいローカル変数を導入する let ブロックを追加すると、同じ名前を使って（シャドーイングして）いても、各反復で1つずつ、計3つの異なる変数がキャプチャされます。

julia> function test_let_x()
           x = 0
           map(1:3) do _
               x += 1
               let x = x
                   return ()->x
               end
           end
       end
test_let_x (generic function with 1 method)

julia> [f() for f in test_let_x()]
3-element Vector{Int64}:
 1
 2
 3

新しいローカル変数を導入するスコープ構文は、繰り返し実行されるとすべてこのように振る舞います。let の特徴は、外側に同名の変数がある場合にそれをシャドーイングできる、新しい local を簡潔に宣言できることです。たとえば、do 関数の引数を直接使った場合も、同様に3つの異なる変数がキャプチャされます。

julia> function test_do_x()
           map(1:3) do x
               return ()->x
           end
       end
test_do_x (generic function with 1 method)

julia> [f() for f in test_do_x()]
3-element Vector{Int64}:
 1
 2
 3

if — Keyword
if/elseif/else

if/elseif/elseは条件評価を行います。これにより、ブール式の値に応じてコードの一部を評価するかどうかを決められます。if/elseif/else条件構文の構成は次のとおりです。

if x < y
    println("x is less than y")
elseif x > y
    println("x is greater than y")
else
    println("x is equal to y")
end

条件式x < yがtrueの場合、対応するブロックが評価されます。そうでない場合は、条件式x > yが評価され、trueであれば対応するブロックが評価されます。どちらの式もtrueでない場合は、elseブロックが評価されます。elseifブロックとelseブロックは省略可能で、elseifブロックは必要な数だけ使用できます。

一部の他の言語とは異なり、条件の型はBoolでなければなりません。条件がBoolに変換可能であるだけでは不十分です。

julia> if 1 end
ERROR: TypeError: non-boolean (Int64) used in boolean context

try — Keyword
try/catch

try/catch文は、throwがスローするエラー（例外）を捕捉し、プログラムの実行を続行できるようにします。たとえば、次のコードはファイルへの書き込みを試みますが、書き込めない場合は実行を終了せず、ユーザーに警告して処理を続けます。

try
    open("/danger", "w") do f
        println(f, "Hello")
    end
catch
    @warn "Could not write file."
end

ファイルを変数に読み込めない場合は、次のようになります。

lines = try
    open("/danger", "r") do f
        readlines(f)
    end
catch
    @warn "File not found."
end

構文catch e（eは任意の変数）は、スローされた例外オブジェクトを、指定した変数にcatchブロック内で代入します。

try
    a_dangerous_operation()
catch e
    if isa(e, EOFError)
        @warn "The operation failed - EOF."
    elseif isa(e, OutOfMemoryError)
        @warn "The operation failed - OOM."
    else
        rethrow() # ensure other exceptions can bubble up the call stack
    end
end

try/catch構文の利点は、深くネストされた計算から、呼び出し関数のスタック上のはるかに高いレベルへ直ちに巻き戻せることです。

try/catchブロックには、例外が発生しなかった場合にのみ実行されるelse節を付けることもできます。

try
    a_dangerous_operation()
catch
    @warn "The operation failed."
else
    @info "The operation succeeded."
end

tryブロックまたはtry/catchブロックには、例外が発生したかどうかにかかわらず最後に実行されるfinally節を付けることもできます。たとえば、開いたファイルが必ず閉じられるようにするために使えます。

f = open("file")
try
    operate_on_file(f)
catch
    @warn "An error occurred!"
finally
    close(f)
end

（finallyは、catchブロックなしでも使用できます。）

Julia 1.8

else節を使用するには、Julia 1.8以降が必要です。

source
finally — Keyword
finally

指定したtryコードブロックがどのように終了しても、その終了時にコードを実行できます。たとえば、開いたファイルが必ず閉じられるようにするには、次のようにします。

f = open("file")
try
    operate_on_file(f)
finally
    close(f)
end

tryブロックから制御が抜けると（たとえば、returnによる場合や、通常どおり処理が完了した場合）、close(f)が実行されます。tryブロックが例外によって終了した場合、その例外は引き続き伝播します。catchブロックは、tryやfinallyと組み合わせることもできます。この場合、エラーがcatchによって処理された後に、finallyブロックが実行されます。

try/catch/else/finally式を評価するとき、式全体の値は、finallyブロックを除き、最後に実行されたブロックの値になります。たとえば、次のようになります。

julia> try
           1
       finally
           2
       end
1

julia> try
           error("")
       catch
           1
       else
           2
       finally
           3
       end
1

julia> try
           0
       catch
           1
       else
           2
       finally
           3
       end
2

const — Keyword
const

constは、値が変わらないグローバル変数を宣言するために使います。ほとんどのコード、特に性能が重要なコードでは、グローバル変数をこの方法で定数として宣言する必要があります。

const x = 5

1つのconst内で、複数の変数を宣言できます。

const y, z = 7, 11

constは1つの=演算にのみ適用されるため、const x = y = 1ではxは定数として宣言されますが、yは定数として宣言されません。一方、const x = const y = 1では、xとyの両方が定数として宣言されます。

「定数であること」は、変更可能なコンテナの中身には及びません。定数なのは、変数とその値との結び付きだけです。たとえば、xが配列や辞書であれば、要素の変更、追加、削除は引き続き可能です。

場合によっては、const変数の値を変更してもエラーではなく警告が表示されます。しかし、予測できない動作やプログラムの状態の破損につながる可能性があるため、変更は避けてください。この機能は、対話的な使用時の利便性のみを目的としています。

abstract typeはインスタンス化できない型を宣言します。型グラフのノードとしてのみ機能し、関連する具象型の集合、すなわちその子孫にあたる具象型を表します。抽象型は概念上の階層を形成し、Juliaの型システムを単なるオブジェクト実装の集合以上のものにしています。たとえば、次のようになります。

where — Keyword
where

whereキーワードはUnionAll型を作成します。この型は、ある変数のすべての値について、ほかの型を反復的に和集合したものと考えることができます。たとえば、Vector{T} where T<:Realには、要素型が何らかのReal数であるすべてのVectorが含まれます。

変数の上限を省略した場合、デフォルトでAnyになります。

Vector{T} where T    # short for `where T<:Any`

変数には下限を指定することもできます。

Vector{T} where T>:Int
Vector{T} where Int<:T<:Real

入れ子になったwhere式を簡潔に記述する構文もあります。たとえば、次の式は

Pair{T, S} where S<:Array{T} where T<:Number

次のように短縮できます。

Pair{T, S} where {T<:Number, S<:Array{T}}

この形式は、メソッドシグネチャでよく使われます。

この形式では、変数は外側のものから順に並べます。これは、T{p1, p2, ...}構文を使って型をパラメーター値に「適用」するときに、変数が置き換えられる順序と一致します。

= — Keyword
=

=は代入演算子です。

  • 変数aと式bに対して、a = bはaがbの値を参照するようにします。
  • 関数f(x)に対して、f(x) = xは新しい関数定数fを定義します。すでにfが定義されている場合は、fに新しいメソッドを追加します。この用法はfunction f(x); x; endと同等です。
  • a[i] = vはsetindex!(a,v,i)を呼び出します。
  • a.b = cはsetproperty!(a,:b,c)を呼び出します。
  • 関数呼び出しの中では、f(a=b)はキーワード引数aの値としてbを渡します。
  • カンマを含む括弧内では、(a=1,)はNamedTupleを構築します。

Examples

aをbに代入しても、bのコピーは作成されません。代わりにcopyまたはdeepcopyを使用してください。

julia> b = [1]; a = b; b[1] = 2; a
1-element Vector{Int64}:
 2

julia> b = [1]; a = copy(b); b[1] = 2; a
1-element Vector{Int64}:
 1

julia> function f!(x); x[:] .+= 1; end
f! (generic function with 1 method)

julia> a = [1]; f!(a); a
1-element Vector{Int64}:
 2

代入では、反復可能オブジェクトから値を取り出して、複数の変数に並列に代入できます。

julia> a, b = 4, 5
(4, 5)

julia> a, b = 1:3
1:3

julia> a, b
(1, 2)

julia> a = [1]; b = [2]; c = [3]; a = b = c
1-element Vector{Int64}:

julia> b[1] = 2; a, b, c

[...]

julia> push!(a, 2, 3)
4-element Vector{Int64}:
 1
 1
 2
 3

[]を代入しても、コレクションから要素は削除されません。削除するには、代わりにfilter!を使用してください。

julia> a = collect(1:3); a[a .<= 1] = []

[...]

Base.isequal — Function
isequal(x)

引数を isequal を使って x と比較する関数を作成します。つまり、y -> isequal(y, x) と同等の関数です。

返される関数の型は Base.Fix2{typeof(isequal)} で、これを使って特化したメソッドを実装できます。

source
isequal(x, y)::Bool

==と同様ですが、浮動小数点数と欠損値の扱いが異なります。isequalは、すべての浮動小数点数のNaN値を互いに等しいものとして扱い、-0.0を0.0とは等しくないものとして扱い、missingをmissingと等しいものとして扱います。常にBool値を返します。

isequalは同値関係です。すなわち、反射的（===ならばisequal）、対称的（isequal(a, b)ならばisequal(b, a)）、推移的（isequal(a, b)かつisequal(b, c)ならばisequal(a, c)）です。

Implementation

isequalのデフォルト実装は==を呼び出すため、浮動小数点値を含まない型では、通常==を定義するだけで十分です。

isequalは、ハッシュテーブル（Dict）で使われる比較関数です。isequal(x,y)ならば、hash(x) == hash(y)でなければなりません。

通常、カスタムの==またはisequalメソッドが定義されている型では、それに対応するhashメソッドも実装する必要があります（逆も同様です）。コレクションでは通常、すべての要素に対して再帰的にisequalを呼び出すことで、isequalを実装します。

さらに、isequalはislessと連携し、固定された全順序を定義します。このとき、isequal(x, y)、isless(x, y)、isless(y, x)のうち、trueであるものは必ず1つだけで、残り2つはfalseでなければなりません。

スカラー型では一般に、isequalを==とは別に実装する必要はありません。ただし、浮動小数点数を表す型で、汎用フォールバック実装（isnan、signbit、==に基づくもの）より効率的な実装が可能な場合は除きます。

Examples

julia> isequal([1., NaN], [1., NaN])
true

julia> [1., NaN] == [1., NaN]
false

julia> 0.0 == -0.0
true

julia> isequal(0.0, -0.0)
false

julia> missing == missing
missing

julia> isequal(missing, missing)
true
source
Base.isless — Function
isless(x, y)

x が y より小さいかどうかを、（isequal とともに定義される）固定された全順序に従って判定します。isless は、すべての型の (x, y) の組に対して定義されているわけではありません。ただし、定義されている場合は、次の性質を満たすことが期待されます。

  • isless(x, y) が定義されているなら、isless(y, x) と isequal(x, y) も定義され、その3つのうちちょうど1つだけが true となります。
  • isless が定める関係は推移的です。つまり、isless(x, y) && isless(y, z) ならば isless(x, z) です。

通常は順序付けられない値（NaN など）は、通常の値より後に順序付けられます。missing の値は最後に順序付けられます。

これは、sort! が使用するデフォルトの比較です。

Implementation

全順序を持つ非数値型では、この関数を実装する必要があります。数値型では、NaN のような特殊値を持つ場合にのみ実装が必要です。半順序を持つ型では、< を実装してください。ソートや関連する関数で使用できる別の順序付け方法の定義については、Alternate Orderings のドキュメントを参照してください。

Examples

julia> isless(1, 3)
true

julia> isless("Red", "Blue")
false

Base.hash — Function
hash(x[, h::UInt])::UInt

isequal(x,y)がisequal(hash(x), hash(y))を意味するような整数ハッシュコードを計算します。省略可能な第2引数hは、結果と混合する別のハッシュコードです。

新しい型では、通常、内容のハッシュを互いに（またhとも）混合するために、2引数形式を実装し、2引数のhashメソッドを再帰的に呼び出します。通常、hashを実装する型は、上記の性質を保証するために、独自の==（したがってisequal）も実装する必要があります。

ハッシュ値は、新しいJuliaプロセスを開始すると変わることがあります。

julia> a = hash(10)
0x759d18cc5346a65f

julia> hash(10, a) # only use the output of another hash function as the second argument
0x03158cd61b1b0bd1

f はタスク切り替えを引き起こしてはなりません。そのため、println など、ほとんどの I/O 操作は実行できません。デバッグ時には、@async マクロ（コンテキスト切り替えをファイナライザーの外側に遅延させるため）や、ccall を使って C の I/O 関数を直接呼び出すと役立つ場合があります。

f の実行時の world age は保証されていないことに注意してください。ファイナライザーが登録された時点の world age、またはそれ以降の任意の world age で呼び出される可能性があります。

Examples

finalizer(my_mutable_struct) do x
    @async println("Finalizing $x.")
end

finalizer(my_mutable_struct) do x
    ccall(:jl_safe_printf, Cvoid, (Cstring, Cstring), "Finalizing %s.", repr(x))
end

オブジェクトの構築時にファイナライザーを登録することもできます。次の例では、新たに作成された可変構造体 x をファイナライザーが返すことに暗黙的に依存している点に注意してください。

mutable struct MyMutableStruct
    bar
    function MyMutableStruct(bar)
        x = new(bar)
        f(t) = @async println("Finalizing $t.")
        finalizer(f, x)
    end
end

Core.:<: — Function
<:(T1, T2)::Bool

2つの型の間に定義される部分型関係。Juliaでは、型 S が型 T の 部分型 であるとは、S <: T が成り立つことをいいます。

任意の型 L と任意の型 R について、L <: R ならば、型 L の任意の値 v は、型 R でもあります。つまり、(L <: R) && (v isa L) ならば、v isa R です。

部分型関係は 半順序 です。つまり、<: は次の性質を持ちます。

  • 反射的: 任意の型 T について、T <: T が成り立つ
  • 反対称的: 任意の型 A と任意の型 B について、(A <: B) && (B <: A) ならば A == B が成り立つ
  • 推移的: 任意の型 A、任意の型 B、任意の型 C について、(A <: B) && (B <: C) ならば A <: C が成り立つ

Types、Union{}、Any、isa も参照してください。

Examples

julia> Float64 <: AbstractFloat
true

julia> Vector{Int} <: AbstractArray
true

julia> Matrix{Float64} <: Matrix{AbstractFloat}  # `Matrix` is invariant
false

julia> Tuple{Float64} <: Tuple{AbstractFloat}    # `Tuple` is covariant
true

julia> Union{} <: Int  # The bottom type, `Union{}`, subtypes each type.
true

julia> Union{} <: Float32 <: AbstractFloat <: Real <: Number <: Any  # Operator chaining
true

キーワード <: には、同じ部分型関係を表す構文上の用法がほかにもいくつかあります。ただし、これらの用法では演算子は実行されず、Bool も返されません。

  • where 文で、UnionAll 型のパラメーターの下限と上限を指定する。
  • メソッドの（静的）パラメーターの下限と上限を指定する。Parametric Methods を参照。
  • 新しい型の宣言時に部分型関係を定義する。struct と abstract type を参照。

Base.eps — Method
eps(x::AbstractFloat)

x の 最下位桁の単位（ulp）を返します。これは、x における、隣り合う表現可能な浮動小数点数の間の距離です。通常、x の両側で距離が異なる場合は、大きい方を採用します。つまり、

eps(x) == max(x-prevfloat(x), nextfloat(x)-x)

この規則の例外は、最小および最大の有限値（たとえば、nextfloat(-Inf) と prevfloat(Inf)（Float64 の場合））です。これらの値では、小さい方の値に丸められます。

この動作の根拠は、eps が浮動小数点の丸め誤差の上限となることです。デフォルトの丸めモードである RoundNearest では、$y$ が実数で、$x$ が $y$ に最も近い浮動小数点数であるとき、

\[|y-x| \leq \operatorname{eps}(x)/2.\]

関連項目：nextfloat、issubnormal、floatmax。

Examples

julia> eps(1.0)
2.220446049250313e-16

Core.NamedTuple — Type
NamedTuple

NamedTupleは、その名のとおり、名前付きのTupleです。つまり、各要素に一意の名前が付いた、タプルに似た値のコレクションであり、名前はSymbolで表されます。Tupleと同様に、NamedTupleは不変です。構築後に名前や値をその場で変更することはできません。

名前付きタプルは、キーを指定したタプルリテラル（例：(a=1, b=2)）、開き括弧の後にセミコロンを置いたタプルリテラル（例：(; a=1, b=2)。この形式では、後述のようにプログラムで生成した名前も使用できます）、またはNamedTuple型をコンストラクターとして使う方法（例：NamedTuple{(:a, :b)}((1,2))）で作成できます。

名前付きタプルの名前に対応する値には、フィールドアクセス構文（例：x.a）またはgetindexを使ってアクセスできます（例：x[:a]、x[(:a, :b)]）。名前のタプルはkeysで、値のタプルはvaluesで取得できます。

Note

NamedTupleを反復すると、名前ではなく値が得られます（下の例を参照）。名前と値のペアを反復するには、pairs関数を使います。

@NamedTupleマクロを使うと、NamedTuple型を簡単に宣言できます。

Examples

julia> x = (a=1, b=2)
(a = 1, b = 2)

julia> x.a
1

julia> x[:a]
1

julia> x[(:a,)]
(a = 1,)

julia> keys(x)
(:a, :b)

julia> values(x)
(1, 2)

julia> collect(x)
2-element Vector{Int64}:
 1
 2

julia> collect(pairs(x))
2-element Vector{Pair{Symbol, Int64}}:
 :a => 1
 :b => 2

キーワード引数をプログラムで定義する場合と同様に、タプルリテラル内のセミコロンの後にname::Symbol => valueのペアを指定して、名前付きタプルを作成できます。この方法とname=value構文は組み合わせて使えます。

julia> (; :a => 1, :b => 2, c=3)
(a = 1, b = 2, c = 3)

名前と値のペアは、名前付きタプル、または各要素が2つの値を持つコレクションで、最初の値がシンボルであるものを返す任意のイテレーターをスプラットして渡すこともできます。

julia> keys = (:a, :b, :c); values = (1, 2, 3);

julia> NamedTuple{keys}(values)
(a = 1, b = 2, c = 3)

julia> (; (keys .=> values)...)
(a = 1, b = 2, c = 3)

julia> nt1 = (a=1, b=2);

julia> nt2 = (c=3, d=4);

julia> (; nt1..., nt2..., b=20) # the final b overwrites the value from nt1
(a = 1, b = 20, c = 3, d = 4)

julia> (; zip(keys, values)...) # zip yields tuples such as (:a, 1)
(a = 1, b = 2, c = 3)

julia> x = 0

julia> t = (; x)
(x = 0,)

julia> (; t.x)

Core.invoke — Function

指定した引数 args に対し、指定した型 argtypes に一致する、汎用関数 f のメソッドを、キーワード引数 kwargs を渡して呼び出します。引数 args は、指定した型 argtypes に適合している必要があります。つまり、自動的な変換は行われません。このメソッドを使うと、最も具体的に一致するメソッド以外のメソッドを呼び出せます。これは、より一般的な定義の動作を明示的に必要とする場合（多くの場合、同じ関数のより具体的なメソッドの実装の一部として）に便利です。ただし、実行時により多くの処理が必要になるため、invoke は通常の呼び出しによる通常のディスパッチよりも一般に遅く、場合によっては大幅に遅くなります。

@nospecialize

関数の引数名に適用すると、その引数の型ごとにメソッド実装を特殊化せず、宣言された引数の型を使うようコンパイラーに指示します。仮引数リスト内の引数にも、関数本体内にも適用できます。引数に適用する場合、マクロは引数名だけでなく、引数式全体を囲む必要があります。たとえば、@nospecialize(x::Real) や @nospecialize(i::Integer...) のようにします。関数本体内で使う場合は、マクロを文の位置に置き、ほかのコードより前に記述する必要があります。

引数なしで使うと、親スコープ内のすべての引数に適用されます。ローカルスコープでは、これにより包含する関数のすべての引数が対象になります。グローバル（トップレベル）スコープでは、現在のモジュールで以降に定義されるすべてのメソッドが対象になります。

@specialize を使うと、特殊化をデフォルトの状態に戻せます。

function example_function(@nospecialize x)
    ...
end

function example_function(x, @nospecialize(y = 1))
    ...
end

function example_function(x, y, z)
    @nospecialize x y
    ...
end

@nospecialize
f(y) = [x for x in y]
@specialize
Note

@nospecialize はコード生成に影響しますが、推論には影響しません。生成されるネイティブコードの多様性は制限されますが、型推論には（標準的な制限を除き）制約を課しません。推論も抑制するには、Base.@nospecializeinfer と @nospecialize を併用してください。

Examples

julia> f(A::AbstractArray) = g(A)
f (generic function with 1 method)

julia> @noinline g(@nospecialize(A::AbstractArray)) = A[1]
g (generic function with 1 method)

julia> @code_typed f([1.0])
CodeInfo(
1 ─ %1 =    invoke g(A::AbstractArray)::Float64
└──      return %1
) => Float64

ここでは、@nospecialize アノテーションにより、次と同等の処理が行われます。

f(A::AbstractArray) = invoke(g, Tuple{AbstractArray}, A)

これにより、g に対して生成されるネイティブコードは1種類だけとなり、あらゆる AbstractArray に対応する汎用的なものになります。ただし、g と f のどちらについても、具体的な戻り値の型は引き続き推論されます。また、その推論結果は f と g の呼び出し元を最適化する際にも引き続き使われます。

Base.@nospecializeinfer — Macro
Base.@nospecializeinfer function f(args...)
    @nospecialize ...
    ...
end
Base.@nospecializeinfer f(@nospecialize args...) = ...

コンパイラーに、@nospecialize の引数の宣言型を使って f を推論するよう指示します。推論時にコンパイラーが生成する特殊化の数を制限するために使用できます。

Examples

julia> f(A::AbstractArray) = g(A)
f (generic function with 1 method)

julia> @noinline Base.@nospecializeinfer g(@nospecialize(A::AbstractArray)) = A[1]
g (generic function with 1 method)

julia> @code_typed f([1.0])
CodeInfo(
1 ─ %1 =    invoke g(A::AbstractArray)::Any
└──      return %1
) => Any

この例では、f は A の具体的な型ごとに推論されます。一方、g は、宣言された引数型 A::AbstractArray を使って一度だけ推論されます。そのため、具体的な戻り値の型を推論できない場合でも、コンパイラーで過剰な推論時間が発生する可能性は低くなります。@nospecializeinfer がない場合、f([1.0]) は g の戻り値の型を Float64 と推論します。これは、特殊化されたコードの生成が禁止されているにもかかわらず、g(::Vector{Float64}) の推論が実行されたことを示しています。

注釈を付けた関数に対する、関数間定数伝播のモードを制御します。

次の2つのsettingがサポートされています。

  • Base.@constprop :aggressive [ex]: 定数伝播を積極的に適用します。戻り値の型が引数の値に依存するメソッドでは、コンパイル時間が増える代わりに、型推論の結果が改善されることがあります。

    ...
end

# annotate short-form definition
Base.@constprop :aggressive shortdef(x) = ...

# annotate anonymous function that a `do` block creates
f() do
    Base.@constprop :aggressive
    ...

Base.SimdLoop.@simd — Macro
@simd

コンパイラーがループの順序を入れ替えられるよう、for ループに注釈を付けて、より自由に最適化できるようにします。

Warning

この機能は実験的なものであり、今後の Julia のバージョンで変更または削除される可能性があります。@simd マクロを誤って使用すると、予期しない結果を招くことがあります。

@simd for ループで反復処理する対象は、1 次元の範囲である必要があります。@simd を使用すると、ループについて次の性質を満たすことを表明します。

  • リダクション変数に特別な配慮をしたうえで、反復を任意の順序、または重複する順序で安全に実行できる。
  • リダクション変数に対する浮動小数点演算の順序を入れ替えたり、演算を融合したりできる。その結果、@simd を使用しない場合とは異なる結果になる可能性がある。

多くの場合、Julia は @simd を使わなくても、内側の for ループを自動的にベクトル化できます。@simd を使うと、より多くの状況でベクトル化できるよう、コンパイラーに多少の裁量を与えられます。どちらの場合も、内側のループをベクトル化するには、次の性質が必要です。

  • ループは最内ループであること。
  • ループ本体は直線的なコードであること。そのため、現在は配列へのすべてのアクセスに @inbounds が必要です。すべてのオペランドを無条件に評価しても安全な場合、コンパイラーは短い &&、||、?: 式を直線的なコードに変換できることがあります。安全に実行できる場合は、ループ内で ?: の代わりに ifelse 関数を使うことを検討してください。
  • アクセスにはストライドパターンが必要であり、「ギャザー」（ランダムインデックスによる読み取り）や「スキャッター」（ランダムインデックスによる書き込み）は使用できません。
  • ストライドは単位ストライドであること。
Note

@simd は、デフォルトではループ伝搬メモリー依存が完全に存在しないことを表明しません。これは汎用コードでは簡単に破られうる前提です。汎用でないコードを書く場合は、@simd ivdep for ... end を使って、次の点も表明できます。

  • ループ伝搬メモリー依存が存在しない。
  • 反復が、前の反復による進行を待つことがない。

Base.@assume_effects — Macro
Base.@assume_effects setting... [ex]

コンパイラーのエフェクト解析をオーバーライドします。このマクロは、次のような複数のコンテキストで使用できます。

  1. メソッド定義の直前に置き、対象メソッドのエフェクト解析全体をオーバーライドする。
  2. 引数なしで関数本体内に置き、包含するメソッドのエフェクト解析全体をオーバーライドする。
  3. コードブロックに適用し、対象コードブロックのローカルなエフェクト解析をオーバーライドする。

           res = 1
           0 ≤ x < 20 || error("bad fact")
           while x > 1
               res *= x
               x -= 1
           end
           return res
       end
fact (generic function with 1 method)

       end |> only

) => Int64

           map((2,3,4)) do x

               Base.@assume_effects :terminates_locally
               res = 1

Extended help

:consistent

:consistent の設定は、egal（===）な入力に対して、次のことをアサートします。

  • 終了の仕方（戻り値、例外、非終了）は常に同じである。
  • メソッドが戻る場合、結果は常に egal である。
Note

これは特に、メソッドが新たに割り当てた可変オブジェクトを返してはならないことを意味します。可変オブジェクトを複数回割り当てた場合、内容が同一でも egal ではありません。

Note

:consistent-cy アサーションは、特定のワールド範囲 R に対して行われます。より形式的には、ワールドエイジ $i$ における $f$ の評価を $fᵢ$ と表すと、この設定は次を要求します。

\[∀ i ∈ R, j ∈ R, x, y: x ≡ y → fᵢ(x) ≡ fⱼ(y)\]

@assume_effects の場合、範囲 R は、注釈対象またはそれを含むメソッドの m.primary_world:m.deleted_world です。

通常のコードインスタンスでは、R は ci.min_world:ci.max_world です。

さらに、:consistent 関数は、指定されたワールドエイジ範囲内で一定でないヒープの状態やその他のグローバル状態に依存して戻り値を決めてはならないことも意味します。

Note

:consistent-cy には、オプティマイザーが行うすべての合法な書き換えが含まれます。たとえば、浮動小数点数に対する fastmath 演算は :consistent とは見なされません。オプティマイザーが書き換えを行うと、同じワールドエイジであっても出力が :consistent でなくなる可能性があるためです（たとえば、一方がインタープリターで実行され、もう一方が最適化されて実行された場合）。

Note

:consistent 関数が例外を投げて終了する場合、その例外自体は、上記の egal 性の要件を満たす必要はありません。

:effect_free

:effect_free の設定は、メソッドに外部から意味的に観測可能な副作用がないことをアサートします。外部から意味的に観測可能な副作用の例を以下に示します（ただし、これらに限りません）。

  • グローバル変数の値を変更する。
  • 以下に記載する場合を除き、ヒープ（配列や可変値など）を変更する。
  • メソッドテーブルを変更する（たとえば、eval の呼び出しによる変更）。
  • ファイル、ネットワークなどへの入出力。
  • タスクの切り替え。

一方、観測可能な場合があっても、次のものは意味的に観測可能な副作用とは明示的に見なされません。

  • メモリの割り当て（可変・不変の両方）。
  • 経過時間。
  • ガベージコレクション。
  • メソッドの実行期間を超えて存続しないオブジェクト（つまり、メソッド内で割り当てられ、外部に逃げないオブジェクト）のヒープ変更。
  • 戻り値（外部からは見えますが、副作用ではありません）。

目安としては、関数が実行されなかった場合にプログラムの残りの実行に影響するものは、外部から観測可能な副作用です。

Note

:effect_free アサーションは、メソッド自体と、そのメソッドによって実行されるすべてのコードに対して適用されます。このアサーションはすべてのワールドエイジで有効でなければならないため、使用は適切に制限してください。

:nothrow

:nothrow の設定は、このメソッドが例外を投げないこと（つまり、値を返すか、戻らないかのいずれかであること）をアサートします。

Note

:nothrow の注釈が付いたメソッドでも、例外をメソッドの外へ再送出しない限り、内部で例外処理を使用できます。

Note

メソッドの実行によって MethodError などの例外が発生する可能性がある場合、そのメソッドは :nothrow とは見なされません。ただし、StackOverflowError や InterruptException のような環境依存のエラーは、このエフェクトではモデル化されません。そのため、StackOverflowError になる可能性のあるメソッドが、必ずしも !:nothrow である必要はありません（ただし、通常は !:terminates でもあるべきです）。

:terminates_globally

:terminates_globally の設定は、このメソッドが最終的に（正常または異常に）終了し、無限ループしないことをアサートします。

Note

この :terminates_globally アサーションは、注釈対象のメソッドが呼び出す他のすべてのメソッドにも適用されます。

Note

コンパイラーは、この設定をメソッドが比較的速く終了する強い根拠と見なし、（他の条件が許せば）コンパイル時にこのメソッドを呼び出すことがあります。つまり、技術的には終了するものの、実用上は終了しないようなメソッドにこの設定を付けるのは得策ではありません。

:terminates_locally

:terminates_locally の設定は :terminates_globally と似ていますが、注釈対象メソッド内の構文上の制御フローにのみ適用されます。そのため、より弱く安全性の高いアサーションであり、終了しない別のメソッドを呼び出した場合には、注釈対象メソッド自体が終了しない可能性を許容します。

Note

:terminates_globally は :terminates_locally を含意します。

:notaskstate

:notaskstate の設定は、このメソッドがタスクローカルストレージや RNG の状態など、ローカルなタスク状態を使用も変更もしないことをアサートします。そのため、観測可能な結果を変えることなく、タスク間で安全に移動できます。

Note

例外処理の実装では、タスクオブジェクトに保存された状態を使用します。ただし、この状態は現在 :notaskstate の対象範囲とは見なされず、:nothrow エフェクトによって別途追跡されます。

Note

:notaskstate アサーションが対象とするのは、現在実行中のタスクの状態です。どのタスクが現在実行中かを考慮しない別の手段で Task オブジェクトへの参照を取得した場合、:notaskstate エフェクトは汚染されないことがあります。そのタスクオブジェクトが現在実行中のタスクに対して === であっても同様です。

Note

タスク状態へのアクセスは、通常、他のエフェクトも汚染します。たとえば、タスク状態を変更する場合は :effect_free、結果の計算にタスク状態を使用する場合は :consistent が汚染されます。特に、:notaskstate ではないものの、:effect_free かつ :consistent であるコードは、依然としてデッドコード除去の対象となり、:total に昇格することがあります。

:inaccessiblememonly

:inaccessiblememonly の設定は、このメソッドが外部からアクセス可能な可変メモリにアクセスも変更もしないことをアサートします。つまり、メソッドから戻る前に他のメソッドやトップレベルの実行からアクセスできない新規割り当てオブジェクトの可変メモリであれば、アクセスや変更が可能です。一方、可変なグローバル状態や、引数が指す可変メモリにはアクセスも変更もできません。

Note

この前提を無効にする例を以下に示します（ただし、これらに限りません）。

  • グローバル参照、または可変なグローバル変数にアクセスする getglobal 呼び出し。
  • グローバルへの代入、または定数でないグローバル変数に代入する setglobal! 呼び出し。
  • グローバルな可変変数のフィールドを変更する setfield! 呼び出し。
Note

この :inaccessiblememonly アサーションは、注釈対象のメソッドが呼び出す他のすべてのメソッドにも適用されます。

:noub

:noub の設定は、このメソッドが（どのような入力に対しても）未定義動作を実行しないことをアサートします。未定義動作によって、:consistent や :effect_free など、他のエフェクトに関するアサーションにも違反する可能性はあります。しかし、これはモデル化されておらず、各エフェクトは未定義動作がないことを前提としています。

:nortcall

:nortcall の設定は、このメソッドが Core.Compiler.return_type を呼び出さず、また、このメソッドが呼び出す可能性のある他のメソッドも Core.Compiler.return_type を呼び出さないことをアサートします。

Note

厳密には、実行時に Core.Compiler.return_type の呼び出しが行われない場合、つまり Core.Compiler.return_type の結果がコンパイル時に正確に判明し、オプティマイザーによって呼び出しが除去される場合には、このアサーションを使用できます。ただし、Core.Compiler.return_type の結果がコンパイル時に定数畳み込みされるかどうかは、コンパイラーの実装に大きく依存します。そのため、対象メソッドが何らかの形で Core.Compiler.return_type を使用する場合、このアサーションを行うのは一般に危険です。

:foldable

この設定は、コンパイル時に呼び出しを定数畳み込みするためにコンパイラーが保証を必要とするエフェクト一式を、簡潔に指定するものです。現在は、次の setting と同等です。

  • :consistent
  • :effect_free
  • :terminates_globally
  • :noub
  • :nortcall
Note

このリストには、特に :nothrow が含まれていません。コンパイラーは引き続き定数伝播を試み、コンパイル時に発生したエラーを記録します。ただし、:consistent-cy の要件により、この注釈が付いた呼び出しは、同じ引数値に対して常に一貫して例外を投げなければなりません。

Note

関数内に明示的な @inbounds 注釈がある場合も、定数畳み込みは無効になります。この注釈は :foldable によってオーバーライドされません。

:removable

この設定は、コンパイル時に結果が使われない呼び出しを確実に除去するためにコンパイラーが必要とするエフェクト一式を、簡潔に指定するものです。現在は、次の setting と同等です。

  • :effect_free
  • :nothrow
  • :terminates_globally

:total

この setting は、可能な限り最大のエフェクト集合です。現在、次の他の setting を含意します。

  • :consistent
  • :effect_free
  • :nothrow
  • :terminates_globally
  • :notaskstate
  • :inaccessiblememonly
  • :noub
  • :nortcall
Warning

:total は非常に強いアサーションであり、Julia の将来のバージョンでは追加の意味が加わる可能性があります（たとえば、エフェクトが追加され、:total の定義に含まれる場合）。そのため、慎重に使用してください。可能な限り、用途に必要な最小限の具体的なエフェクトアサーションを使用してください。多数のエフェクトのオーバーライドを複数の関数に適用する場合は、:total を使うより、カスタムマクロを使うことをお勧めします。

Negated effects

エフェクト名の前に ! を付けると、先行するメタエフェクトからそのエフェクトを取り除くことを示せます。たとえば、:total !:nothrow は、呼び出しが一般には全域的である一方、例外を投げる可能性があることを示します。

Base.shell_escape_wincmd — Function
shell_escape_wincmd(s::AbstractString)
shell_escape_wincmd(io::IO, s::AbstractString)

エクスポートされていない関数 shell_escape_wincmd は、Windows cmd.exe シェルのメタ文字をエスケープします。()!^<>&| は、その前に ^ を置いてエスケープします。@ がエスケープされるのは、文字列の先頭にある場合だけです。" のペアと、その間にある文字列はエスケープされずにそのまま渡されます。残りの " は ^ でエスケープされ、結果に含まれるエスケープされていない " の数が偶数になるようにします。

cmd.exe は、エスケープ文字 ^ および " を処理する前に、変数参照（%USER% など）を置換します。そのため、この関数はパーセント記号（%）をエスケープしようとはしません。入力に % が含まれていると、結果の使用箇所によっては深刻な問題が発生する可能性があります。

エスケープできない ASCII 制御文字（NUL、CR、LF）を含む入力文字列を渡すと、ArgumentError 例外が発生します。

結果は、CMD.exe /S /C " ... " が処理するコマンド呼び出しの引数（前後を二重引用符で囲む）として安全に渡せます。入力に % が含まれていなければ、対象のアプリケーションにはそのまま渡されます（含まれている場合、この関数は ArgumentError を発生させます）。入力文字列に % が含まれていると、コマンドインジェクションの脆弱性につながる可能性があります。また、前述の処理順序のため、この関数の出力が cmd の引数として適切であるという保証も無効になる場合があります。複数のソースから文字列を組み立てる際は注意してください。

プロセスパイプラインを構築する場合、この関数は Cmd の windows_verbatim フラグと組み合わせると便利です。

wincmd(c::String) =
   run(Cmd(Cmd(["cmd.exe", "/s /c \" $c \""]);
           windows_verbatim=true))
wincmd_echo(s::String) =
   wincmd("echo " * Base.shell_escape_wincmd(s))
wincmd_echo("hello $(ENV["USERNAME"]) & the \"whole\" world! (=^I^=)")

ただし、入力文字列 s に % が含まれていると、引数リストやエコーされたテキストが破損し、任意のコマンドが実行される可能性がある点に注意してください。代わりに引数を環境変数として渡せば、% に関する問題と windows_verbatim フラグが不要になります。

cmdargs = Base.shell_escape_wincmd("Passing args with %cmdargs% works 100%!")
run(setenv(`cmd /C echo %cmdargs%`, "cmdargs" => cmdargs))
Warning

バッチファイルを呼び出す際に CMD が行う引数解析（.bat ファイル内での呼び出し、およびバッチファイルへの引数としての呼び出し）は、この関数の出力と完全には互換性がありません。特に、% の処理方法が異なります。

Important

CMD パーサー／インタープリターの特殊な動作により、リテラルの | 文字（コマンドパイプラインを示す）の後にある各コマンドには、shell_escape_wincmd を2回適用する必要があります。CMD によって2回解析されるためです。つまり、環境変数も2回展開されます。たとえば、次のようになります。

to_print = "All for 1 & 1 for all!"
to_print_esc = Base.shell_escape_wincmd(Base.shell_escape_wincmd(to_print))
run(Cmd(Cmd(["cmd", "/S /C \" break | echo $(to_print_esc) \""]), windows_verbatim=true))

I/O ストリームのパラメーター io を指定すると、結果は文字列として返されず、そこに書き込まれます。

最初に delay 秒待った後、待機中のタスクが起こされ、関数 callback が呼び出されます。その後は、秒単位で指定された interval の間隔でこれを繰り返します。interval が 0 と等しい場合、コールバックは一度だけ実行されます。関数 callback は、タイマー自体を唯一の引数として呼び出されます。タイマーを停止するには close を呼び出します。ただし、タイマーがすでに満了している場合は、callback が最後にもう一度実行されることがあります。

spawn が true の場合、作成されたタスクは spawn されます。つまり、スレッド間の移動が許可されるため、親タスクが現在のスレッドに固定されてしまう副作用を回避できます。spawn が nothing（デフォルト）の場合、親タスクが sticky でなければ、タスクは spawn されます。

Base.Timer — Type
Timer(delay; interval = 0)

タイマーを作成すると、それを待機しているタスクを起こせます（タイマーオブジェクトに対して wait を呼び出します）。

待機中のタスクは、最初に delay 秒以上経過した後に起こされます。その後は、さらに interval 秒以上経過するたびに起こされます。interval が 0 と等しい場合、タイマーは一度だけ発火します。タイマーを閉じると（close を呼び出すと）、待機中のタスクはエラーによって起こされます。タイマーがまだアクティブかどうかを確認するには、isopen を使用します。非アクティブなタイマーは発火しません。t.timeout と t.interval を使用すると、Timer t の設定条件を読み取れます。

julia> isopen(t)
true

julia> t.timeout
1.0

julia> close(t)

julia> isopen(t)
false

interval では、時間のずれが累積することがあります。特定の絶対時刻に正確なイベントを発生させる必要がある場合は、各回の期限が来るたびに、次の時刻までの差分を計算して新しいタイマーを作成してください。

Base.GC.@preserve — Macro
GC.@preserve x1 x2 ... xn expr

式 expr の評価中、オブジェクト x1, x2, ... を「使用中」としてマークします。これは、expr が x のいずれかが所有するメモリやその他のリソースを暗黙的に使用する、unsafe なコードでのみ必要です。

x の暗黙的な使用とは、コンパイラーからは見えない、x が論理的に所有するリソースの間接的な使用を指します。例を挙げます。

  • Ptr を介してオブジェクトのメモリに直接アクセスする
  • x へのポインターを ccall に渡す
  • ファイナライザーによってクリーンアップされる x のリソースを使用する

@preserve は、オブジェクトの寿命を一時的に延長するだけの一般的なユースケースでは、通常、パフォーマンスに影響しません。実装上、@preserve には、動的に割り当てられたオブジェクトがガベージコレクションされないよう保護する効果があります。

Examples

unsafe_load を使ってポインターから読み込む場合、参照先のオブジェクトは暗黙的に使用されます。たとえば、次の例では unsafe_load(p) によって x が暗黙的に使用されます。

julia> let
           x = Ref{Int}(101)
           p = Base.unsafe_convert(Ptr{Int}, x)
           GC.@preserve x unsafe_load(p)
       end
101

ccall にポインターを渡す場合、ポインターが指すオブジェクトは暗黙的に使用されるため、保持しておく必要があります。ただし通常は、x を ccall に直接渡すだけでかまいません。これは明示的な使用として扱われます。

           p = pointer(x)

Base.GC.safepoint — Function
GC.safepoint()

ガベージコレクションが実行される可能性のあるポイントをプログラム内に挿入します。

セーフポイントは高速で、それ自体がガベージコレクションを開始することはありません。ただし、別のスレッドがGCの実行を要求している場合、セーフポイントに到達すると、現在のスレッドはブロックしてGCの完了を待ちます。

これは、マルチスレッドプログラムでまれに役立つことがあります。あるタスクがメモリを割り当てている（そのためGCの実行が必要になる可能性がある）一方で、別のタスクは単純な操作だけを行っている（メモリ割り当て、タスク切り替え、I/Oを行わない）場合です。後者のタスクはJuliaのランタイムに制御を渡さないため、GCの実行を妨げます。メモリを割り当てないタスクでこの関数を定期的に呼び出すと、ガベージコレクションを実行できるようになります。

セーフポイントは高速（通常は約2クロックサイクル）ですが、タイトなループ内で呼び出すとパフォーマンスが低下することがあります。

isbinaryoperator(s::Symbol)

その記号を二項（中置）演算子として使用できる場合は、trueを返します。そうでない場合は、falseを返します。

Examples

julia> Meta.isbinaryoperator(:-), Meta.isbinaryoperator(:√), Meta.isbinaryoperator(:f)
(true, false, false)
