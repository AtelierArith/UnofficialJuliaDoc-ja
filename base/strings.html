Core.AbstractString — Type

AbstractString 型は、Julia におけるすべての文字列実装のスーパータイプです。文字列は、AbstractChar 型で表される Unicode コードポイントの列をエンコードしたものです。Julia の文字列には、いくつかの前提があります。

  • 文字列は、固定サイズの「コードユニット」でエンコードされます。

    • コードユニットは codeunit(s, i) で取り出せます。
    • 最初のコードユニットのインデックスは 1 です。
    • 最後のコードユニットのインデックスは ncodeunits(s) です。
    • 1 ≤ i ≤ ncodeunits(s) が範囲内であるようなインデックス i は、すべて有効です。

  • 文字列のインデックス付けは、これらのコードユニットを基準に行われます。

    • 有効な文字列インデックス i を指定して s[i] を呼び出すと、文字を取り出せます。
    • 文字列内の各 AbstractChar は、1つ以上のコードユニットでエンコードされます。
    • AbstractChar の最初のコードユニットのインデックスだけが有効なインデックスです。
    • AbstractChar のエンコードは、その前後にある内容に依存しません。
    • 文字列のエンコードは self-synchronizing です。つまり、isvalid(s, i) は O(1) です。

文字列からコードユニット、文字、部分文字列を取り出す関数の中には、範囲外または無効な文字列インデックスを渡すとエラーになるものがあります。codeunit(s, i) と s[i] もこれに該当します。一方、文字列インデックスの算術演算を行う関数は、より緩やかな方法でインデックスを扱います。範囲内では最も近い有効な文字列インデックスを返し、範囲外では、文字列の両側に無限個の文字が埋め込まれているかのように動作します。通常、これらの仮想的な埋め込み文字のコードユニット長は 1 ですが、文字列型によっては、実装に適した別の「仮想」文字サイズを選ぶこともできます（たとえば、部分文字列では、インデックス算術をビュー先の元の文字列に委ねる場合があります）。インデックス算術を目的とする thisind、nextind、prevind などが、こうした緩やかなインデックス処理を行う関数です。このモデルでは、範囲外のインデックスを中間値として使っても、文字の取得に使わない限りインデックス算術を行えます。そのため、境界条件に対処するコードを避けられることがよくあります。

関連項目: codeunit、ncodeunits、thisind、nextind、prevind。

Core.AbstractChar — Type

AbstractChar 型は、Julia におけるすべての文字実装のスーパータイプです。文字は Unicode コードポイントを表し、codepoint 関数を使って整数に変換すればコードポイントの数値を取得できます。また、同じ整数から文字を構築することもできます。たとえば、文字同士を < や == で比較する際には、これらの数値が使われます。新しい T <: AbstractChar 型では、少なくとも codepoint(::T) メソッドと T(::UInt32) コンストラクターを定義する必要があります。

ある AbstractChar のサブタイプが Unicode の一部しか表現できない場合、サポートされていない UInt32 値からの変換でエラーが発生することがあります。一方、組み込みの Char 型は、無効なバイトストリームを損失なくエンコードできるよう、Unicode の スーパーセット を表現します。そのため、Unicode に含まれない値を UInt32 に変換するとエラーが発生します。isvalid 関数を使うと、指定した AbstractChar 型でどのコードポイントを表現できるか確認できます。

内部では、AbstractChar 型はさまざまなエンコーディングを使用できます。codepoint(char) による変換では、常に文字の Unicode 値が返されるため、使用されているエンコーディングはわかりません。任意の c::AbstractChar に対する print(io, c) は、必要に応じて Char に変換したうえで、io によって決まるエンコーディングを生成します（組み込みの IO 型ではすべて UTF-8 です）。

これに対して、write(io, c) は typeof(c) に応じたエンコーディングを出力することがあります。また、read(io, typeof(c)) は write と同じエンコーディングを読み取る必要があります。新しい AbstractChar 型では、write と read をそれぞれ独自に実装する必要があります。

Core.Char — Type
Char(c::Union{Number,AbstractChar})

Charは、Juliaで文字を表すデフォルトの32ビットAbstractChar型です。Charは、'x'のような文字リテラルに使われる型であり、Stringの要素型でもあります。

Stringに格納された任意のバイトストリームを損失なく表現するため、Charの値には、Unicodeコードポイントに変換できない情報が含まれる場合があります。そのようなCharをUInt32に変換すると、エラーが発生します。isvalid(c::Char)関数を使うと、cが有効なUnicode文字を表しているかどうかを調べられます。

Base.length — Method
length(s::AbstractString)::Int
length(s::AbstractString, i::Integer, j::Integer)::Int

文字列sの、インデックスiからjまでの文字数を返します。

これは、iからjまでのコード単位インデックスのうち、有効な文字インデックスの数として計算されます。文字列引数が1つだけの場合は、文字列全体の文字数を計算します。引数にiとjを指定すると、文字列s内で有効なインデックスのうち、iからjまでの範囲にあるものの数を計算します。範囲内の値に加えて、iには範囲外の値ncodeunits(s) + 1を、jには範囲外の値0を指定できます。

Note

この操作の時間計算量は、一般に線形です。値をその場で数えるため、文字列内のバイト数または文字数に比例した時間がかかります。これは、定数時間で実行される配列向けのメソッドとは異なります。

関連項目: isvalid、ncodeunits、lastindex、thisind、nextind、prevind。

Examples

julia> length("jμΛIα")
5

Base.repr — Method
repr(x; context=nothing)

2引数のshow(io, x)関数を使うと、任意の値を文字列表現にできます。この関数は、可能な場合にJuliaコードとして解析できる文字列を生成することを目指しています。つまり、eval(Meta.parse(repr(x))) == xが成り立つ必要があります。reprにメソッドを追加してはいけません。代わりに、showメソッドを定義してください。

julia> repr(big(1/3))

Base.LazyString — Type
LazyString <: AbstractString

文字列補間を遅延評価する表現です。実際の補間や文字列の構築が不要、または望ましくない状況（関数のエラー処理など）で文字列を構築する場合に便利です。

この型は、実行時の構築コストを抑えるよう設計されています。可能な限り多くの処理をマクロまたは後続の出力処理に委ねます。

Examples

julia> n = 5; str = LazyString("n is ", n)
"n is 5"

@lazy_strも参照してください。

Julia 1.8

LazyStringを使用するには、Julia 1.8以降が必要です。

Extended help

Safety properties for concurrent programs

遅延文字列自体は、複数のJuliaタスクで出力しても並行処理上の問題を引き起こしません。ただし、キャプチャされた値に対するprintメソッドが、同期なしで呼び出された場合に並行処理上の問題を起こし得るなら、遅延文字列の出力によって問題が発生することがあります。また、キャプチャされた値に対するprintメソッドは複数回呼び出されることがありますが、返される結果は必ず1つだけです。

Julia 1.9

LazyStringは、Julia 1.9以降では上記の意味で安全です。

Base.transcode — Function
transcode(T, src)

Unicode エンコーディング間で文字列データを変換します。src は、UTF-XX コード単位の String または Vector{UIntXX} であり、XX は 8、16、または 32 です。T は戻り値のエンコーディングを指定します。String は（UTF-8 でエンコードされた）String を返し、UIntXX は UTF-XX データの Vector{UIntXX} を返します。（外部 C ライブラリで使用される wchar_t* 文字列を変換する場合は、整数型としてエイリアス Cwchar_t も使用できます。）

transcode 関数は、入力データを変換先のエンコーディングで妥当に表現できる限り成功します。UTF-XX エンコーディング間の変換では、不正な Unicode データであっても常に成功します。

現在サポートされているのは、UTF-8 との変換のみです。

Examples

julia> str = "αβγ"
"αβγ"

julia> transcode(UInt16, str)
3-element Vector{UInt16}:
 0x03b1
 0x03b2
 0x03b3

julia> transcode(String, transcode(UInt16, str))
"αβγ"

Base.unsafe_string — Function
unsafe_string(p::Ptr{T}, [length::Integer]) where {T<:Union{UInt16,UInt32,Cwchar_t}}
unsafe_string(p::Cwstring)

UTF-16（T=UInt16）、UTF-32（T=UInt32）、またはシステム依存のwchar_t（T=Cwchar_tまたはCwstring）でエンコードされたC形式（NUL終端）の文字列について、そのアドレスから文字列をトランスコードし、UTF-8エンコーディングのStringを返します。transcodeと似ていますが、ポインターから直接読み取ります。（ポインターは、その後安全に解放できます。）length（エンコーディング単位で表したデータの長さ）を指定した場合、文字列をNUL終端にする必要はありません。

pが、指定された長さのデータ（またはNUL終端データ）を指す有効なメモリアドレスでない場合、この関数はクラッシュするため、「unsafe」とされています。

Base.@r_str — Macro
@r_str -> Regex

補間やエスケープ処理を行わずに正規表現を作成します。たとえば r"^[a-z]*$" のように記述します（ただし、引用符 " はエスケープする必要があります）。終了引用符の後に1つ以上のフラグを指定すると、正規表現の動作を変更できます。

  • i は、大文字と小文字を区別しないマッチングを有効にします。
  • m は、^ と $ が文字列全体ではなく、各行の先頭と末尾にマッチするようにします。
  • s は、. 修飾子が改行にもマッチするようにします。
  • x は「フリースペースモード」を有効にします。このモードでは、エスケープされていない空白は正規表現のトークン間で無視され、\ でエスケープされた空白は無視されません。また、正規表現中の # はコメントの開始として扱われ、行末まで無視されます。
  • a は ASCII モードを有効にします（UTF モードと UCP モードは無効になります）。デフォルトでは、\B、\b、\D、\d、\S、\s、\W、\w などは、Unicode の文字プロパティに基づいてマッチします。このオプションを指定すると、これらのシーケンスは ASCII 文字にのみマッチします。\u も同様に、指定された文字値を UTF-8 にエンコードしようとせず、単一バイトとして直接出力します。重要な点として、このオプションを使うと、不正な UTF-8 文字列にもマッチできます。マッチャーと対象を文字エンコーディングではなく、単純なバイト列（ISO/IEC 8859-1 / Latin-1 のバイト列と同様）として扱うためです。この場合、このオプションは s と組み合わせて使われることがよくあります。パターンの先頭に (UCP) または (UTF) を指定すると、このオプションをさらに細かく調整できます。

補間が必要な場合は、Regex を参照してください。

julia> match(r"a+.*b+.*?d$"ism, "Goodbye,\nOh, angry,\nBad world\n")

この正規表現では、最初の3つのフラグが有効になっています。

Base.RegexMatch — Type
RegexMatch <: AbstractMatch

文字列内で見つかったRegexへの単一のマッチを表す型です。通常はmatch関数によって作成されます。

matchフィールドには、マッチした文字列全体の部分文字列が格納されます。capturesフィールドには、各キャプチャグループの部分文字列が番号をインデックスとして格納されます。キャプチャグループ名でインデックスを指定するには、例に示すように、マッチオブジェクト全体をインデックス指定します。マッチの開始位置はoffsetフィールドに格納されます。offsetsフィールドには、各キャプチャグループの開始位置が格納されます。キャプチャされなかったグループは0で示されます。

文字列を反転します。厳密には、この関数は文字列内のコードポイントを反転します。主な用途は、文字列を逆順に処理すること、特に正規表現による逆方向検索です。reverseindも参照してください。これは、s内のインデックスをreverse(s)内のインデックスに変換し、その逆も行います。また、コードポイントではなく、ユーザーに見える「文字」（書記素）を扱うには、モジュールUnicodeのgraphemesを参照してください。コピーを作成せずに逆順で反復するには、Iterators.reverseも参照してください。独自の文字列型では、reverse関数を実装する必要があります。通常は、同じ型とエンコーディングの文字列を返すようにしてください。異なるエンコーディングの文字列を返す場合は、s[reverseind(s,i)] == reverse(s)[i]を満たすため、その文字列型に対してreverseindもオーバーライドする必要があります。

Examples

julia> reverse("JuliaLang")
"gnaLailuJ"
Note

以下の例は、システムによって表示が異なる場合があります。コメントは、想定される表示方法を示しています。

結合文字によって、予想外の結果になることがあります。

julia> reverse("ax̂e") # hat is above x in the input, above e in the output
"êxa"

julia> using Unicode

julia> join(reverse(collect(graphemes("ax̂e")))) # reverses graphemes; hat is above x in both in- and output
"ex̂a"

Base.replace — Method
replace([io::IO], s::AbstractString, pat=>r, [pat2=>r2, ...]; [count::Integer])

s 内で指定されたパターン pat を検索し、一致する各箇所を r に置き換えます。count が指定されている場合、置換する箇所は最大 count 個です。pat には、単一の文字、文字のベクトルまたは集合、文字列、正規表現を指定できます。r が関数の場合、一致する各箇所は r(s) に置き換えられます。ここで s は、pat が AbstractPattern または AbstractString の場合は一致した部分文字列、pat が AbstractChar または AbstractChar のコレクションの場合は一致した文字です。pat が正規表現で、r が SubstitutionString の場合、r 内のキャプチャグループへの参照は、対応する一致テキストに置き換えられます。string から pat に一致する箇所を削除するには、r に空の String（""）を設定します。

戻り値は、置換後の新しい文字列です。io::IO 引数が指定されている場合は、代わりに変換後の文字列を io に書き込み、io を返します。（たとえば、IOBuffer と組み合わせることで、事前に確保したバッファ配列をその場で再利用できます。）

複数のパターンを指定できます。入力文字列は先頭（左）から末尾（右）まで一度だけ走査され、各部分文字列には最初に一致した置換が適用されます。入力文字列の同じ位置から始まる部分文字列に複数のパターンが一致する場合は、指定された引数の順に置換が適用されます。したがって、各文字に適用されるパターンは1つだけであり、パターンは入力テキストにのみ適用され、置換後のテキストには適用されません。

Julia 1.7

複数のパターンを使用するには、バージョン1.7以降が必要です。

Julia 1.10

io::IO 引数を使用するには、バージョン1.10以降が必要です。

Examples

julia> replace("Python is a programming language.", "Python" => "Julia")
"Julia is a programming language."

julia> replace("The quick foxes run quickly.", "quick" => "slow", count=1)
"The slow foxes run quickly."

julia> replace("The quick foxes run quickly.", "quick" => "", count=1)
"The  foxes run quickly."

julia> replace("The quick foxes run quickly.", r"fox(es)?" => s"bus\1")
"The quick buses run quickly."

julia> replace("abcabc", "a" => "b", "b" => "c", r".+" => "a")

Base.nextind — Method
nextind(str::AbstractString, i::Integer, n::Integer=1)::Int

  • ケース n == 1

    i が str の範囲内にある場合、インデックス i より後からエンコーディングが始まる文字の開始位置のインデックスを返します。つまり、i が文字の開始位置であれば、次の文字の開始位置を返します。i が文字の開始位置でない場合は、次の文字の開始位置まで進み、そのインデックスを返します。i が 0 と等しい場合は、1 を返します。i が範囲内にあり、lastindex(str) 以上の場合は、ncodeunits(str)+1 を返します。それ以外の場合は BoundsError をスローします。

Base.escape_string — Function
escape_string(str::AbstractString[, esc]; keep=(), ascii=false, fullhex=false)::AbstractString
escape_string(io, str::AbstractString[, esc]; keep=())::Nothing

従来のC形式およびUnicode形式のエスケープシーケンスを一般的にエスケープします。1つ目の形式はエスケープ後の文字列を返し、2つ目の形式は結果をioに出力します。

バックスラッシュ（\）は、二重のバックスラッシュ（"\\"）にエスケープされます。印字できない文字は、標準的なC形式のエスケープコード、NULの場合は"\0"（曖昧さがない場合）、Unicodeコードポイント（"\u"プレフィックス）、または16進数（"\x"プレフィックス）でエスケープされます。

省略可能なesc引数では、先頭にバックスラッシュを付けてエスケープする追加の文字を指定します（1つ目の形式では、"もデフォルトでエスケープされます）。

keep引数では、そのまま保持する文字の集合を指定します。ただし、ここではescが優先されます。

ascii引数をtrueに設定すると、ASCII以外のすべての文字がエスケープされます。デフォルトのascii=falseでは、印字可能なUnicode文字はそのまま出力されます。（keepはasciiより優先されます。）

fullhex引数をtrueに設定すると、すべての\uエスケープは4桁の16進数で、\Uエスケープは8桁の16進数で出力されます。デフォルト（fullhex=false）では、可能な場合は先頭のゼロを省略し、桁数を少なくして出力します。

逆の操作については、unescape_stringも参照してください。

Julia 1.7

keep引数はJulia 1.7以降で使用できます。

Julia 1.12

ascii引数とfullhex引数にはJulia 1.12が必要です。

julia> escape_string("aaa\nbbb"; keep = '\n')

Base.AnnotatedString — Type
AnnotatedString{S <: AbstractString} <: AbstractString

注釈付き領域を含む、メタデータ付きの文字列です。

より具体的には、任意のAbstractStringを包むシンプルなラッパーで、ラップされた文字列の領域にラベル付きの値を注釈として付与できます。

                           C
                    ┌──────┸─────────┐
  "this is an example annotated string"
  └──┰────────┼─────┘         │
     A        └─────┰─────────┘
                    B

上の図は、3つの範囲に注釈（ラベルはA、B、C）が付与されたAnnotatedStringを示しています。各注釈は、ラベル（Symbol）と値（Any）を持ちます。この3つの情報は、@NamedTuple{region::UnitRange{Int64}, label::Symbol, value}として保持されます。

ラベルは一意である必要はありません。同じ領域に、同じラベルの注釈を複数付与できます。

一般に、AnnotatedString向けに書かれたコードでは、次の性質を維持する必要があります。

  • 注釈が適用される文字
  • 各文字に注釈が適用される順序

AnnotatedStringの具体的な用途によっては、さらに意味が加わる場合があります。

この規則から、同じラベルと値を持つ注釈が隣接して連続している場合、それらは結合した範囲に付与された単一の注釈と同等になります。

AnnotatedChar、annotatedstring、annotations、annotate!も参照してください。
