Base.Filesystem.readdir — Function
readdir(dir::AbstractString=pwd();
    join::Bool = false,
    sort::Bool = true,

dir ディレクトリ内の名前を返します。ディレクトリが指定されていない場合は、現在の作業ディレクトリ内の名前を返します。join が false の場合、readdir はディレクトリ内の名前をそのまま返します。join が true の場合は、各 name に対して joinpath(dir, name) を返し、返される文字列はフルパスになります。絶対パスを取得するには、絶対パスのディレクトリを指定し、join を true にして readdir を呼び出します。

Base.Filesystem.walkdir — Function
walkdir(dir = pwd(); topdown=true, follow_symlinks=false, onerror=throw)

ディレクトリのディレクトリツリーをたどるイテレータを返します。

このイテレータは、(path, dirs, files)を含むタプルを返します。反復のたびに、pathはツリー内の次のディレクトリに変わります。その後、dirsとfilesは、現在のpathディレクトリ内のディレクトリとファイルを含むベクターになります。ディレクトリツリーは、トップダウンまたはボトムアップでたどれます。walkdirまたはstatでIOErrorが発生した場合、デフォルトではエラーが再スローされます。onerrorキーワード引数で、独自のエラー処理関数を指定できます。onerrorには、引数としてIOErrorが渡されます。返されるイテレータは状態を保持するため、繰り返しアクセスすると、Iterators.Statefulのように、前回の続きから再開します。

関連項目: readdir。

Julia 1.12

Julia 1.12で、pwd()がデフォルトのディレクトリとして追加されました。

Examples

for (path, dirs, files) in walkdir(".")
    println("Directories in $path")
    for dir in dirs
        println(joinpath(path, dir)) # path to directories
    end
    println("Files in $path")
    for file in files
        println(joinpath(path, file)) # path to files
    end
end
julia> mkpath("my/test/dir");

julia> itr = walkdir("my");

julia> (path, dirs, files) = first(itr)
("my", ["test"], String[])

julia> (path, dirs, files) = first(itr)
("my/test", ["dir"], String[])

julia> (path, dirs, files) = first(itr)
("my/test/dir", String[], String[])

Base.Filesystem.mkdir — Function
mkdir(path::AbstractString; mode::Unsigned = 0o777)

新しいディレクトリを、名前を path、パーミッションを mode として作成します。mode のデフォルト値は 0o777 で、現在のファイル作成マスクによって変更されます。この関数が作成するディレクトリは1つだけです。ディレクトリがすでに存在する場合、または途中のディレクトリが存在しない場合、この関数はエラーをスローします。必要な中間ディレクトリをすべて作成する関数については、mkpath を参照してください。path を返します。

Examples

julia> mkdir("testingdir")
"testingdir"

julia> cd("testingdir")

julia> pwd()
"/home/JuliaUser/testingdir"

Base.Filesystem.mkpath — Function
mkpath(path::AbstractString; mode::Unsigned = 0o777)

必要に応じて、path 内のすべての中間ディレクトリを作成します。ディレクトリは mode の権限で作成されます。この権限はデフォルトで 0o777 であり、現在のファイル作成マスクによって変更されます。mkdir とは異なり、mkpath は、path（またはその一部）がすでに存在していてもエラーになりません。ただし、path（またはその一部）が既存のファイルを指している場合は、エラーが発生します。path を返します。

path にファイル名が含まれている場合は、ファイル名を使ってディレクトリを作成しないよう、mkpath(dirname(path)) を使用するとよいでしょう。

Examples

julia> cd(mktempdir())

julia> mkpath("my/test/dir") # creates three directories
"my/test/dir"

julia> readdir()
1-element Vector{String}:
 "my"

julia> cd("my")

julia> readdir()
1-element Vector{String}:
 "test"

julia> readdir("test")
1-element Vector{String}:
 "dir"

julia> mkpath("intermediate_dir/actually_a_directory.txt") # creates two directories
"intermediate_dir/actually_a_directory.txt"

julia> isdir("intermediate_dir/actually_a_directory.txt")
true

julia> mkpath("my/test/dir/") # returns the original `path`
"my/test/dir/"

Base.Filesystem.symlink — Function
symlink(target::AbstractString, link::AbstractString; dir_target = false)

targetへのシンボリックリンクを、linkという名前で作成します。

Windowsでは、シンボリックリンクがディレクトリを指すかどうかを明示する必要があります。targetがすでに存在する場合、デフォルトではlinkの種類が自動判定されます。ただし、targetが存在しない場合、この関数はデフォルトでファイルへのシンボリックリンクを作成します。ただし、dir_targetがtrueに設定されている場合は除きます。ユーザーがdir_targetを設定していても、targetが存在し、それがファイルである場合、ディレクトリへのシンボリックリンクが作成されますが、リンク先をたどるとエラーになります。これは、ディレクトリを作成する前にdir_targetをfalseに設定してsymlink()を呼び出し、ファイルへのシンボリックリンクを作成してから、そのリンクをたどってディレクトリにアクセスしようとした場合と同様です。

また、Windowsでリンクを作成する方法には、シンボリックリンクとジャンクションポイントの2種類があります。ジャンクションポイントはやや効率的ですが、相対パスには対応していません。そのため、相対パスのディレクトリシンボリックリンクが要求された場合（isabspath(target)がfalseを返す場合）はシンボリックリンクが使われ、それ以外の場合はジャンクションポイントが使われます。Windowsでシンボリックリンクを作成する際は、参照先のファイルやディレクトリを作成してからリンクを作成するのがベストプラクティスです。

関連項目: hardlink。

Note

Windows XPなど、ソフトシンボリックリンクに対応していないオペレーティングシステムでは、この関数はエラーを発生させます。

Julia 1.6

dir_targetキーワード引数はJulia 1.6で追加されました。それ以前は、Windowsでは存在しないパスへのシンボリックリンクは常にファイルへのリンクとなり、ディレクトリへの相対シンボリックリンクには対応していませんでした。

Base.Filesystem.uperm — Function

Base.Filesystem.cp — Function
cp(src::AbstractString, dst::AbstractString; force::Bool=false, follow_symlinks::Bool=false)

src から dst に、ファイル、リンク、またはディレクトリをコピーします。force=true は、既存の dst を最初に削除します。

follow_symlinks=false がシンボリックリンクであり、src もシンボリックリンクの場合、dst はシンボリックリンクとして作成されます。follow_symlinks=true がシンボリックリンクであり、src もシンボリックリンクの場合、dst は、src が指すファイルまたはディレクトリのコピーになります。dst を返します。

Note

cp 関数は、Unix コマンドの cp とは異なります。cp 関数は、dst がファイルであると常に仮定して動作します。一方、このコマンドは、dst がディレクトリかファイルかによって動作が異なります。dst がディレクトリの場合に force=true を使用すると、dst ディレクトリ内のすべての内容が失われ、代わりに dst は src の内容を持つファイルになります。

julia> mv("hello.txt", "goodbye.txt", force=true)

julia> rm("goodbye.txt");
Note

mv 関数は、Unix コマンドの mv とは異なります。mv 関数は、dst が存在すると、デフォルトではエラーになります。一方、このコマンドはデフォルトで既存の dst ファイルを削除します。また、mv 関数は常に dst をファイルとして扱いますが、このコマンドは dst がディレクトリかファイルかによって動作が異なります。dst がディレクトリの場合に force=true を使うと、dst ディレクトリ内のすべての内容が失われ、代わりに src の内容を持つファイルが dst として作成されます。

Base.Filesystem.rename — Function
Base.rename(oldpath::AbstractString, newpath::AbstractString)

ファイルまたはディレクトリの名前を、oldpathからnewpathに変更します。newpathが既存のファイルまたは空のディレクトリである場合は、置き換えられることがあります。Unixのrename(2)と同等です。パスに「\0」が含まれている場合は、ArgumentErrorをスローします。それ以外のエラーが発生した場合は、IOErrorをスローします。newpathを返します。

これは、mvを実装するために使用される、低レベルのファイルシステム操作です。

oldpathとnewpathが異なるディレクトリにある場合、OS固有の制約が適用されることがあります。

Windowsでは現在、動作にいくつかの違いがあります。これらは将来のリリースで解消される可能性があります。具体的には、現在のWindowsでは次のとおりです。

  1. renameは、oldpathまたはnewpathが開かれたファイルの場合、失敗します。
  2. renameは、newpathが既存のディレクトリの場合、失敗します。
  3. renameは、newpathがファイルで、oldpathがディレクトリの場合、成功することがあります。
  4. renameは、oldpathがnewpathへのハードリンクである場合、これを削除することがあります。

Base.Filesystem.tempname — Function
tempname(parent=tempdir(); cleanup=true, suffix="")::String

一時ファイルのパスを生成します。この関数はパスを返すだけで、ファイルは作成しません。パスは一意である可能性が高いものの、tempnameを同時に呼び出した際、非常にまれに同じファイル名が生成される可能性があるため、一意性は保証されません。ただし、tempnameの呼び出し時点ですでに存在するすべてのファイルとは異なる名前が保証されます。

引数を指定せずに呼び出すと、一時パスとして、tempdir()で指定されるシステムの一時ディレクトリ内の絶対パスが返されます。parentディレクトリを引数に指定した場合は、そのディレクトリ内のパスが返されます。サフィックスを指定すると、一時ファイル名はそのサフィックスで終わり、そのサフィックスを付けた状態で一意性が確認されます。

cleanupオプションは、プロセス終了時に返されたパスを自動的に削除するかどうかを制御します。tempname関数は、返された場所にファイルやディレクトリを作成しないため、そこにファイルやディレクトリを作成しない限り、後片付けの対象はありません。作成した場合、cleanupがtrueであれば、プロセス終了時に削除されます。

parent引数とcleanup引数は、1.4で追加されました。Julia 1.4より前では、パスtempnameがプロセス終了時に削除されることはありませんでした。

Julia 1.12

suffixキーワード引数は、Julia 1.12で追加されました。

Warning

別のプロセスが同じファイル名を取得し、こちらがファイルを作成する前にそのファイルを作成すると、セキュリティ上の問題が発生するおそれがあります。これが懸念される場合は、JL_O_EXCLを使ってファイルを開いてください。代わりにmktemp()を使うことも推奨されます。

Base.Filesystem.joinpath — Function
joinpath(parts::AbstractString...)::String
joinpath(parts::Vector{AbstractString})::String
joinpath(parts::Tuple{AbstractString})::String

パスの各要素を結合して、完全なパスを作成します。引数のいずれかが絶対パスである場合、または（Windows で）それ以前のパスを結合して算出したドライブと異なるドライブ指定を含む場合、それより前の要素は破棄されます。

Windows ではドライブごとにカレントディレクトリがあるため、joinpath("c:", "foo")はドライブ「c:」のカレントディレクトリからの相対パスを表します。したがって、これは「c:\foo」ではなく「c:foo」と同じです。さらに、joinpathはこれを絶対パスではないものとして扱い、ドライブ文字の大文字・小文字を区別しません。そのため、joinpath("C:\\A","c:b") = "C:\\A\\b"となります。

Examples

julia> joinpath("/home/myuser", "example.jl")

julia> joinpath(["/home/myuser", "example.jl"])
