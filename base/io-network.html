source
IOBuffer([data::AbstractVector{UInt8}]; keywords...)::IOBuffer

メモリ上に I/O ストリームを作成します。既存の配列を使用することもできます。

次のキーワード引数を省略可能な形で指定できます。

  • read、write、append: 操作をバッファー内に制限します。詳細は open を参照してください。
  • truncate: バッファーのサイズをゼロに切り詰めます。
  • maxsize: バッファーを拡張できる上限サイズを指定します。
  • sizehint: バッファーの容量を指定します（data は sizehint!(data, size) を実装している必要があります）。

data を指定しない場合、バッファーはデフォルトで読み書き可能になります。

`write=true` を指定して `data` を `IOBuffer` のスクラッチ領域として渡すと、予期しない動作が起こることがあります

IOBuffer に対して write を呼び出した後は、data への以前の参照は無効になったものと考えるのが最善です。実質的に、take! が呼び出されるまで、IOBuffer がこのデータを「所有」します。data を間接的に変更すると、IOBuffer が前提とする抽象化が損なわれ、未定義の動作につながる可能性があります。write=true の場合、IOBuffer は任意のオフセットにデータを格納し、ほかのオフセットには任意の値を残すことがあります。maxsize > length(data) の場合、IOBuffer はデータ全体を再割り当てすることがあります。その結果は、array への既存のバインディングから見える場合もあれば、見えない場合もあります。

Examples

julia> io = IOBuffer();

julia> write(io, "JuliaLang is a GitHub organization.", " It has many members.")
56

julia> takestring!(io)
"JuliaLang is a GitHub organization. It has many members."

julia> io = IOBuffer(b"JuliaLang is a GitHub organization.")
IOBuffer(data=UInt8[...], readable=true, writable=false, seekable=true, append=false, size=35, maxsize=Inf, ptr=1, mark=-1)

julia> read(io, String)
"JuliaLang is a GitHub organization."

julia> write(io, "This isn't writable.")
ERROR: ArgumentError: ensureroom failed, IOBuffer is not writeable

julia> io = IOBuffer(UInt8[], read=true, write=true, maxsize=34)
IOBuffer(data=UInt8[...], readable=true, writable=true, seekable=true, append=false, size=0, maxsize=34, ptr=1, mark=-1)

julia> write(io, "JuliaLang is a GitHub organization.")
34

julia> takestring!(io)
"JuliaLang is a GitHub organization"

julia> length(read(IOBuffer(b"data", read=true, truncate=false)))
4

julia> length(read(IOBuffer(b"data", read=true, truncate=true)))
0

Base.Pipe — Type
Pipe()

複数のプロセス間での IO 通信などに使う、未初期化の Pipe オブジェクトを構築します。

プロセスの起動時にこのオブジェクトを使用すると、パイプの適切な端が自動的に初期化されます。たとえば、プロセスパイプライン内で参照を簡単に取得するのに便利です。

julia> err = Pipe()

# After this `err` will be initialized and you may read `foo`'s
# stderr from the `err` pipe, or pass `err` to other pipelines.
julia> run(pipeline(pipeline(`foo`, stderr=err), `cat`), wait=false)

# Now destroy the write half of the pipe, so that the read half will get EOF
julia> closewrite(err)

julia> read(err, String)
"stderr messages"

Base.link_pipe! も参照してください。

Base.close — Function
close(io::IO)

ioを閉じます。まずflushを実行します。

IOを閉じると、その基盤となるリソース（OSハンドル、ネットワーク接続など）が破棄されることを示します。閉じたIOは状態が未定義であり、読み書きしてはいけません。閉じたIOに対して読み書きを試みた場合、実装によっては例外が発生したり、通常どおり動作し続けたり、0バイトの読み書きが行われたりすることがあります。ただし、閉じたIOの読み書きによって未定義動作が発生しないよう、実装側で保証する必要があります。

関連項目: isopen

source
Base.closewrite — Function
closewrite(stream)

全二重 I/O ストリームの書き込み側をシャットダウンします。まず flush を実行します。基盤となるファイルにはこれ以上データを書き込まないことを、相手側に通知します。この操作は、すべての IO 型でサポートされているわけではありません。

実装されている場合、closewrite を呼び出すと、その後の read または eof の呼び出しがブロックする状況では、代わりに EOF がスローされるか、true が返されます。ストリームがすでに閉じている場合、この操作は冪等です。

Examples

julia> io = Base.BufferStream(); # this never blocks, so we can read and write on the same Task

julia> write(io, "request");

julia> # calling `read(io)` here would block forever

julia> closewrite(io);

julia> read(io, String)
"request"
source
Base.write — Function
write(io::IO, x)

値の正規バイナリ表現を、指定された I/O ストリームまたはファイルに書き込みます。ストリームに書き込まれたバイト数を返します。テキスト表現を書き込む場合は、printも参照してください（エンコーディングはioによって異なる場合があります）。

書き込まれる値のエンディアンは、ホストシステムのエンディアンに依存します。プラットフォーム間で結果を一貫させるには、書き込み時または読み込み時に、htolやltohなどを使って固定エンディアンに変換してください。

同じwrite呼び出しで複数の値を書き込めます。つまり、次の例は同じ結果になります。

write(io, x, y...)
write(io, x) + write(io, y...)

Examples

一貫性のあるシリアライズ:

julia> fname = tempname(); # random temporary filename

julia> open(fname,"w") do f
           # Make sure we write 64bit integer in little-endian byte order
           write(f,htol(Int64(42)))
       end
8

julia> open(fname,"r") do f
           # Convert back to host byte order and host integer type
           Int(ltoh(read(f,Int64)))
       end
42

write呼び出しの統合:

julia> io = IOBuffer();

julia> write(io, "JuliaLang is a GitHub organization.", " It has many members.")
56

julia> takestring!(io)
"JuliaLang is a GitHub organization. It has many members."

julia> write(io, "Sometimes those members") + write(io, " write documentation.")
44

julia> takestring!(io)
"Sometimes those members write documentation."

Multimedia I/O

テキスト出力を print が行い、ユーザー定義型が show をオーバーロードすることでテキスト表現を指定できるのと同様に、Julia には、画像、書式付きテキスト、さらには音声や動画などのリッチなマルチメディア出力を行うための標準化された仕組みがあります。この仕組みは次の3つの要素から成ります。

  • Julia オブジェクト x を、プレーンテキストにフォールバックしつつ、利用可能な中で最もリッチな形式で表示するよう要求する関数 display(x)。
  • show をオーバーロードすると、ユーザー定義型について、標準 MIME タイプをキーとする任意のマルチメディア表現を指定できます。
  • マルチメディア対応の表示バックエンドは、汎用の AbstractDisplay 型をサブクラス化して登録し、pushdisplay を使って表示バックエンドのスタックに追加できます。

Julia の基本ランタイムが提供するのはプレーンテキスト表示のみですが、外部モジュールを読み込むか、グラフィカルな Julia 環境（IPython ベースの IJulia ノートブックなど）を使うことで、よりリッチな表示を利用できます。

Base.show — Method
show(io::IO, mime, x)

最終的に、display 関数は show を呼び出し、可能であれば、オブジェクト x を指定された mime 型として、指定された I/O ストリーム io（通常はメモリバッファ）に書き込みます。ユーザー定義型 T の豊かなマルチメディア表現を提供するには、T に対する新しい show メソッドを、次のように定義するだけで十分です。show(io, ::MIME"mime", x::T) = ...。ここで、mime は MIME タイプを表す文字列であり、関数本体では write（または同様の関数）を呼び出して、その表現の x を io に書き込みます。（なお、MIME"" 記法で指定できるのはリテラル文字列のみです。より柔軟に MIME 型を構築するには、MIME{Symbol("")} を使用してください。）

たとえば、MyImage 型を定義し、それを PNG ファイルに書き込む方法がわかっている場合、関数 show(io, ::MIME"image/png", x::MyImage) = ... を定義すれば、PNG に対応した任意の AbstractDisplay（IJulia など）で画像を表示できるようになります。Julia 組み込み関数 show に新しいメソッドを追加するには、通常どおり import Base.show を忘れずに行ってください。

技術的には、MIME"mime" マクロは、指定された mime 文字列に対するシングルトン型を定義します。これにより、Julia のディスパッチ機構を利用して、任意の型のオブジェクトをどのように表示するかを決定できます。

デフォルトの MIME タイプは MIME"text/plain" です。text/plain 出力にはフォールバック定義があり、これは2引数の show を呼び出すため、このケースでは必ずしもメソッドを追加する必要はありません。ただし、型に人間が読みやすい独自の出力が適している場合は、show(::IO, ::MIME"text/plain", ::T) を定義してください。たとえば、Day 型では、text/plain MIME タイプの出力に 1 day を使用し、2引数の show の出力には Day(1) を使用します。

Examples

julia> struct Day
           n::Int
       end

julia> Base.show(io::IO, ::MIME"text/plain", d::Day) = print(io, d.n, " day")

julia> Day(1)
1 day

コンテナ型では通常、3引数の show を実装する際、要素 x に対して show(io, MIME"text/plain"(), x) を呼び出します。その際、最初の引数として渡す IOContext では、:compact => true を設定します。

前述のとおり、新しい表示バックエンドを定義することもできます。たとえば、PNG 画像をウィンドウに表示できるモジュールは、その機能を Julia に登録できます。これにより、PNG 表現を持つ型に対して display(x) を呼び出すと、そのモジュールのウィンドウに画像が自動的に表示されます。

新しい表示バックエンドを定義するには、まず抽象クラス AbstractDisplay のサブタイプ D を作成します。次に、D 上で表示できる各 MIME タイプ（文字列 mime）について、その MIME タイプとして x を表示する関数 display(d::D, ::MIME"mime", x) = ... を定義します。通常は show(io, mime, x) または repr(io, mime, x) を呼び出します。x をその MIME タイプとして表示できない場合は、MethodError をスローする必要があります。show または repr を呼び出せば、これは自動的に行われます。

最後に、D がサポートする mime 型を showable(mime, x) に問い合わせ、その中から「最適な」ものを表示する関数 display(d::D, x) を定義します。x に対応する MIME タイプが見つからない場合は、MethodError をスローする必要があります。同様に、一部のサブタイプでは redisplay(d::D, ...) をオーバーライドすることもできます。（繰り返しますが、display に新しいメソッドを追加するには、import Base.display する必要があります。）これらの関数の戻り値は実装に委ねられます（場合によっては、何らかの表示「ハンドル」を返すと便利なためです）。D の表示関数は直接呼び出すこともできますが、次のように新しい表示を表示バックエンドのスタックに追加すれば、display(x) から自動的に呼び出すこともできます。

Base.Multimedia.istextmime — Function
istextmime(m::MIME)

MIMEタイプがテキストデータかどうかを判定します。MIMEタイプは、テキストデータ（Unicodeの場合もあります）として知られている一部のタイプを除き、バイナリデータであるとみなされます。

true

false
