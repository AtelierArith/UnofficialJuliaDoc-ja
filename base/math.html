Base.:+ — Function
+(x, y...)

加算演算子。

中置演算子 x+y+z+... は、すべての引数を使ってこの関数を呼び出します。つまり、+(x, y, z, ...) であり、デフォルトでは左から順に (x+y) + z + ... を呼び出します。

julia> +(1, 20, 4)

julia> [1,2] + [3,4]

 4
 6

julia> typemax(Int) + 1 < 0
true

Base.:* — Method
*(x, y...)

乗算演算子。

中置演算子 x*y*z*... は、すべての引数を使ってこの関数を呼び出します。つまり、*(x, y, z, ...) です。デフォルトでは、左から順に (x*y) * z * ... を呼び出します。

2pi のような並置も *(2, pi) を呼び出します。この演算は、リテラル * よりも優先順位が高いことに注意してください。また、x で始まる名前の変数に整数の 0 を掛ける「0x...」の並置は禁止されています。符号なし整数リテラルと衝突するためです。0x01 isa UInt8

大きな数を乗算すると、デフォルトの Int を含む、ほとんどの整数型でオーバーフローが発生する可能性があります。

Examples

julia> 2 * 7 * 8
112

julia> *(2, 7, 8)
112

julia> [2 0; 0 3] * [1, 10]  # matrix * vector
2-element Vector{Int64}:
  2
 30

julia> 1/2pi, 1/2*pi  # juxtaposition has higher precedence
(0.15915494309189535, 1.5707963267948966)

julia> x = [1, 2]; x'x  # adjoint vector * vector
5

Base.:^ — Method
^(x, y)

べき乗演算子。

x と y が整数の場合、結果がオーバーフローすることがあります。科学表記で数値を入力するには、1.2 * 10^3 ではなく、Float64 リテラル（1.2e3 など）を使用してください。

y が Int リテラルの場合（たとえば、x^2 の 2 や、x^-3 の -3）、コンパイラは Julia コード x^y を Base.literal_pow(^, x, Val(y)) に変換し、指数の値に基づくコンパイル時特殊化を可能にします。（デフォルトのフォールバックとして Base.literal_pow(^, x, Val(y)) = ^(x,y) があり、通常は呼び出し側の名前空間で ^ が定義されていない限り、^ == Base.^ となります。）y が負の整数リテラルの場合、Base.literal_pow はデフォルトで演算を inv(x)^-y に変換します。このとき -y は正の値です。

exp2、<< も参照してください。

Examples

julia> 3^5
243

julia> 3^-1  # uses Base.literal_pow
0.3333333333333333

julia> p = -1;

julia> 3^p
ERROR: DomainError with -1:
Cannot raise an integer x to a negative power -1.
[...]

julia> 3.0^p
0.3333333333333333

julia> 10^19 > 0  # integer overflow
false

julia> big(10)^19 == 1e19
true

Base.div — Method
div(x, y, r::RoundingMode=RoundToZero)

ユークリッド（整数）除算による商です。x / yを、丸めモードrに従って整数に丸めて計算します。つまり、次の量を

round(x / y, r)

中間で丸めることなく計算します。

この関数の特殊なケースであるfldおよびcldも参照してください。

RoundFromZeroはJulia 1.9以降で利用できます。

Examples:

julia> div(4, 3, RoundToZero) # Matches div(4, 3)
1
julia> div(4, 3, RoundDown) # Matches fld(4, 3)
1
julia> div(4, 3, RoundUp) # Matches cld(4, 3)
2
julia> div(5, 2, RoundNearest)
2
julia> div(5, 2, RoundNearestTiesAway)
3
julia> div(-5, 2, RoundNearest)
-2
julia> div(-5, 2, RoundNearestTiesAway)
-3
julia> div(-5, 2, RoundNearestTiesUp)

julia> div(4, 3, RoundFromZero)

julia> div(-4, 3, RoundFromZero)
-2

div(x, y)は、浮動小数点数の真の値に基づいて厳密に正しい切り捨てを行うため、直感に反する結果になることがあります。たとえば、次のようになります。

julia> div(6.0, 0.1)

julia> 6.0 / 0.1

julia> 6.0 / big(0.1)

ここで起きているのは、0.1と表記される浮動小数点数の真の値が数値1/10よりわずかに大きい一方、6.0は数値6を正確に表しているということです。そのため、6.0 / 0.1の真の値は60よりわずかに小さくなります。除算ではこれが正確に60.0に丸められますが、div(6.0, 0.1, RoundToZero)は常に真の値を切り捨てるため、結果は59.0になります。

julia> x = 129 % BigInt

julia> typeof(x)

source
mod(x, y)
rem(x, y, RoundDown)

xをyで切り下げ除算したときの余り。つまり、xをyで割った余りであり、中間で丸めを行わずに計算した場合はx - y*fld(x,y)となる。

結果の符号は、isfinite(y)の場合、yと同じになり、絶対値はabs(y)より小さくなる（例外については下記の注を参照）。

Note

浮動小数点値に対して使用すると、厳密な結果をその型で表現できない場合があり、丸め誤差が生じることがあります。特に、厳密な結果がyに非常に近い場合、yに丸められることがあります。

関連項目: rem、div、fld、mod1、invmod。

julia> mod(8, 3)
2

julia> mod(9, 3)
0

julia> mod(8.9, 3)
2.9000000000000004

julia> mod(eps(), 3)
2.220446049250313e-16

julia> mod(-eps(), 3)
3.0

julia> mod.(-5:5, 3)'
1×11 adjoint(::Vector{Int64}) with eltype Int64:
 1  2  0  1  2  0  1  2  0  1  2

Base.rem — Method
rem(x, y, r::RoundingMode=RoundToZero)

x を y で整数除算したときの余りを、丸めモード r に従って商を丸めて計算します。つまり、次の量です。

x - y * round(x / y, r)

中間丸めは行いません。

  • r == RoundNearest の場合、結果は正確で、区間 $[-|y| / 2, |y| / 2]$ に含まれます。RoundNearest も参照してください。
  • r == RoundToZero（デフォルト）の場合、結果は正確で、x が正なら区間 $[0, |y|)$ に、そうでなければ区間 $(-|y|, 0]$ に含まれます。RoundToZero も参照してください。
  • r == RoundDown の場合、y が正なら区間 $[0, y)$ に、そうでなければ区間 $(y, 0]$ に含まれます。x と y の符号が異なり、かつ abs(x) < abs(y) の場合、結果は正確でないことがあります。RoundDown も参照してください。
  • r == RoundUp の場合、y が正なら区間 $(-y, 0]$ に、そうでなければ区間 $[0, -y)$ に含まれます。x と y の符号が同じで、かつ abs(x) < abs(y) の場合、結果は正確でないことがあります。RoundUp も参照してください。
  • r == RoundFromZero の場合、y が正なら区間 $(-y, 0]$ に、そうでなければ区間 $[0, -y)$ に含まれます。x と y の符号が同じで、かつ abs(x) < abs(y) の場合、結果は正確でないことがあります。RoundFromZero も参照してください。
Julia 1.9

RoundFromZero は Julia 1.9 以降が必要です。

Examples:

julia> x = 9; y = 4;

julia> x % y  # same as rem(x, y)
1

julia> x ÷ y  # same as div(x, y)
2

julia> x == div(x, y) * y + rem(x, y)
true

Base.Math.rem2pi — Function
rem2pi(x, r::RoundingMode)

xを2πで整数除算したときの余りを、商を丸めるモードrに従って計算します。つまり、次の量を

x - 2π*round(x/(2π),r)

中間で丸めることなく計算します。この計算では内部的に高精度の2π近似値を使用するため、rem(x,2π,r)よりも正確な結果が得られます。

  • r == RoundNearestの場合、結果は区間$[-π, π]$に含まれます。通常、これが最も正確な結果になります。RoundNearestも参照してください。
  • r == RoundToZeroの場合、xが正なら結果は区間$[0, 2π]$に、そうでなければ区間$[-2π, 0]$に含まれます。RoundToZeroも参照してください。
  • r == RoundDownの場合、結果は区間$[0, 2π]$に含まれます。RoundDownも参照してください。
  • r == RoundUpの場合、結果は区間$[-2π, 0]$に含まれます。RoundUpも参照してください。

Examples

julia> rem2pi(7pi/4, RoundNearest)
-0.7853981633974485

julia> rem2pi(7pi/4, RoundDown)
5.497787143782138
source
Base.Math.mod2pi — Function
mod2pi(x)

2πで割った余りを、$[0,2π)$の範囲で返します。

Base.range — Function
range(start, stop, length)
range(start, stop; length, step)
range(start; length, stop, step)

引数から、要素が等間隔に並び、効率的なストレージを使用する特殊な配列（AbstractRange）を構築します。数学的には、start、step、stop、lengthのうち任意の3つがあれば、範囲は一意に定まります。rangeの有効な呼び出し方は次のとおりです。

  • start、step、stop、lengthのうち任意の3つを指定して、rangeを呼び出します。
  • start、stop、lengthのうち2つを指定して、rangeを呼び出します。この場合、stepは正の1とみなされます。両方の引数が整数の場合は、UnitRangeが返されます。
  • stopまたはlengthのいずれかを指定して、rangeを呼び出します。startとstepは正の1とみなされます。

降順の範囲を構築するには、負のステップ幅を指定します。例：range(5, 1; step = -1) => [5,4,3,2,1]。それ以外の場合、stopの値がstartの値より小さく、stepの既定値が+1であれば、空の範囲が構築されます。空の範囲は、stopがstartより1小さくなるよう正規化されます。例：range(5, 1) == 5:4。

Base.:(==) — Function
==(x, y)

汎用の等価演算子です。=== にフォールバックします。インスタンスが表す抽象的な値に基づいて、等価性の概念を持つすべての型で実装する必要があります。たとえば、数値型は型を無視して数値としての値を比較し、文字列はエンコーディングを無視して文字の並びとして比較します。同じ型のコレクションでは、通常、キーの集合を比較します。キーの集合が == であれば、それぞれのキーに対応する値を比較し、すべての組が == の場合に true を返します。通常、正確な型など、その他のプロパティは考慮されません。

この演算子は浮動小数点数に対して IEEE のセマンティクスに従います。0.0 == -0.0 と NaN != NaN。

結果の型は Bool です。ただし、オペランドのいずれかが missing の場合は、missing が返されます（three-valued logic）。コレクションでは通常、all に似た三値論理を実装します。オペランドに missing 値が含まれていて、その他のすべての組が等しい場合は、missing を返します。常に Bool の結果を得るには、isequal または === を使用してください。

Implementation

新しい数値型では、その型の引数を2つ取るこの関数を実装し、可能であれば昇格規則を使って他の型との比較も処理する必要があります。

等価性とハッシュは密接に関係しています。isequal とみなされる2つの値は、同じ hash を持たなければなりません。また、デフォルトでは isequal は == にフォールバックします。型が == や isequal の動作をカスタマイズする場合は、hash も同様に実装し、isequal と hash が一致するようにする必要があります。Sets、Dicts をはじめ、多くの内部実装は、この不変条件が成り立つことを前提としています。

ある型が ==、isequal、isless を定義する場合は、比較の一貫性を保つために < も実装する必要があります。

Base.isapprox — Function
isapprox(x; kwargs...) / ≈(x; kwargs...)

引数を x と比較する関数を、≈ を使って作成します。つまり、y -> y ≈ x と同等の関数です。

ここでサポートされるキーワード引数は、2 引数の isapprox と同じです。

Julia 1.5

このメソッドを使用するには、Julia 1.5 以降が必要です。

source
isapprox(x, y; atol::Real=0, rtol::Real=atol>0 ? 0 : √eps, nans::Bool=false[, norm::Function])

近似等値比較。2つの数値は、相対距離 または 絶対距離が許容範囲内であれば等しいと判定されます。isapprox は、norm(x-y) <= max(atol, rtol*max(norm(x), norm(y))) の場合に true を返します。デフォルトの atol（絶対許容誤差）はゼロで、デフォルトの rtol（相対許容誤差）は、x と y の型によって決まります。キーワード引数 nans は、NaN 値を等しいとみなすかどうかを指定します（デフォルトは false）。

実数または複素数の浮動小数点値では、atol > 0 が指定されていない場合、rtol は、x または y のうち、より大きい（精度の低い）型の eps の平方根がデフォルトになります。これは、有効数字のおよそ半分が一致することを要求する設定に相当します。一方、整数の引数の場合や、atol > 0 が指定されている場合などは、rtol のデフォルトはゼロです。

キーワード norm のデフォルトは、数値の (x,y) では abs、配列では LinearAlgebra.norm です（別の norm を選ぶと便利な場合もあります）。x と y が配列で、norm(x-y) が有限でない（つまり ±Inf または NaN）場合、比較では、x と y のすべての要素が成分ごとに近似的に等しいかどうかを調べます。

二項演算子 ≈ は、デフォルト引数を指定した isapprox と同等であり、x ≉ y は !isapprox(x,y) と同等です。

なお、x ≈ 0（つまり、デフォルトの許容誤差でゼロと比較すること）は、デフォルトの atol が 0 であるため、x == 0 と同等です。このような場合は、適切な atol を指定する（または norm(x) ≤ atol を使う）か、コードの構成を変えてください（たとえば、x - y ≈ 0 ではなく x ≈ y を使います）。問題全体のスケーリング（「単位」）によって適切な値が異なるため、ゼロ以外の atol を自動的に選ぶことはできません。たとえば、x - y ≈ 0 では、x がメートル単位の radius of the Earth なら、atol=1e-9 は途方もなく小さい許容誤差ですが、x がメートル単位の radius of a Hydrogen atom なら、途方もなく大きい許容誤差になります。

Julia 1.6

数値（配列以外）の引数を比較する際に norm キーワード引数を渡すには、Julia 1.6 以降が必要です。

Examples

julia> isapprox(0.1, 0.15; atol=0.05)
true

julia> isapprox(0.1, 0.15; rtol=0.34)
true

julia> isapprox(0.1, 0.15; rtol=0.33)
false

julia> 0.1 + 1e-10 ≈ 0.1
true

julia> 1e-10 ≈ 0
false

julia> isapprox(1e-10, 0, atol=1e-8)
true

julia> isapprox([10.0^9, 1.0], [10.0^9, 2.0]) # using `norm`
true

Base.round — Function
round([T,] x, [r::RoundingMode])
round(x, [r::RoundingMode]; digits::Integer=0, base = 10)
round(x, [r::RoundingMode]; sigdigits::Integer, base = 10)

数値 x を丸めます。

キーワード引数を指定しない場合、x は整数値に丸められ、型 T の値を返します。ただし、T が指定されていない場合は、x と同じ型の値を返します。値を T で表現できない場合は、convert と同様に、InexactError がスローされます。

キーワード引数 digits を指定すると、基数 base で、小数点以下（digits が負の場合は小数点より前）の指定桁数に丸めます。

キーワード引数 sigdigits を指定すると、基数 base で、指定した有効桁数に丸めます。

RoundingMode r は丸めの方向を制御します。デフォルトは RoundNearest で、最も近い整数に丸めます。ちょうど中間の値（小数部が 0.5 の値）は、最も近い偶数の整数に丸められます。グローバルな丸めモードを変更すると、round が誤った結果を返す場合があることに注意してください（rounding を参照）。

浮動小数点型に丸める場合、真の整数ではなく、その型で表現可能な整数（および Inf）に丸めます。「最も近い値」を判定する際、Inf は floatmax(T) より 1 ulp 大きい値として扱われます。これは convert と同様です。

Examples

julia> round(1.7)
2.0

julia> round(Int, 1.7)
2

julia> round(1.5)
2.0

julia> round(2.5)
2.0

julia> round(pi; digits=2)
3.14

julia> round(pi; digits=3, base=2)
3.125

julia> round(123.456; sigdigits=2)
120.0

julia> round(357.913; sigdigits=4, base=2)
352.0

julia> round(Float16, typemax(UInt128))
Inf16

julia> floor(Float16, typemax(UInt128))
Float16(6.55e4)
Note

2 以外の基数で指定桁数に丸める場合、2 進浮動小数点数を扱うと正確に丸められないことがあります。たとえば、Float64 の値は 1.15 で表されますが、実際には 1.15 より 小さい 値です。それでも 1.2 に丸められます。例：

julia> x = 1.15
1.15

julia> big(1.15)
1.149999999999999911182158029987476766109466552734375

julia> x < 115//100
true

julia> round(x, digits=1)
1.2

Extensions

round を新しい数値型に拡張するには、通常、Base.round(x::NewType, r::RoundingMode) を定義するだけで十分です。

Base.invmod — Function
invmod(n::Integer, T) where {T <: Base.BitInteger}
invmod(n::T) where {T <: Base.BitInteger}

型 T の整数環において、n のモジュラー逆元を計算します。つまり、N = 8*sizeof(T) の場合、法は 2^N です（たとえば、Int32 の場合は N = 32）。言い換えると、これらのメソッドは次の恒等式を満たします。

n * invmod(n) == 1
(n * invmod(n, T)) % T == 1
(n % T) * invmod(n, T) == 1

ここで、* は整数環におけるモジュラー乗算、すなわち T であることに注意してください。n が偶数の場合、2^N と互いに素ではなく、逆元が存在しないため、エラーが発生します。

整数型が暗黙に定める法は、その型で表現できる範囲を超える大きさであるため、法を明示的な値として指定するのは不便なことがよくあります。

モジュラー逆元は、https://arxiv.org/pdf/2204.04342.pdf. で説明されているアルゴリズムを用いることで、一般の場合よりもはるかに効率よく計算されます。

Julia 1.11

invmod(n) および invmod(n, T) メソッドを使用するには、Julia 1.11 以降が必要です。

Customizable binary operators

Some unicode characters can be used to define new binary operators that support infix notation. For example ⊗(x,y) = kron(x,y) defines the ⊗ (otimes) function to be the Kronecker product, and one can call it as binary operator using infix syntax: C = A ⊗ B as well as with the usual prefix syntax C = ⊗(A,B).

Other characters that support such extensions include \odot ⊙ and \oplus ⊕
