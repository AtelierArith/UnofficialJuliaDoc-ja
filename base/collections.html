Iteration

逐次反復は、iterate 関数によって実装されています。一般的な for ループ:

for i in iter   # or  "for i = iter"
    # body
end

は、次のように変換されます。

next = iterate(iter)
while next !== nothing
    (i, state) = next
    # body
    next = iterate(iter, state)
end

state オブジェクトには任意のものを指定でき、反復可能な型ごとに適切なものを選ぶ必要があります。カスタムの反復可能な型の定義について詳しくは、manual section on the iteration interface を参照してください。

Base.iterate — Function
iterate(iter [, state])::Union{Nothing, Tuple{Any, Any}}

イテレーターを進めて次の要素を取得します。要素が残っていない場合は、nothingを返します。そうでない場合は、次の要素と新しい反復状態からなる2要素タプルを返します。

Base.IteratorSize — Type
IteratorSize(itertype::Type)::IteratorSize

イテレータの型を指定すると、次のいずれかの値を返します。

  • SizeUnknown() 要素数を事前に特定できない場合。
  • HasLength() 長さが有限かつ固定の場合。
  • HasShape{N}() 配列のように、長さが既知で多次元の形状を持つ場合。この場合、N は次元数を返し、イテレータに対して axes 関数が有効です。
  • IsInfinite() イテレータが値を無限に生成する場合。

この関数を定義していないイテレータのデフォルト値は HasLength() です。つまり、ほとんどのイテレータは length を実装しているものとみなされます。

この特性は一般に、結果の領域を事前に確保するアルゴリズムと、結果を段階的に拡張するアルゴリズムを選択するために使われます。

julia> Base.IteratorSize(1:5)
Base.HasShape{1}()

julia> Base.IteratorSize((2,3))
Base.HasLength()

Base.IteratorEltype — Type
IteratorEltype(itertype::Type)::IteratorEltype

イテレータの型を指定すると、次のいずれかの値を返します。

  • イテレータが生成する要素の型が事前にわからない場合は、EltypeUnknown()。

このトレイトは一般に、特定の型の結果を事前に確保するアルゴリズムと、生成された値の型に基づいて結果の型を選ぶアルゴリズムを切り替えるために使われます。

AbstractRange{T} <: AbstractVector{T}

要素の型が T である線形範囲のスーパータイプです。UnitRange、LinRange などの型は、この型のサブタイプです。

Base.OrdinalRange — Type
OrdinalRange{T, S} <: AbstractRange{T}

要素の型がTで、間隔の型がSである序数範囲のスーパータイプです。ステップ幅は常にoneunitの整数倍でなければならず、Tは、oneunitより小さい値を取れない「離散」型でなければなりません。たとえば、IntegerやDateの型は該当しますが、Float64は該当しません（この型はoneunit(Float64)より小さい値を表現できるためです）。UnitRange、StepRangeなどの型は、この型のサブタイプです。

Base.StepRange — Type

Base.isdone — Function
isdone(itr, [state])::Union{Bool, Missing}

この関数は、イテレーターの完了を高速に判定するためのヒントを提供します。これは、ユーザーに公開されない要素が消費されるのを避けたいステートフルなイテレーターに役立ちます（たとえば、isempty または zip で完了状態を確認する場合）。

この機能を利用するステートフルなイテレーターは、イテレーターが完了しているかどうかに応じて true または false を返す isdone メソッドを定義してください。ステートレスなイテレーターでは、この関数を実装する必要はありません。

結果が missing の場合、isdone ではイテレーターの状態が終端かどうかを判定できません。そのため、呼び出し側は確定的な答えを得るために iterate(itr, state) === nothing を計算する必要があります。

関連項目: iterate、isempty

source

Base.in — Function
in(item, collection)::Bool
∈(item, collection)::Bool

指定されたコレクションを反復して生成される値のいずれかに==かどうかを判定します。中置記法でも同様に使用できます。

item in collection
item ∈ collection

Boolの値を返します。ただし、itemがmissingである場合、またはcollectionにmissingが含まれ、itemは含まれない場合は、missingを返します（three-valued logic。anyおよび==と同じ動作です）。コレクションによっては、定義が少し異なります。たとえば、Setでは、項目がいずれかの要素にisequalかどうかを調べます。Dictではkey=>valueのペアを検索し、keyはisequalを使って比較します。

辞書にキーが存在するかどうかを調べるには、haskeyまたはk in keys(dict)を使用してください。上記のコレクションでは、結果は常にBoolです。

in.(items, collection)またはitems .∈ collectionでブロードキャストすると、itemsとcollectionの両方がブロードキャストされますが、これは意図した動作でないことがよくあります。たとえば、両方の引数がベクトルで（次元が一致している場合）、コレクションitemsの各値が、collectionの対応する位置にある値にinかどうかを示すベクトルが返されます。itemsの各値がcollectionに含まれるかどうかを示すベクトルを得るには、次のようにcollectionをタプルまたはRefで囲みます。in.(items, Ref(collection))またはitems .∈ Ref(collection)。

関連項目：∉、insorted、contains、occursin、issubset。

Examples

julia> a = 1:3:20
1:3:19

julia> 4 in a
true

julia> 5 in a
false

julia> missing in [1, 2]
missing

julia> 1 in [2, missing]
missing

julia> 1 in [1, missing]
true

julia> missing in Set([1, 2])
false

julia> (1=>missing) in Dict(1=>10, 2=>20)
missing

julia> [1, 2] .∈ [2, 3]
2-element BitVector:
 0
 0

julia> [1, 2] .∈ ([2, 3],)
2-element BitVector:
 0
 1
source

Base.allunique — Function
allunique(itr)::Bool
allunique(f, itr)::Bool

itr のすべての値が isequal と比較して互いに異なる場合は、true を返します。2つ目の方法では、[f(x) for x in itr] のすべての値が互いに異なる場合に返します。

allunique(f, itr) は、f を length(itr) 回より少なく呼び出すことがあります。呼び出し回数の正確な値は、実装の詳細とみなされます。

入力がソート済みの場合、allunique は専用の実装を使用することがあります。

関連項目: unique、issorted、allequal。

Julia 1.11

メソッド allunique(f, itr) を使用するには、Julia 1.11 以降が必要です。

Examples

julia> allunique([1, 2, 3])
true

julia> allunique([1, 2, 1, 2])
false

julia> allunique(Real[1, 1.0, 2])
false

Base.reduce — Method
reduce(op, itr; [init])

与えられたコレクション itr を、二項演算子 op で縮約します。初期値 init を指定する場合、それは op の単位元でなければならず、空のコレクションに対して返されます。空でないコレクションでは init が使われるかどうかは未規定です。

空のコレクションでは、init を指定する必要があります。ただし、いくつかの特殊なケース（たとえば、op が +、*、max、min、&、| のいずれかの場合）では、Julia が op の単位元を判定できます。

よく使われる演算子の一部には、専用の実装を持つ縮約関数があります。その場合は、次の関数を使ってください。maximum(itr)、minimum(itr)、sum(itr)、prod(itr)、any(itr)、all(itr)。配列の配列を効率よく連結するには、reduce(vcat, arr) または reduce(hcat, arr) を呼び出します。

縮約の結合順序は実装に依存します。そのため、- のような非結合演算は使用できません。reduce(-,[1,2,3]) が (1-2)-3 と 1-(2-3) のどちらとして評価されるかは未定義だからです。左結合または右結合を保証するには、代わりに foldl または foldr を使ってください。

演算によっては、誤差が累積します。縮約をグループ単位で実行できると、並列化が容易になります。Julia の将来のバージョンでは、アルゴリズムが変更される可能性があります。順序付きコレクションを使う場合、要素の順序は変更されません。

julia> reduce(*, Int[]; init=1)

Base.mapreduce — Method
mapreduce(f, op, itrs...; [init])

itrs の各要素に f を適用し、その結果を二項関数 op で畳み込みます。init を指定する場合、それは op の単位元でなければならず、空のコレクションに対して返されます。空でないコレクションで init が使われるかどうかは未規定です。一般に、空のコレクションを扱うには init を指定する必要があります。

mapreduce は reduce(op, map(f, itr); init=init) を呼び出すのと機能的に同等ですが、中間コレクションを作成する必要がないため、一般により高速に実行されます。reduce および map のドキュメントも参照してください。

Dictionaries

Dict は標準の辞書です。その実装では、キーのハッシュ関数として hash を、等価性の判定に isequal を使用します。ハッシュテーブルでのカスタム型の格納方法を変更するには、これら2つの関数を定義してください。

IdDict は、キーが常にオブジェクトの同一性である特殊なハッシュテーブルです。

WeakKeyDict は、キーとしてオブジェクトへの弱参照を使用するハッシュテーブルの実装です。そのため、ハッシュテーブルから参照されていても、オブジェクトはガベージコレクションの対象になることがあります。Dict と同様に、ハッシュには hash を、等価性の判定には isequal を使用します。一方、Dict とは異なり、挿入時にキーを変換しません。

Dict は、=> で構築したペアオブジェクトを Dict コンストラクターに渡すことで作成できます: Dict("A"=>1, "B"=>2)。この呼び出しでは、キーと値から型情報を推論しようとします（つまり、この例では Dict{String, Int64} が作成されます）。型を明示的に指定するには、Dict{KeyType,ValueType}(...) の構文を使用します。たとえば、Dict{String,Int32}("A"=>1, "B"=>2) のようにします。

辞書はジェネレーターを使って作成することもできます。たとえば、Dict(i => f(i) for i = 1:10) のようにします。

辞書 D に対して、構文 D[x] は、キー x の値を返します（キーが存在する場合）。存在しない場合はエラーをスローします。また、D[x] = y は、キーと値のペア x => y を D に格納します（キー x に既存の値があれば置き換えます）。D[...] に複数の引数を渡すと、それらはタプルに変換されます。たとえば、構文 D[x,y] は D[(x,y)] と同等であり、タプル (x,y) をキーとする値を参照します。

Base.sizehint! — Function
sizehint!(s, n; first::Bool=false, shrink::Bool=true) -> s

コレクション s に、少なくとも n 個の要素を格納できる容量を確保します。つまり、s に多数の値を追加する予定がある場合、あらかじめ一度に容量を確保しておけば、段階的な再割り当てのコストを避けられ、パフォーマンスが向上することがあります。

first が true の場合、追加の領域はコレクションの先頭より前に確保されます。これにより、後続の pushfirst! の呼び出しは、push! の呼び出しより高速になることがあります。このキーワードを指定すると、コレクションが順序付けられていない場合や、このコレクションで pushfirst! がサポートされていない場合にエラーになることがあります。

shrink=true（デフォルト）の場合、現在の容量が n より大きければ、コレクションの容量が縮小されることがあります。

resize! も参照してください。

Notes on the performance model

sizehint! をサポートする型では、次のようになります。

  1. push! メソッドと append! メソッドは、一般に追加の領域を事前確保することがあります（必須ではありません）。Base で実装された型では、通常、汎用的な用途に最適化されたヒューリスティックを使って事前確保します。
  2. sizehint! で、この事前確保を制御できることがあります。Base の型では、通常、この方法で制御できます。
  3. この種の事前確保をサポートする型では、empty! のコストはほぼゼロ（O(1)）です。
Julia 1.11

shrink 引数と first 引数は、Julia 1.11 で追加されました。
