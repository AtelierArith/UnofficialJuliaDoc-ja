Core.nothing — Constant
nothing

値を返さない場合（C の void 関数など）や、変数またはフィールドに値がない場合に、慣例として使用される Nothing 型のシングルトンインスタンス。

nothing を返しても、REPL などの対話型環境には表示されません。

関連項目: isnothing、something、missing。

Base.DEPOT_PATH — Constant
DEPOT_PATH

パッケージマネージャーや Julia のコード読み込み機構が、パッケージレジストリ、インストール済みパッケージ、名前付き環境、リポジトリのクローン、コンパイル済みパッケージイメージのキャッシュ、設定ファイルを探すための「デポ」ディレクトリのスタック。デフォルトでは、次の場所が含まれます。

  1. ~/.julia（システムに応じたユーザーのホームディレクトリが ~ にあたります）;
  2. アーキテクチャ固有の共有システムディレクトリ（例: /usr/local/share/julia）;
  3. アーキテクチャに依存しない共有システムディレクトリ（例: /usr/share/julia）。

したがって、DEPOT_PATH は次のようになります。

[joinpath(homedir(), ".julia"), "/usr/local/share/julia", "/usr/share/julia"]

最初のエントリは「ユーザーデポ」であり、現在のユーザーが所有し、書き込み可能である必要があります。ユーザーデポには、レジストリのクローン、新しいパッケージバージョンのインストール、名前付き環境の作成と更新、パッケージリポジトリのクローン、新たにコンパイルされたパッケージイメージファイルの保存、ログファイルの書き込み、開発用パッケージのデフォルトでのチェックアウト、グローバル設定データの保存が行われます。デポパスの後続のエントリは読み取り専用として扱われ、システム管理者がインストールおよび管理するレジストリやパッケージなどに適しています。

DEPOT_PATH は、JULIA_DEPOT_PATH 環境変数が設定されている場合、その値に基づいて設定されます。

DEPOT_PATH contents

DEPOT_PATH の各エントリは、Julia がさまざまな用途に使うサブディレクトリを含むディレクトリへのパスです。デポ内に存在する可能性のあるサブディレクトリの概要を以下に示します。

  • artifacts: パッケージが使用するコンテンツを格納します。インストールは Pkg が管理します。
  • clones: パッケージリポジトリの完全なクローンを格納します。Pkg.jl が管理し、キャッシュとして使用します。
  • config: startup.jl など、Julia レベルの設定を格納します。
  • compiled: パッケージのプリコンパイル済み *.ji ファイルを格納します。Julia が管理します。
  • dev: Pkg.develop のデフォルトディレクトリです。Pkg.jl とユーザーが管理します。
  • environments: デフォルトのパッケージ環境を格納します。たとえば、特定の Julia バージョン用のグローバル環境などです。Pkg.jl が管理します。
  • logs: Pkg および REPL の操作ログを格納します。Pkg.jl と Julia が管理します。
  • packages: 明示的にインストールされたものと、暗黙的な依存関係であるものを含むパッケージを格納します。Pkg.jl が管理します。
  • registries: パッケージレジストリを格納します。デフォルトでは General のみです。Pkg.jl が管理します。
  • scratchspaces: パッケージ自身が Scratch.jl パッケージを介してインストールするコンテンツを格納します。Pkg.gc() は、未使用であることが確認されたコンテンツを削除します。
Note

コンテンツを保存するパッケージは、デポのルートに新しいサブディレクトリを作成するのではなく、Scratch.jl を介して scratchspaces サブディレクトリを使用してください。

JULIA_DEPOT_PATH および Code Loading も参照してください。

source
Base.LOAD_PATH — Constant
LOAD_PATH

コードの読み込み時に、プロジェクト環境またはパッケージディレクトリとして扱う using 文と import 文のパスを格納する配列です。JULIA_LOAD_PATH 環境変数が設定されている場合はその値に基づいて設定され、設定されていない場合は ["@", "@v#.#", "@stdlib"] が既定値になります。@ で始まる項目には、次の特別な意味があります。

  • @ は「現在アクティブな環境」を指します。その初期値は、JULIA_PROJECT 環境変数または --project コマンドラインオプションによって決まります。
  • @stdlib は、現在の Julia インストールにおける標準ライブラリディレクトリの絶対パスに展開されます。
  • @name は名前付き環境を指します。名前付き環境はデポ（JULIA_DEPOT_PATH を参照）の environments サブディレクトリに保存されます。ユーザーの名前付き環境は ~/.julia/environments に保存されるため、@name は、~/.julia/environments/name に存在し、Project.toml ファイルを含む環境を指します。name に # 文字が含まれている場合、その文字は Julia のバージョン番号のメジャー、マイナー、パッチの各要素に置き換えられます。たとえば、Julia 1.2 を実行している場合、@v#.# は @v1.2 に展開され、その名前の環境が検索されます。通常は ~/.julia/environments/v1.2 にあります。

プロジェクトやパッケージの検索に使われる LOAD_PATH の展開後の値は、Base.load_path() 関数を呼び出すと確認できます。

JULIA_LOAD_PATH、JULIA_PROJECT、JULIA_DEPOT_PATH、Code Loading も参照してください。

Base.Sys.CPU_THREADS — Constant
Sys.CPU_THREADS::Int

システムで利用可能な論理 CPU コアの数、つまり CPU が同時に実行できるスレッド数です。たとえば hyper-threading がある場合など、CPU コア数と一致するとは限りません。

物理コア数など、より詳しい情報については Hwloc.jl または CpuId.jl を参照してください。

関連項目: cgroup の制限を考慮した、コンテナ対応の CPU 数については Sys.EFFECTIVE_CPU_THREADS を参照してください。

source
Base.Sys.EFFECTIVE_CPU_THREADS — Constant
Sys.EFFECTIVE_CPU_THREADS::Int

コンテナの制限（Docker --cpus、Kubernetes の CPU 制限、cgroup のクォータなど）を考慮した、Julia プロセスが利用できる論理 CPU コア数です。ハードウェアの CPU スレッド数と、適用されている CPU 制限のうち、小さい方の値になります。

コンテナ化されていない環境では、通常 Sys.CPU_THREADS と同じ値になります。コンテナ化された環境では cgroup の CPU 制限が反映されるため、利用可能な並列処理能力をより正確に把握できます。

コンテナ環境で適切に動作するよう、デフォルトのスレッドプールサイズや並列度を決める際に、この定数を使用してください。
