inertia(B::BunchKaufman; atol::Real=0, rtol::Real=atol>0 ? 0 : n*ϵ) ->     np::Union{Nothing,Integer}, nn::Union{Nothing,Integer}, nz::Integer

`inertia` は、Bunch-Kaufman アルゴリズムで分解された実対称行列またはエルミート行列 `B` の数値的な慣性（正、負、ゼロの固有値の数。それぞれ `np`、`nn`、`nz` で表されます）を計算します。複素対称行列では慣性は定義されません。その場合、`np` と `nn` は `nothing` に設定されますが、この関数はゼロ固有値の数を返します。慣性は、`B.D` の固有値の符号を数えて計算します。ゼロ固有値の数は、複素 1 ノルム（`|re(.)|+|im(.)|` と定義）で `max(atol, rtol*s₁)` 以下となる、推定固有値の数として計算されます。ここで、`s₁` は `B.D` の最大特異値の上界であり、`σ₁`（より具体的には、実行列では `0.5*s₁ <= σ₁ <= s₁`、複素行列では `0.35*s₁ <= σ₁ <= s₁`）です。`atol` と `rtol` は、それぞれ絶対許容誤差と相対許容誤差です。相対許容誤差の既定値は `n*ϵ` です。ここで、`n` は `A` のサイズ、`ϵ` は `A` の数値型が `AbstractFloat` のサブタイプである場合の、その型の [`eps`](@ref) です。それ以外の場合（たとえば、`A` の数値型が `Rational` の場合）、`ϵ` は `0` に設定されます。

!!! note
    数値的な慣性は、固有値の大きさが許容誤差のしきい値 `max(atol, rtol*s₁)` に近い、悪条件行列に対しては、結果が不安定で精度の低い特性評価となることがあります。このような場合、Bunch-Kaufman 計算や行列にわずかな摂動が加わるだけで、1 つ以上の固有値がしきい値をまたぎ、`rank` の結果が変わることがあります。こうした変動は、Julia のバージョン、アーキテクチャ、コンパイラ、オペレーティングシステムの違いによる浮動小数点誤差の変化だけでも起こり得ます。特に、三角因子の要素の大きさは対角因子の固有値のスケールに直接影響するため、慣性を計算する場合は rook ピボット選択を使用することを強く推奨します。一方、行列の要素が有理数であれば、基礎となる整数型でオーバーフローやアンダーフローが発生しない限り（そのような場合は Julia 自体がエラーをスローします）、または正の許容誤差（絶対または相対）が指定されていれば、慣性の計算は厳密に行われることが保証されます。
