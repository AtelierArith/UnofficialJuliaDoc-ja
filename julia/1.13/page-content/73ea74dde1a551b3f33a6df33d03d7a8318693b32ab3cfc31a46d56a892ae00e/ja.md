# Noteworthy Differences from other Languages

## Noteworthy differences from MATLAB

MATLABユーザーにはJuliaの構文がなじみ深く感じられるかもしれませんが、JuliaはMATLABのクローンではありません。構文にも機能にも大きな違いがあります。MATLABに慣れたJuliaユーザーが戸惑う可能性のある主な違いを以下に示します。

  * Juliaの配列は角括弧でインデックス指定します。`A[i,j]`。
  * Juliaでは、配列を別の変数に代入してもコピーされません。`A = B`の後に`B`の要素を変更すると、`A`も変更されます。これを避けるには、`A = copy(B)`を使います。
  * Juliaでは、関数に値を渡してもコピーされません。関数が配列を変更すると、その変更は呼び出し元からも見えます。
  * Juliaでは、代入文によって配列が自動的に拡張されることはありません。MATLABでは`a(4) = 3.2`で配列`a = [0 0 0 3.2]`を作成し、`a(5) = 7`で`a = [0 0 0 3.2 7]`に拡張できます。一方、Juliaで対応する`a[5] = 7`を実行すると、`a`の長さが5未満の場合、またはこの文が識別子`a`の初回使用である場合にエラーになります。Juliaには[`push!`](@ref)と[`append!`](@ref)があり、MATLABの`a(end+1) = val`よりも効率よく`Vector`を拡張できます。
  * 虚数単位`sqrt(-1)`は、Juliaでは[`im`](@ref)で表します。MATLABのように`i`や`j`とはしません。
  * Juliaでは、小数点のない数値リテラル（たとえば`42`）は浮動小数点数ではなく整数になります。そのため、浮動小数点数を想定する演算の中には、定義域エラーを投げるものがあります。たとえば`julia> a = -1; 2^a`は、結果が整数ではないため定義域エラーになります（詳しくは[the FAQ entry on domain errors](@ref faq-domain-errors)を参照）。
  * Juliaでは、複数の値はタプルとして返され、タプルに代入されます。たとえば`(a, b) = (1, 2)`や`a, b = 1, 2`のように書きます。返り値の数に応じて任意の処理を行うためにMATLABでよく使われる`nargout`は、Juliaにはありません。同様の機能は、オプション引数やキーワード引数で実現できます。
  * Juliaには真の1次元配列があります。列ベクトルのサイズは`N`であり、`Nx1`ではありません。たとえば[`rand(N)`](@ref)は1次元配列を作成します。
  * Juliaでは、`[x,y,z]`は常に、`x`、`y`、`z`を含む3要素の配列を作成します。

      * 第1（「垂直」）次元に連結するには、[`vcat(x,y,z)`](@ref)を使うか、セミコロンで区切ります（`[x; y; z]`）。
      * 第2（「水平」）次元に連結するには、[`hcat(x,y,z)`](@ref)を使うか、空白で区切ります（`[x y z]`）。
      * ブロック行列（第1・第2次元への連結）を作るには、[`hvcat`](@ref)を使うか、空白とセミコロンを組み合わせます（`[a b; c d]`）。
  * Juliaでは、`a:b`と`a:b:c`は`AbstractRange`オブジェクトを作成します。MATLABのような通常のベクトルを作るには、[`collect(a:b)`](@ref)を使います。ただし、一般には`collect`を呼び出す必要はありません。`AbstractRange`オブジェクトは多くの場合、通常の配列と同じように使えますが、値を遅延計算するため、より効率的です。完全な配列ではなく、こうした特殊なオブジェクトを作るパターンはよく使われており、[`range`](@ref)などの関数や、`enumerate`、`zip`などのイテレーターにも見られます。これらの特殊なオブジェクトの多くは、通常の配列と同じように使えます。
  * Juliaの関数は、関数定義で返す変数名を列挙するのではなく、最後の式の値、または`return`キーワードで値を返します（詳しくは[The return Keyword](@ref)を参照）。
  * Juliaのスクリプトには任意の数の関数を含められ、ファイルを読み込むとすべての定義が外部から参照可能になります。現在の作業ディレクトリ外にあるファイルからも関数定義を読み込めます。
  * Juliaでは、[`sum`](@ref)、[`prod`](@ref)、[`maximum`](@ref)などの縮約関数は、`sum(A)`のように引数を1つだけ指定すると、`A`が多次元配列であっても、配列のすべての要素に対して処理を行います。
  * Juliaでは、引数が0個の関数を呼び出す場合も、[`rand()`](@ref)のように括弧が必要です。
  * Juliaでは、文末のセミコロンの使用は推奨されません。文の結果は自動的には表示されず（対話プロンプトを除く）、コード行をセミコロンで終える必要もありません。特定の出力を表示するには、[`println`](@ref)または[`@printf`](@ref)を使います。
  * Juliaでは、`A`と`B`が配列の場合、`A == B`のような論理比較演算は真偽値の配列を返しません。代わりに`A .== B`を使います。他の論理演算子である[`<`](@ref)や[`>`](@ref)についても同様です。
  * Juliaでスカラー値を返す関数を配列の各要素に適用するには、`f(A)`ではなく、ブロードキャスト構文`f.(A)`を使います。どちらの演算も定義されていても、意味が異なる場合があります。MATLABでは`exp(A)`は要素ごとの演算で、`expm(A)`は[matrix exponential](https://en.wikipedia.org/wiki/Matrix_exponential)ですが、Juliaでは`exp.(A)`が要素ごとの演算で、`exp(A)`は行列指数関数です。
  * Juliaの演算子[`&`](@ref)、[`|`](@ref)、[`⊻`](@ref xor)（[`xor`](@ref)）は、MATLABの`and`、`or`、`xor`に相当するビット演算を行います。優先順位はCではなくPythonのビット演算子に近いものです。配列に対して論理演算（MATLABの`&`や`|`の一般的な使い方など）を行うには、Juliaの短絡評価演算子`.&&`と`.||`をブロードキャストします。たとえば、配列`A`の要素が1または2と等しいかを調べるには、`A .== 1 .|| A .== 2`を使います。
  * Juliaでは、コレクションの要素をスプラット演算子`...`で関数の引数として渡せます。たとえば`xs=[1,2]; f(xs...)`のように書きます。
  * Juliaの[`svd`](@ref)は、特異値を密な対角行列ではなくベクトルとして返します。
  * Juliaでは、コード行を継続するために`...`を使いません。式が未完了であれば、自動的に次の行へ続きます。
  * JuliaとMATLABのどちらでも、対話セッションで最後に実行した式の値が変数`ans`に設定されます。ただしJuliaでは、MATLABと異なり、非対話モードでコードを実行した場合、`ans`は設定されません。
  * Juliaの`struct`は、MATLABの`class`と異なり、実行時にフィールドを動的に追加できません。代わりに[`Dict`](@ref)を使います。JuliaのDictには順序がありません。
  * Juliaでは各モジュールが独自のグローバルスコープ／名前空間を持ちますが、MATLABのグローバルスコープは1つだけです。
  * MATLABでは、不要な値を取り除く慣用的な方法として、`x(x>3)`のような論理インデックス指定や、`x(x>3) = []`のように`x`をインプレースで変更する方法があります。一方、Juliaには高階関数[`filter`](@ref)と[`filter!`](@ref)があり、対応する直訳的な書き方`x[x.>3]`と`x = x[x.>3]`の代わりに、`filter(z->z>3, x)`や`filter!(z->z>3, x)`と書けます。[`filter!`](@ref)を使うと、一時配列の使用を減らせます。
  * 前項に関連して、行列の全要素にしきい値処理を行うなど、特定の条件を満たす値を置き換える処理は、MATLABでは次のように書けます。`A(A < threshold) = 0`。Juliaでの対応する書き方は`A[A .< threshold] .= 0`です。
  * MATLABで`vertcat(A{:})`のようにセル配列の全要素を取り出す（「参照解除」する）操作は、Juliaではスプラット演算子を使って、たとえば`vcat(A...)`のように書きます。
  * Juliaの`adjoint`関数は共役転置を行います。一方、MATLABの`adjoint`は「随伴行列」または古典的随伴行列を返します。これは余因子行列の転置です。
  * Juliaではa^b^cはa^(b^c)として評価されますが、MATLABでは(a^b)^cとして評価されます。

## Noteworthy differences from R

Juliaの目標の1つは、データ分析や統計プログラミングに適した言語を提供することです。RからJuliaに移行するユーザーが知っておくとよい主な違いを以下に示します。

  * Juliaでは、シングルクォートで囲むのは文字であり、文字列ではありません。
  * Juliaでは、文字列をインデックス指定して部分文字列を作成できます。Rでは、部分文字列を作る前に文字列を文字ベクトルに変換する必要があります。
  * Juliaでは、Pythonと同様に、Rとは異なり、三重引用符`""" ... """`で文字列を作成できます。改行を含む文字列を作るのに便利な構文です。
  * Juliaでは、可変長引数はスプラット演算子`...`で指定します。この演算子は必ず特定の変数名の後に置きます。一方、Rでは`...`を単独で使えます。
  * Juliaでは剰余は`mod(a, b)`であり、`a %% b`ではありません。Juliaの`%`は剰余演算子です。
  * Juliaでは角括弧を使ってベクトルを作ります。Juliaの`[1, 2, 3]`は、Rの`c(1, 2, 3)`に相当します。
  * Juliaでは、すべてのデータ構造が論理インデックス指定に対応しているわけではありません。また、論理インデックス指定が使えるのは、インデックス対象と同じ長さのベクトルに限られます。たとえば次のとおりです。

      * Rでは、`c(1, 2, 3, 4)[c(TRUE, FALSE)]`は`c(1, 3)`に相当します。
      * Rでは、`c(1, 2, 3, 4)[c(TRUE, FALSE, TRUE, FALSE)]`は`c(1, 3)`に相当します。
      * Juliaでは、`[1, 2, 3, 4][[true, false]]`は[`BoundsError`](@ref)を投げます。
      * Juliaでは、`[1, 2, 3, 4][[true, false, true, false]]`は`[1, 3]`を生成します。
  * 多くの言語と同様、Juliaでは長さの異なるベクトルに対する演算が常に許されるわけではありません。ベクトルのインデックス範囲が共通していればよいRとは異なります。たとえば`c(1, 2, 3, 4) + c(1, 2)`はRでは有効ですが、Juliaで対応する`[1, 2, 3, 4] + [1, 2]`はエラーになります。
  * Juliaでは、コードの意味が変わらない場合、末尾にカンマを付けられます。配列のインデックス指定では、これがRユーザーの混乱を招くことがあります。たとえばRの`x[1,]`は行列の第1行を返しますが、Juliaではカンマが無視されるため、`x[1,] == x[1]`は第1要素を返します。行を取り出すには、`x[1,:]`のように`:`を使ってください。
  * Juliaの[`map`](@ref)は、引数より先に関数を取ります。Rの`lapply(<structure>, function, ...)`とは順序が逆です。同様に、Rの`apply(X, MARGIN, FUN, ...)`に相当するJuliaの関数は[`mapslices`](@ref)で、関数が第1引数になります。
  * Rの多変量apply（たとえば`mapply(choose, 11:13, 1:3)`）は、Juliaでは`broadcast(binomial, 11:13, 1:3)`と書けます。同様に、Juliaには関数をベクトル化する短いドット構文`binomial.(11:13, 1:3)`もあります。
  * Juliaでは、条件ブロック（`if`など）、ループブロック（`while`／`for`など）、関数の終わりを示すのに`end`を使います。1行で書く`if ( cond ) statement`の代わりに、`if cond; statement; end`、`cond && statement`、`!cond || statement`の形式で文を書けます。後者2つの構文で代入文を使う場合は、`cond && (x = value)`のように、明示的に括弧で囲む必要があります。
  * Juliaでは、`<-`、`<<-`、`->`は代入演算子ではありません。
  * Juliaの`->`は無名関数を作成します。
  * Juliaの[`*`](@ref)演算子は、Rとは異なり、行列積を計算できます。`A`と`B`が行列の場合、Juliaの`A * B`は行列積を表し、Rの`A %*% B`に相当します。Rでは同じ表記が要素ごとの積（アダマール積）を表します。要素ごとの積をJuliaで行うには、`A .* B`と書きます。
  * Juliaでは、`transpose`関数で行列を転置し、`'`演算子または`adjoint`関数で共役転置します。したがって、Juliaの`transpose(A)`はRの`t(A)`に相当します。また、Juliaには再帰しない転置を行う`permutedims`関数もあります。
  * Juliaでは、`if`文や`for`／`while`ループを書くときに括弧は不要です。`for (i in c(1, 2, 3))`ではなく`for i in [1, 2, 3]`を、`if (i == 1)`ではなく`if i == 1`を使います。
  * Juliaでは、`0`と`1`は真偽値として扱われません。Juliaでは`if (1)`とは書けません。`if`文が真偽値だけを受け付けるためです。代わりに`if true`、`if Bool(1)`、または`if 1==1`と書けます。
  * Juliaには`nrow`と`ncol`はありません。代わりに、`nrow(M)`には`size(M, 1)`を、`ncol(M)`には`size(M, 2)`を使います。
  * Juliaではスカラー、ベクトル、行列を明確に区別します。Rでは`1`と`c(1)`は同じですが、Juliaでは相互に置き換えて使えません。
  * Juliaの[`diag`](@ref)と[`diagm`](@ref)は、Rの同名のものとは異なります。
  * Juliaでは、関数呼び出しの結果を代入演算の左辺に指定できません。つまり、`diag(M) = fill(1, n)`とは書けません。
  * Juliaでは、メインの名前空間に関数を詰め込むことは推奨されません。Juliaの統計機能の多くは、[JuliaStats organization](https://github.com/JuliaStats)の下にある[packages](https://pkg.julialang.org/)で提供されています。たとえば次のとおりです。

      * 確率分布に関する関数は[Distributions package](https://github.com/JuliaStats/Distributions.jl)が提供します。
      * データフレームは[DataFrames package](https://github.com/JuliaData/DataFrames.jl)が提供します。
      * 一般化線形モデルは[GLM package](https://github.com/JuliaStats/GLM.jl)が提供します。
  * Juliaにはタプルと本格的なハッシュテーブルがありますが、R形式のリストはありません。複数の項目を返す場合は、通常、タプルまたは名前付きタプルを使います。`list(a = 1, b = 2)`の代わりに、`(1, 2)`または`(a=1, b=2)`を使います。
  * Juliaでは、RのS3やS4オブジェクトより扱いやすい独自の型を定義することが推奨されています。Juliaの多重ディスパッチにより、`table(x::TypeA)`と`table(x::TypeB)`は、Rの`table.TypeA(x)`と`table.TypeB(x)`のように機能します。
  * Juliaでは、値を代入したり関数に渡したりしてもコピーされません。関数が配列を変更すると、その変更は呼び出し元からも見えます。これはRとは大きく異なり、新しい関数が大きなデータ構造をより効率的に処理できる理由でもあります。
  * Juliaでは、ベクトルや行列の連結に[`hcat`](@ref)、[`vcat`](@ref)、[`hvcat`](@ref)を使います。Rのように`c`、`rbind`、`cbind`は使いません。
  * Juliaでは、`a:b`のような範囲は、Rのようなベクトルの略記ではなく、反復処理に使う特殊な`AbstractRange`オブジェクトです。範囲をベクトルに変換するには[`collect(a:b)`](@ref)を使います。
  * `:`演算子の優先順位は、RとJuliaで異なります。特にJuliaでは算術演算子の優先順位が`:`演算子より高いのに対し、Rでは逆です。たとえばJuliaの`1:n-1`は、Rの`1:(n-1)`に相当します。
  * Juliaの[`max`](@ref)と[`min`](@ref)は、それぞれRの`pmax`と`pmin`に相当しますが、両方の引数の次元が同じでなければなりません。[`maximum`](@ref)と[`minimum`](@ref)はRの`max`と`min`に代わるものですが、重要な違いがあります。
  * Juliaの[`sum`](@ref)、[`prod`](@ref)、[`maximum`](@ref)、[`minimum`](@ref)は、Rの対応する関数とは異なります。いずれも、演算対象の次元を指定する省略可能なキーワード引数`dims`を受け取ります。たとえば、Juliaの`A = [1 2; 3 4]`とRの`B <- rbind(c(1,2),c(3,4))`が同じ行列だとします。このとき、`sum(A)`は`sum(B)`と同じ結果になります。一方、`sum(A, dims=1)`は各列の合計を含む行ベクトルを、`sum(A, dims=2)`は各行の合計を含む列ベクトルを返します。これは、別々の`colSums(B)`関数と`rowSums(B)`関数で同様の処理を行うRとは異なります。`dims`キーワード引数がベクトルの場合、合計を計算するすべての次元を指定し、合計後の配列の次元は保持します。たとえば`sum(A, dims=(1,2)) == hcat(10)`のようにします。なお、第2引数のエラーチェックは行われません。
  * Juliaには、引数を変更する関数がいくつかあります。たとえば[`sort`](@ref)と[`sort!`](@ref)の両方があります。
  * Rでは性能のためにベクトル化が必要ですが、Juliaではほぼ逆です。ベクトル化を避けたループを使うほうが、高速なコードになることがよくあります。
  * Juliaは先行評価を行い、R形式の遅延評価には対応していません。多くのユーザーにとって、引用符で囲まない式や列名を使う場面が非常に少ないことを意味します。
  * Juliaは`NULL`型に対応していません。最も近いのは[`nothing`](@ref)ですが、リストではなくスカラー値のように振る舞います。`is.null(x)`の代わりに`x === nothing`を使います。
  * Juliaでは、欠損値は`NA`ではなく[`missing`](@ref)オブジェクトで表します。`is.na(x)`の代わりに[`ismissing(x)`](@ref)を使います（ベクトルの要素ごとの演算には`ismissing.(x)`を使います）。通常は`na.rm=TRUE`ではなく[`skipmissing`](@ref)関数を使います（ただし、特定のケースでは`skipmissing`引数を取る関数もあります）。
  * Juliaには、Rの`assign`や`get`に相当するものはありません。
  * Juliaでは、`return`に括弧は不要です。
  * Rでは、不要な値を取り除く慣用的な方法として、`x[x>3]`のような論理インデックス指定や、`x = x[x>3]`のように`x`をインプレースで変更する方法があります。一方、Juliaには高階関数[`filter`](@ref)と[`filter!`](@ref)があり、対応する直訳的な書き方`x[x.>3]`と`x = x[x.>3]`の代わりに、`filter(z->z>3, x)`や`filter!(z->z>3, x)`と書けます。[`filter!`](@ref)を使うと、一時配列の使用を減らせます。

## Noteworthy differences from Python

  * Juliaでは、`for`、`if`、`while`などのブロックは、`end`キーワードで終わります。Pythonとは異なり、インデントの深さは意味を持ちません。また、JuliaにはPythonの`pass`キーワードに相当するものはありません。
  * Juliaでは文字列を二重引用符（`"text"`）で囲みます（複数行文字列では二重引用符を3つ使います）。Pythonでは一重引用符（`'text'`）または二重引用符（`"text"`）のどちらでも囲めます。Juliaでは一重引用符は文字に使います（`'c'`）。
  * Juliaでは文字列の連結に`*`を使います。Pythonのように`+`は使いません。同様に、文字列の反復には`^`を使い、`*`は使いません。Pythonのように文字列リテラルを暗黙に連結すること（たとえば`'ab' 'cd' == 'abcd'`）は、Juliaでは行われません。
  * 柔軟ですが低速なPythonのリストは、Juliaの`Vector{Any}`型、またはより一般には、`T`が具体型でない要素型である`Vector{T}`に相当します。要素をインプレースに格納するNumPy配列のような「高速」配列（つまり、`dtype`が`np.float64`、`[('f1', np.uint64), ('f2', np.int32)]`など）は、`T`が具体的な不変要素型である`Array{T}`で表せます。これには`Float64`、`Int32`、`Int64`などの組み込み型だけでなく、`Tuple{UInt64,Float64}`のような複雑な型や、多くのユーザー定義型も含まれます。
  * Juliaでは、配列や文字列などのインデックスは1始まりであり、0始まりではありません。
  * Juliaのスライスによるインデックス指定では、最後の要素も含まれます。Juliaの`a[2:3]`は、Pythonの`a[1:3]`に相当します。
  * Pythonとは異なり、Juliaでは[AbstractArrays with arbitrary indexes](https://julialang.org/blog/2017/04/offset-arrays/)が可能です。Pythonで負のインデックスに特別な意味を持たせる`a[-1]`と`a[-2]`は、Juliaでは`a[end]`と`a[end-1]`と書きます。
  * Juliaで最後の要素までをインデックス指定するには、`end`が必要です。Juliaの`x[2:end]`は、Pythonの`x[1:]`に相当します。
  * Juliaでは、任意のオブジェクトの前に`:`を置くと、[`Symbol`](@ref)を作成するか、式を*クォート*します。そのため、`x[:5]`は`x[5]`と同じです。配列の先頭から`n`個の要素を取得するには、範囲によるインデックス指定を使います。
  * Juliaの範囲インデックス指定は`x[start:step:stop]`の形式ですが、Pythonでは`x[start:(stop+1):step]`の形式です。したがって、Pythonの`x[0:10:2]`はJuliaの`x[1:2:10]`に相当します。同様に、逆順の配列を表すPythonの`x[::-1]`は、Juliaの`x[end:-1:1]`に相当します。
  * Juliaでは、配列のインデックス指定と同じ構文を使って、`start:step:stop`のように範囲を単独で作成できます。`range`関数も使えます。
  * Juliaでは、`X[[1,2], [1,3]]`のように配列で行列をインデックス指定すると、第1・第2行と第1・第3列の交点を含む部分行列を参照します。Pythonの`X[[1,2], [1,3]]`は、行列のセル`[1,1]`と`[2,3]`の値を含むベクトルを参照します。Juliaの`X[[1,2], [1,3]]`はPythonの`X[np.ix_([0,1],[0,2])]`に相当し、Pythonの`X[[0,1], [0,2]]`はJuliaの`X[[CartesianIndex(1,1), CartesianIndex(2,3)]]`に相当します。
  * Juliaには行継続構文がありません。行末までの入力が完全な式ならそこで完了とみなされ、そうでなければ入力は次の行へ続きます。式を強制的に続ける方法の1つは、括弧で囲むことです。
  * Juliaの配列は列優先（Fortran順）ですが、NumPy配列は既定で行優先（C順）です。配列をループ処理する際に最適な性能を得るには、NumPyに比べてJuliaではループの順序を逆にします（[relevant section of Performance Tips](@ref man-performance-column-major)を参照）。
  * Juliaの更新演算子（たとえば`+=`、`-=`など）は*インプレースではありません*が、NumPyではインプレースです。つまり、`A = [1, 1]; B = A; B += [3, 3]`は`A`の値を変更せず、右辺の`B = B + 3`の結果（新しい配列）に左辺の名前`B`を再束縛します。インプレースで演算するには、`B .+= 3`（[dot operators](@ref man-dot-operators)も参照）、明示的なループ、または`InplaceOps.jl`を使います。
  * Juliaでは、関数の引数の既定値はメソッドが呼び出されるたびに評価されます。Pythonでは関数定義時に一度だけ評価されます。たとえば、引数なしで呼び出すたびに新しい乱数を返す関数は`f(x=rand()) = x`です。一方、`g(x=[1,2]) = push!(x,3)`は`g()`として呼び出すたびに`[1,2,3]`を返します。
  * Juliaでは、キーワード引数はキーワードを使って渡す必要があります。通常、位置引数として渡せるPythonとは異なります。キーワード引数を位置引数として渡そうとすると、メソッドシグネチャが変わり、`MethodError`が発生したり、誤ったメソッドが呼び出されたりします。
  * Juliaでは`%`は剰余演算子ですが、Pythonではモジュロ演算子です。
  * Juliaでよく使われる`Int`型は、Pythonの任意精度整数`int`とは異なり、マシン整数型（`Int32`または`Int64`）に相当します。そのため、Juliaの`Int`型ではオーバーフローが起こり、`2^64 == 0`となります。より大きな値が必要な場合は、`Int128`、[`BigInt`](@ref)、または`Float64`のような浮動小数点型など、適切な型を使います。
  * 虚数単位`sqrt(-1)`は、Juliaでは`im`で表します。Pythonの`j`とは異なります。
  * Juliaでは、べき乗演算子は`^`です。Pythonの`**`ではありません。
  * Juliaでは、`nothing`を型`Nothing`としてnull値を表します。Pythonでは型`NoneType`の`None`を使います。
  * Juliaでは、行列型に対する標準演算子は行列演算ですが、Pythonでは要素ごとの演算です。`A`と`B`が行列の場合、Juliaの`A * B`は行列積を計算し、Pythonのような要素ごとの積にはなりません。Juliaの`A * B`はPythonの`A @ B`に相当し、Pythonの`A * B`はJuliaの`A .* B`に相当します。
  * Juliaでスカラー値を返す関数を配列の各要素に適用するには、`f(A)`ではなく、ブロードキャスト構文`f.(A)`を使います。どちらの演算も定義されていても、意味が異なる場合があります。`numpy.exp(A)`は要素ごとの演算で、`scipy.linalg.expm(A)`は[matrix exponential](https://en.wikipedia.org/wiki/Matrix_exponential)ですが、Juliaでは`exp.(A)`が要素ごとの演算で、`exp(A)`は行列指数関数です。
  * Juliaの随伴演算子`'`は、ベクトルの随伴（行ベクトルの遅延表現）を返します。一方、Pythonでベクトルに転置演算子`.T`を適用しても、元のベクトルが返されます（何も行われません）。
  * Juliaの関数には、複数の具体的な実装（「メソッド」）を持たせることができます。呼び出し時にすべての引数の型に基づく多重ディスパッチで、適切な実装が選択されます。Pythonの関数は実装が1つで、多相性もありません（ただし、Pythonのメソッド呼び出しは別の構文を使い、メソッドの受け手に基づくディスパッチが可能です）。
  * Juliaにクラスはありません。代わりに、データを持つ構造体（可変または不変）がありますが、メソッドは持ちません。
  * Pythonでクラスのインスタンスのメソッドを呼び出す（`x = MyClass(*args); x.f(y)`）ことは、Juliaでは関数呼び出し（たとえば`x = MyType(args...); f(x, y)`）に相当します。一般に、多重ディスパッチはPythonのクラスシステムより柔軟で強力です。
  * Juliaの構造体が持てる抽象スーパータイプは1つだけですが、Pythonのクラスは1つ以上の（抽象または具象）スーパークラスを継承できます。
  * Juliaのプログラム構造（パッケージとモジュール）はファイル構造から独立していますが、Pythonのコード構造はディレクトリ（パッケージ）とファイル（モジュール）で定義されます。
  * Juliaでは、大きなモジュールのコードを複数のファイルに分割し、ファイルごとに新しいモジュールを作らないのが慣用的です。メインファイル内で`include`を使い、コードを1つのモジュールにまとめます。Pythonで対応する`exec`はこの用途では一般的ではなく、以前の定義を警告なしに上書きします。Juliaのプログラムは`module`レベルで`using`または`import`を使って単位として定義され、Pythonの`include`のように、必要になったときに初回だけ実行されます。モジュールを構成する個々のファイルは、意図した順序で一度ずつ列挙し、`include`で読み込みます。
  * Juliaの三項演算子`x > 0 ? 1 : -1`は、Pythonの条件式`1 if x > 0 else -1`に相当します。
  * Juliaでは`@`はマクロを表しますが、Pythonではデコレーターを表します。
  * Juliaでは`try` — `catch` — `finally`を使って例外を処理します。Pythonの`try` — `except` — `finally`とは異なります。Pythonとは異なり、Juliaでは通常の処理の一部として例外処理を使うことは推奨されません（通常の制御フローはJuliaのほうが高速ですが、例外の捕捉は遅いためです）。
  * Juliaではループが高速なので、性能のために「ベクトル化」したコードを書く必要はありません。
  * Juliaでは、特にタイトなループ内で、定数でないグローバル変数に注意してください。Pythonとは異なり、Juliaでは機械語に近いコードを書けるため、グローバル変数の影響が非常に大きくなることがあります（[Performance Tips](@ref man-performance-tips)を参照）。
  * Juliaでは、丸めと切り捨てを明示的に行います。Pythonの`int(3.7)`は、Juliaでは`floor(Int, 3.7)`または`Int(floor(3.7))`と書き、`round(Int, 3.7)`とは区別されます。`floor(x)`と`round(x)`は、単独で使うと、常に`Int`を返すのではなく、`x`と同じ型の整数値を返します。
  * Juliaでは、解析を明示的に行います。Pythonの`float("3.7")`は、Juliaでは`parse(Float64, "3.7")`に相当します。
  * Pythonでは、多くの値を論理コンテキストで使えます（たとえば`if "a":`なら後続のブロックが実行され、`if "":`なら実行されません）。Juliaでは`Bool`への明示的な変換が必要です（たとえば`if "a"`は例外を投げます）。Juliaで空でない文字列かどうかを調べるには、明示的に`if !isempty("")`と書きます。意外かもしれませんが、Pythonでは`if "False"`と`bool("False")`はどちらも`True`と評価されます（`"False"`は空でない文字列だからです）。Juliaでは`parse(Bool, "false")`は`false`を返します。
  * Juliaでは、ループや`try` — `catch` — `finally`など、ほとんどのコードブロックが新しいローカルスコープを導入します。内包表記（リスト内包表記、ジェネレーターなど）はPythonとJuliaの両方で新しいローカルスコープを導入しますが、`if`ブロックはどちらの言語でも新しいローカルスコープを導入しません。

## Noteworthy differences from C/C++

  * Juliaの配列は角括弧でインデックス指定でき、複数の次元を持てます。`A[i,j]`。この構文は、C/C++のようにポインターやアドレスを参照するための単なる糖衣構文ではありません。[the manual entry about array construction](@ref man-multi-dim-arrays)を参照してください。
  * Juliaでは、配列や文字列などのインデックスは1始まりであり、0始まりではありません。
  * Juliaでは、配列を別の変数に代入してもコピーされません。`A = B`の後に`B`の要素を変更すると、`A`も変更されます。`+=`のような更新演算子はインプレースで動作せず、`A = A + B`と同等です。つまり、右辺の式の結果に左辺を再束縛します。
  * Juliaの配列は列優先（Fortran順）ですが、C/C++の配列は既定で行優先です。配列をループ処理する際に最適な性能を得るには、C/C++に比べてJuliaではループの順序を逆にします（[relevant section of Performance Tips](@ref man-performance-column-major)を参照）。
  * Juliaでは、値を代入したり関数に渡したりしてもコピーされません。関数が配列を変更すると、その変更は呼び出し元からも見えます。
  * Juliaでは、C/C++とは異なり、空白が意味を持ちます。そのため、Juliaプログラムで空白を追加・削除する際は注意が必要です。
  * Juliaでは、小数点のない数値リテラル（たとえば`42`）は符号付き整数（型`Int`）になります。ただし、マシンワードサイズに収まらない大きさのリテラルは、より大きな型に自動的に昇格します。たとえば、`Int`が`Int32`の場合は`Int64`、または`Int128`、任意の大きさを扱える`BigInt`型などです。符号付き／符号なしを示す`L`、`LL`、`U`、`UL`、`ULL`のような数値リテラルの接尾辞はありません。10進リテラルは常に符号付きで、C/C++と同様に`0x`で始まる16進リテラルは、128ビットを超える値を表す場合を除き、符号なしです。128ビットを超える場合は`BigInt`型になります。また、C/C++/JavaやJuliaの10進リテラルとは異なり、16進リテラルの型は先頭の0を含むリテラルの*桁数*で決まります。たとえば、`0x0`と`0x00`は[`UInt8`](@ref)型、`0x000`と`0x0000`は[`UInt16`](@ref)型です。16進数が5～8桁のリテラルは`UInt32`型、9～16桁は`UInt64`型、17～32桁は`UInt128`型、32桁を超えるものは`BigInt`型になります。たとえば16進マスクを定義する際には、この点に注意が必要です。`~0xf == 0xf0`は`~0x000f == 0xfff0`とは大きく異なります。64ビットの`Float64`リテラルと32ビットの[`Float32`](@ref)リテラルは、それぞれ`1.0`と`1.0f0`と書きます。浮動小数点リテラルは、正確に表現できない場合、`BigFloat`型に昇格するのではなく丸められます。浮動小数点リテラルの動作はC/C++に近いものです。8進リテラル（`0o`を接頭辞とする）と2進リテラル（`0b`を接頭辞とする）も符号なしとして扱われます（128ビットを超える場合は`BigInt`）。
  * Juliaでは、両方のオペランドが整数型の場合、除算演算子[`/`](@ref)は浮動小数点数を返します。整数除算には[`div`](@ref)または[`÷`](@ref div)を使います。
  * Juliaでは、浮動小数点型を使って`Array`をインデックス指定すると、通常はエラーになります。Cの式`a[i / 2]`に相当するJuliaの式は`a[i ÷ 2 + 1]`です。ここで`i`は整数型です。
  * 文字列リテラルは`"`または`"""`で囲めます。`"""`で囲んだリテラルでは、`"`文字を`"\""`のように引用符で囲まずに含められます。文字列リテラルには、`$variablename`または`$(expression)`で示すことで、他の変数や式の値を埋め込めます。変数名や式は、関数のコンテキストで評価されます。
  * `//`は[`Rational`](@ref)数を表し、Juliaの1行コメント（`#`）ではありません。
  * `#=`は複数行コメントの開始を示し、`=#`で終了します。
  * Juliaの関数は、最後の式の値、または`return`キーワードで値を返します。関数は複数の値を返すことができ、`(a, b) = myfunction()`や`a, b = myfunction()`のようにタプルとして代入できます。C/C++のように値へのポインターを渡す必要はありません（つまり`a = myfunction(&b)`）。
  * Juliaでは、文末にセミコロンを付ける必要はありません。式の結果は自動的には表示されず（対話プロンプト、つまりREPLを除く）、コード行をセミコロンで終える必要もありません。特定の出力を表示するには[`println`](@ref)または[`@printf`](@ref)を使います。REPLでは、出力を抑制するために`;`を使えます。また、`;`は`[ ]`内では別の意味を持つため、注意が必要です。`;`を使うと1行に複数の式を記述できますが、多くの場合必須ではなく、主に読みやすさのために使います。
  * Juliaでは、演算子[`⊻`](@ref xor)（[`xor`](@ref)）はビット単位のXOR演算を行います。つまり、C/C++の[`^`](@ref)に相当します。また、ビット演算子の優先順位はC/C++と同じではないため、括弧が必要になる場合があります。
  * Juliaの[`^`](@ref)はべき乗（pow）であり、C/C++のようなビット単位のXORではありません。JuliaでXORを行うには[`⊻`](@ref xor)または[`xor`](@ref)を使います。
  * Juliaには右シフト演算子が2つあり、`>>`と`>>>`です。`>>`は算術シフトを行い、`>>>`は常に論理シフトを行います。C/C++では、`>>`の意味はシフト対象の値の型によって異なります。
  * Juliaの`->`は無名関数を作成します。ポインターを介してメンバーにアクセスするものではありません。
  * Juliaでは、`if`文や`for`／`while`ループを書くときに括弧は不要です。`for (int i=1; i <= 3; i++)`ではなく`for i in [1, 2, 3]`を、`if (i == 1)`ではなく`if i == 1`を使います。
  * Juliaでは、`0`と`1`は真偽値として扱われません。Juliaでは`if (1)`とは書けません。`if`文が真偽値だけを受け付けるためです。代わりに`if true`、`if Bool(1)`、または`if 1==1`と書けます。
  * Juliaでは、条件ブロック（`if`など）、ループブロック（`while`／`for`など）、関数の終わりを示すのに`end`を使います。1行で書く`if ( cond ) statement`の代わりに、`if cond; statement; end`、`cond && statement`、`!cond || statement`の形式で文を書けます。後者2つの構文で代入文を使う場合は、演算子の優先順位のため、`cond && (x = value)`のように明示的に括弧で囲む必要があります。
  * Juliaには行継続構文がありません。行末までの入力が完全な式ならそこで完了とみなされ、そうでなければ入力は次の行へ続きます。式を強制的に続ける方法の1つは、括弧で囲むことです。
  * Juliaのマクロはプログラムのテキストではなく、解析済みの式を処理するため、Juliaコードを高度に変換できます。マクロ名は`@`文字で始まり、関数形式の`@mymacro(arg1, arg2, arg3)`と文形式の`@mymacro arg1 arg2 arg3`があります。両者は相互に置き換え可能です。関数形式は、マクロが別の式の中に現れる場合に特に便利で、意味も明確になりやすい形式です。文形式は、分散`for`構文のように、ブロックに注釈を付ける場合によく使われます。`@distributed for i in 1:n; #= body =#; end`。マクロ構文の終わりが分かりにくい場合は、関数形式を使ってください。
  * Juliaには列挙型があり、`@enum(name, value1, value2, ...)`マクロで表します。たとえば次のとおりです。`@enum(Fruit, banana=1, apple, pear)`
  * 慣例として、引数を変更する関数の名前は`!`で終わります。たとえば`push!`です。
  * C++では、既定で静的ディスパッチが使われるため、動的ディスパッチを行うには関数にvirtualを指定する必要があります。一方、Juliaではすべてのメソッドが「仮想」です（ただし、メソッドは`this`だけでなく、すべての引数の型に基づいて、最も具体的な宣言を選ぶ規則でディスパッチされるため、より一般的な仕組みです）。

### Julia ⇔ C/C++: Namespaces

  * C/C++の`namespace`は、Juliaの`module`におおむね相当します。
  * Juliaには、非公開のグローバル変数やフィールドはありません。完全修飾パス（または必要に応じて相対パス）を使えば、すべてにアクセスできます。
  * C++の`using MyNamespace::myfun`は、Juliaの`import MyModule: myfun`におおむね相当します。
  * C++の`using namespace MyNamespace`は、Juliaの`using MyModule`におおむね相当します。

      * Juliaでは、`export`されたシンボルだけが呼び出し元のモジュールから利用できます。
      * C++では、インクルードされた（公開）ヘッダーファイルにある要素だけが利用できます。
  * 注意：Juliaの`import`／`using`キーワードは、モジュールの*読み込み*も行います（後述）。
  * 注意：Juliaの`import`／`using`は、グローバルスコープ（`module`s）でのみ機能します。

      * C++では、`using namespace X`は任意のスコープ（例：関数スコープ）内で機能します。

### Julia ⇔ C/C++: Module loading

  * C/C++の「**ライブラリ**」に相当するものを探している場合、Juliaでは「**パッケージ**」が該当するでしょう。

      * 注意：C/C++のライブラリには複数の「ソフトウェアモジュール」が含まれることがよくありますが、Juliaの「パッケージ」に含まれるのは通常1つです。
      * 補足：Juliaの`module`sはグローバルスコープであり、必ずしも「ソフトウェアモジュール」ではありません。
  * **build／`make`スクリプトの代わりに**、Juliaでは「プロジェクト環境」（「Project」または「Environment」と呼ばれることもあります）を使います。

      * ビルドスクリプトが必要なのは、C/C++の実行ファイルをコンパイルまたはダウンロードするような、より複雑なアプリケーションの場合だけです。
      * Juliaでアプリケーションやプロジェクトを開発するには、ルートディレクトリを「プロジェクト環境」として初期化し、アプリケーション固有のコードやパッケージをそこに置きます。これにより、プロジェクトの依存関係を適切に管理し、将来の再現性を確保できます。
      * 利用可能なパッケージは、`Pkg.add()`関数またはPkg REPLモードを使って「プロジェクト環境」に追加します。ただし、これによってパッケージが**読み込まれる**わけではありません。
      * 「プロジェクト環境」で利用できるパッケージ（直接依存関係）の一覧は、`Project.toml`ファイルに保存されます。
      * 「プロジェクト環境」の依存関係の**全情報**は、`Pkg.resolve()`によって自動生成され、`Manifest.toml`ファイルに保存されます。
  * 「プロジェクト環境」で利用できるパッケージ（「ソフトウェアモジュール」）は、`import`または`using`で読み込みます。

      * C/C++では、オブジェクトや関数の宣言を得るために`#include <moduleheader>`を使い、実行ファイルのビルド時にライブラリをリンクします。
      * Juliaでは、using／importを再度呼び出しても既存のモジュールがスコープに入るだけで、再読み込みはされません（C/C++に非標準の`#pragma once`を追加するのに似ています）。
  * **ディレクトリベースのパッケージリポジトリ**（Julia）は、リポジトリのパスを`Base.LOAD_PATH`配列に追加すると利用できるようになります。

      * ディレクトリベースのリポジトリにあるパッケージは、`import`または`using`で読み込む前に`Pkg.add()`ツールを使う必要はありません。プロジェクトからそのまま利用できます。
      * ディレクトリベースのパッケージリポジトリは、「ソフトウェアモジュール」のローカルライブラリを開発するための**最も手軽な方法**です。

### Julia ⇔ C/C++: Assembling modules

  * C/C++では、`.c`／`.cpp`ファイルをビルド／`make`スクリプトでコンパイルし、ライブラリに追加します。

      * Juliaでは、`import [PkgName]`／`using [PkgName]`文によって、パッケージの`[PkgName]/src/`サブディレクトリにある`[PkgName].jl`を読み込みます。
      * 通常、`[PkgName].jl`は`include "[someotherfile].jl"`の呼び出しによって、関連するソースファイルを読み込みます。
  * Juliaの`include "./path/to/somefile.jl"`は、C/C++の`#include "./path/to/somefile.jl"`によく似ています。

      * ただし、Juliaの`include "..."`はヘッダーファイルのインクルードには使いません（その必要もありません）。
      * 他の「ソフトウェアモジュール」のコードを読み込むために、Juliaの`include "..."`を**使わないでください**（代わりに`import`／`using`を使います）。
      * Juliaの`include "path/to/some/module.jl"`を使うと、同じコードの複数のバージョンが異なるモジュール内に作られ、同じ名前を持つ型などが別個に生成されます。
      * `include "somefile.jl"`は通常、同じJuliaパッケージ（「ソフトウェアモジュール」）内の複数のファイルをまとめるために使います。そのため、ファイルが一度だけ`include`されるようにするのは比較的簡単です（`#ifdef`の混乱は起きません）。

### Julia ⇔ C/C++: Module interface

  * C++では「public」`.h`／`.hpp`ファイルでインターフェースを公開します。一方、Juliaでは`module`sによって、ユーザー向けの特定のシンボルを`public`または`export`として指定します。

      * Juliaの`module`sは、既存の関数に新しい「メソッド」を追加することで機能を拡張するだけの場合もよくあります（例：`Base.push!`）。
      * そのため、Juliaパッケージの開発者は、インターフェースのドキュメントとしてヘッダーファイルを頼りにできません。
      * Juliaパッケージのインターフェースは通常、docstring、README.md、静的なWebページなどで説明されます。
  * パッケージ／モジュールの利用に必要なシンボルをすべて`export`しない開発者もいますが、公開されていないユーザー向けシンボルにも`public`を付けるべきです。

      * ユーザーは、パッケージ／モジュール名で関数や構造体などを修飾して、これらの要素にアクセスすることが想定される場合があります（例：`MyModule.run_this_task(...)`）。

## Noteworthy differences from Common Lisp

  * Juliaでは、既定で配列に1始まりのインデックスを使います。また、任意の[index offsets](@ref man-custom-indices)も扱えます。
  * 関数と変数は同じ名前空間を共有します（「Lisp-1」）。
  * [`Pair`](@ref)型はありますが、`COMMON-LISP:CONS`として使うことを意図したものではありません。多くの場面（スプラット、タプルなど）では、さまざまな反復可能コレクションを相互に置き換えて使えます。`Tuple`sは、*短い*異種要素コレクションにおいて、Common Lispのリストに最も近いものです。連想リストの代わりには`NamedTuple`sを使います。より大きな同種要素のコレクションには、`Array`sや`Dict`sを使います。
  * Juliaでの一般的なプロトタイピング作業では、[Revise.jl](https://github.com/timholy/Revise.jl)パッケージを使って、イメージを継続的に操作することもあります。
  * 性能のため、Juliaでは演算の[type stability](@ref man-type-stability)が重視されます。Common Lispが基盤となる機械演算を抽象化するのに対し、Juliaはそれらに近い形で扱います。たとえば次のとおりです。

      * `/`を使った整数除算は、計算結果が正確な場合でも常に浮動小数点数を返します。

          * `//`は常に有理数を返します。
          * `÷`は常に（切り捨てられた）整数を返します。
      * 多倍長整数はサポートされていますが、自動変換は行われません。通常の整数は[overflow](@ref faq-integer-arithmetic)。
      * 複素数はサポートされていますが、複素数の結果を得るには[you need complex inputs](@ref faq-domain-errors)。
      * 複素数型と有理数型には、成分の型が異なる複数の種類があります。
  * モジュール（名前空間）は階層化できます。[`import`](@ref)と[`using`](@ref)には、コードを読み込むと同時に名前空間から利用可能にする役割があります。モジュール名だけを対象に`import`することもできます（おおむね`ASDF:LOAD-OP`に相当）。フィールド名を個別にエクスポートする必要はありません。グローバル変数はモジュールの外から代入できません（例外として`eval(mod, :(var = val))`を使う方法があります）。
  * マクロ名は`@`で始まり、Common Lispほど言語にシームレスに統合されていません。そのため、Common Lispほど広く使われてはいません。[macros](@ref Metaprogramming)には、衛生的なマクロに相当する仕組みが言語でサポートされています。表層構文が異なるため、`COMMON-LISP:&BODY`に相当するものはありません。
  * *すべての*関数はジェネリックであり、多重ディスパッチを使います。引数リストが同じ形式に従う必要はなく、これによって強力な慣用パターンが生まれます（[`do`](@ref)を参照）。オプション引数とキーワード引数の扱いは異なります。メソッドの曖昧さはCommon Lisp Object Systemのようには解決されないため、交差部分に対してより具体的なメソッドを定義する必要があります。
  * シンボルはどのパッケージにも属さず、それ自体では値を持ちません。`M.var`は、モジュール`M`内のシンボル`var`を評価します。
  * クロージャーを含む関数型プログラミングのスタイルは完全にサポートされていますが、Juliaで常に慣用的な解決策とは限りません。捕捉した変数を変更する場合、性能のために[workarounds](@ref man-performance-captured)が必要になることがあります。
