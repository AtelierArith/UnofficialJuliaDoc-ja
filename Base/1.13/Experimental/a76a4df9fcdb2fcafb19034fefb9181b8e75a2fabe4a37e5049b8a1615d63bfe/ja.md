```julia
Base.Experimental.@consistent_overlay mt def
```

このマクロは、[`Base.Experimental.@overlay`](@ref)とほぼ同じように動作し、新しいオーバーレイメソッドを定義します。このマクロとの主な違いは、定義するオーバーレイメソッドの呼び出しが、通常の非オーバーレイメソッド呼び出しと`:consistent`であることをコンパイラに通知する点です。

より形式的には、特定のワールドエイジ``i``において、ジェネリック関数呼び出し``f(x)``を評価する際、通常のメソッド呼び出し``fᵢ(x)``が、このマクロで定義されたオーバーレイメソッド呼び出し``fᵢ′(x)``にリダイレクトされる場合、次の条件を満たせば、``fᵢ(x)``と``fᵢ′(x)``は`:consistent`とみなされます。

  * ``fᵢ(x)``が値``y``を返す場合、``fᵢ′(x)``も何らかの値``yᵢ``を返し、``y ≡ yᵢ``が成り立つ。
  * ``fᵢ(x)``が例外をスローする場合、``fᵢ′(x)``も何らかの例外をスローする。

`:consistent`-cyの詳しい定義については、[`Base.@assume_effects`](@ref)の該当セクションを参照してください。

!!! note
    `:consistent`-cyの要件には、戻り値が等しいことだけでなく、終了の仕方も同じであることが含まれます。ただし、例外をスローする場合、例外そのものが等しい必要はありません。つまり、``fᵢ(x)``が例外をスローするなら、``fᵢ′(x)``も例外をスローする必要がありますが、具体的な例外は異なっていてもかまいません。


!!! note
    `:consistent`-cyの要件が適用されるのは、メソッド自体ではなく、*メソッド呼び出し*である点に注意してください。つまり、`@consistent_overlay`を使用するには、通常のネイティブコンパイルによるメソッド呼び出しと、オーバーレイメソッドテーブルを使ったコンパイルによるメソッド呼び出しが、`:consistent`である必要があります。

    たとえば、`@consistent_overlay`は次のように使用できます。

    ```julia
    callsin(x::Real) = x < 0 ? error(x) : sin(x)
    @consistent_overlay SOME_OVERLAY_MT callsin(x::Float64) =
        x < 0 ? error_somehow(x) : sin(x)
    ```

    ただし、次のように`callsin`に対する新しいメソッドが後から定義されると、この`@consistent_overlay`は直ちに無効になることに注意してください。

    ```julia
    callsin(x::Float64) = cos(x)
    ```

    これは特に、`@consistent_overlay`の使用を、具体的なシグネチャを持つ通常のメソッドを、同じ具体的なシグネチャを持つオーバーレイメソッドで置き換える場合に、できる限り限定すべきであることを意味します。

    この制約は[`Base.Experimental.@overlay`](@ref)の注記と密接に関係しています。そちらも参照してください。
