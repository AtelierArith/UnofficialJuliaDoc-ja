```julia
platforms_match(a::AbstractPlatform, b::AbstractPlatform)
```

`true` を返すのは、`a` と `b` が一致するプラットフォームである場合です。一致するかどうかは、プラットフォームオブジェクトに含まれるすべてのキーを比較して判定します。両方のオブジェクトに同じキーのエントリがある場合、それらの値は一致していなければなりません。比較にはデフォルトで `==` 演算子を使用しますが、`set_compare_strategy!(platform, key, func)` を使って「比較戦略」を追加すれば、キーごとに変更できます。

比較戦略はグローバルではなく `Platform` オブジェクトに設定されるため、カスタム比較戦略はまず `a` オブジェクト内で検索されます。見つからない場合は、`b` オブジェクト内が検索されます。どちらにも見つからない場合は、デフォルトの `==(ak, bk)` が使用されます。`a` と `b` の両方にカスタム比較戦略が設定されていて、それらが同一のカスタム比較でない場合は、エラーが発生します。

予約タグ `os_version` と `libstdcxx_version` は、この仕組みを使ってバージョンの範囲制約を指定します。たとえば、アーティファクトは macOS `v"10.11"` 以降でのみ利用可能な API を使ってビルドされたことを指定できます。また、libstdc++ のバージョンが少なくとも `v"3.4.22"` であることを要求することもできます。
