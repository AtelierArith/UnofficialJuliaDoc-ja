```julia
verify_host(url::AbstractString, [transport::AbstractString]) :: Bool
```

`verify_host` 関数は、TLS や SSH などのセキュアなトランスポートで通信する際に、ホストの識別情報を検証するかどうかを呼び出し元に伝えます。`url` 引数には、次のいずれかを指定できます。

1. `proto://` で始まる正しい URL
2. `ssh` 形式のホスト名単体、または `user@` を前置したホスト名
3. 上記の `scp` 形式のホスト名に、`:` とパスを続けたもの

いずれの場合もホスト名部分が取り出され、検証するかどうかはホスト名だけに基づいて決定されます。入力 URL のその他の情報は判断に影響しません。特に、URL のプロトコルは関係ありません（詳細は後述）。

`transport` 引数は、問い合わせの対象となるトランスポートの種類を示します。現在、認識される値は `SSL`/`ssl`（別名 `TLS`/`tls`）と `SSH`/`ssh` です。トランスポートを省略した場合、どのトランスポートでもホスト名を検証すべきでないときに限り、問い合わせは `true` を返します。

ホスト名は、`transport` が指定されているかどうか、およびその値に応じて、該当する環境変数内のホストパターンと照合されます。

  * `JULIA_NO_VERIFY_HOSTS` — すべてのトランスポートで検証しないホスト
  * `JULIA_SSL_NO_VERIFY_HOSTS` — SSL/TLS で検証しないホスト
  * `JULIA_SSH_NO_VERIFY_HOSTS` — SSH で検証しないホスト
  * `JULIA_ALWAYS_VERIFY_HOSTS` — 常に検証するホスト

これらの各変数の値は、ホスト名パターンをカンマで区切ったリストです。パターンの構文は次のとおりです。各パターンは `.` で分割され、各部分は次のいずれかでなければなりません。

1. ASCII の英字、数字、ハイフン、アンダースコアのいずれか1文字以上からなるドメイン名のリテラル要素（厳密には正規のホスト名の構成要素ではありませんが、使われることがあります）。リテラル要素は、それ自体にのみ一致します。
2. 0個以上のドメイン名要素に一致する `**`
3. 任意の1つのドメイン名要素に一致する `*`

これらの変数に含まれるパターンリストとホスト名を照合する際、ホスト名は `.` で分割され、その要素の並びがパターンと照合されます。リテラルパターンは、値が完全に一致するホスト名要素1つに一致します。`*` パターンは、値を問わずホスト名要素1つに一致します。`**` パターンは、任意の数のホスト名要素に一致します。たとえば、次のようになります。

  * `**` は、すべてのホスト名に一致します。
  * `**.org` は、`.org` トップレベルドメイン内のすべてのホスト名に一致します。
  * `example.com` は、ホスト名が `example.com` と完全に一致する場合にのみ一致します。
  * `*.example.com` は `api.example.com` に一致しますが、`example.com` や `v1.api.example.com` には一致しません。
  * `**.example.com` は、`example.com` 配下のすべてのドメインに一致します。`example.com` 自体に加え、`api.example.com` や `v1.api.example.com` も含まれます。
